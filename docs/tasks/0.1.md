# 0.1 Workspace scaffold

## What was built

- **Cargo workspace** (`Cargo.toml`): resolver 3, edition 2024, three crates
  under `crates/`. Shared metadata, lints and the `leal-core` path dependency
  are defined once at the workspace level and inherited by each crate.
  - `leal-core` (library): `version()`, with a unit test and a doctest.
  - `leal-ffi` (library, `crate-type = ["staticlib", "lib"]`): `core_version()`,
    which wraps `leal_core::version()`, with a unit test. No UniFFI yet (0.3).
  - `leal-cli` (binary `leal`): prints `leal 0.0.0`, with a unit test.
- **`justfile`**: `check`, `test`, `fmt`, `lint`, `bench`, `run`, `app`, and
  `default`, which lists them. `run` and `app` print "available from task 0.3".
- **CI** (`.github/workflows/ci.yml`): `just check` on `macos-latest`, on
  pushes to `main` and on pull requests. Read-only permissions; a new run
  cancels the older one for the same branch or PR.
- **`rustfmt.toml`**: `edition = "2024"` and `newline_style = "Unix"`, both
  stable.
- `Cargo.lock` is committed, because the workspace builds an application and
  a static library (not a published library).

`just check` passes: 3 unit tests (nextest) and 1 doctest. `just bench` runs
and finds nothing to measure yet. A release build produces
`target/release/libleal_ffi.a` and `target/release/leal`.

## Decisions

- **`unsafe_code = "deny"`, not `forbid`.** Later tasks need `unsafe` in
  leal-core's `source` module (mmap, 1.1) and in leal-ffi (0.3). `deny` can be
  overridden with a narrow `#[allow(unsafe_code)]` on that one module or
  crate; `forbid` can't. Cargo does not let a crate merge its own `[lints]`
  with the workspace's, so the override has to be an attribute in the code.
- **`missing_docs` is set for the whole workspace.** It only checks public
  items and the crate root, so for `leal-cli` (a binary with no public API) it
  asks only for the crate doc comment. That meets "library crates" without a
  per-crate lint table, which Cargo does not support alongside
  `workspace = true`.
- **Clippy: `all` plus a chosen subset of `pedantic`.** The full pedantic
  group is noisy (`must_use_candidate`, `module_name_repetitions`,
  `doc_markdown`, `similar_names` and others), and blanket-allowing half of it
  hides what is actually checked. The chosen lints target this project's
  risks: lossy numeric casts (the index uses `u32` offsets), float comparison
  (numeric sort), pointer casts (FFI, mmap), needless copies on hot paths,
  case-sensitive file-extension checks, and error/panic docs on public API.
  Each group is explained in `Cargo.toml`.
- **`panic` stays at the default (`unwind`) in release.** UniFFI catches Rust
  panics at the FFI boundary with `catch_unwind` and turns them into Swift
  errors. With `panic = "abort"` that can't happen, and any panic would kill
  the app, possibly with unsaved edits. `lto = "thin"` and
  `codegen-units = 1` are set.
- **CI installs the toolchain with `rustup toolchain install`, then
  `rustup show`.** The brief said `rustup show` is enough, but since rustup
  1.28 `rustup show` no longer installs a missing toolchain. With no
  arguments, `rustup toolchain install` installs exactly what
  `rust-toolchain.toml` specifies. This is a small deviation from the brief.
- **Action versions** are pinned to the current majors: `actions/checkout@v7`,
  `taiki-e/install-action@v2`, `Swatinem/rust-cache@v2`. The cache step runs
  after the toolchain step, because its key includes the rustc version.
- **No dependencies** were added.

## Rust notes

- **Package vs crate.** A *package* is a directory with a `Cargo.toml`; it is
  what Cargo builds, tests and versions. A *crate* is one unit of compiled
  code: a library or a program. A package holds one library crate at most,
  plus any number of binary crates. Here each package holds one crate, so the
  names line up (`crates/leal-core` is the `leal-core` package, whose library
  crate is imported as `leal_core`; Cargo swaps `-` for `_` in code).
- **Workspace.** The root `Cargo.toml` has a `[workspace]` section and no
  package of its own. It groups the three packages so they share one
  `Cargo.lock`, one `target/` build directory and one set of settings.
  `cargo test --workspace` works on all of them at once. Settings marked
  `.workspace = true` in a crate's `Cargo.toml` (such as
  `version.workspace = true`) are copied from the root.
- **`lib`, `staticlib` and `bin`.** These are the kinds of output a crate can
  produce.
  - `bin` is an executable with a `main` function: `leal-cli` builds
    `target/debug/leal`.
  - `lib` (an *rlib*) is a Rust-only library that other Rust crates depend on.
    `leal-cli` and `leal-ffi` use `leal-core` this way.
  - `staticlib` is a `.a` file in the C format that Xcode can link into
    Leal.app (`libleal_ffi.a`). `leal-ffi` builds both: `staticlib` for the
    app, and `lib` so Rust tests and tools can still use it.
- **Editions.** An edition (2015, 2018, 2021, 2024) is a set of language
  rules chosen per crate, for example which words are reserved. It lets Rust
  make small breaking changes without breaking old code, because each crate
  keeps the edition it declares. Crates of different editions work together.
  We use the newest, 2024. The *resolver* (`resolver = "3"`) is the matching
  rule set for how Cargo picks dependency versions and features; version 3
  also respects `rust-version` when choosing dependency versions.
- **`rust-version`** is the oldest compiler the crates promise to build with.
  It matches the toolchain pinned in `rust-toolchain.toml`, which rustup
  installs automatically in this directory.
- **Lints and clippy.** A lint is an automatic check for code that compiles
  but is probably wrong, unclear or slow. The compiler has built-in lints
  (such as `unsafe_code` and `missing_docs`). Clippy is a separate tool with
  several hundred more, grouped by strictness. Each lint has a level: `allow`
  (off), `warn`, `deny` (error, can be overridden in code) or `forbid` (error,
  can't be overridden). `just check` passes `-D warnings`, so every warning
  fails the check. That keeps warnings from piling up.
- **`unsafe`.** Rust normally proves memory safety at compile time. An
  `unsafe` block marks code where the programmer, not the compiler,
  guarantees it (for example, reading a memory-mapped file or calling C).
  The `unsafe_code` lint makes any such block an error unless it is
  explicitly allowed, so it can only appear where we decide.
- **Tests.** `#[cfg(test)] mod tests { ... }` at the bottom of a file is a
  module compiled only for tests, and `#[test]` marks a test function (see
  `crates/leal-core/src/lib.rs`). A code block in a `///` doc comment is a
  *doctest*: it is compiled and run as a test, so examples in the docs can't
  go stale. `#[must_use]` makes the compiler warn if a caller ignores the
  return value.
- **Why nextest.** `cargo nextest` runs each test in its own process and runs
  them in parallel, which is faster for large suites, isolates a crash to one
  test, and gives clearer output. It does not run doctests, so `just check`
  and `just test` run `cargo test --doc` as well.
