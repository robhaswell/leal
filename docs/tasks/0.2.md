# 0.2 Test harness and corpus

## What was built

### `crates/leal-testkit` (dev-only, `publish = false`)

A library crate that other crates use as a `[dev-dependencies]` entry. No
product crate depends on it normally, so it is never part of a release build
(`cargo tree -p leal-core -e normal` shows nothing).

| Module | What it holds |
|---|---|
| `fidelity` | `assert_identical` (F1), `assert_only_changed` (F2, F3, F6), `apply_changes`, `Change`, and `check_*` twins that return a `FidelityError` for use in proptest bodies. |
| `strategies::bytes` | `csv_bytes()`: arbitrary bytes built from chunks biased towards `, ; \t \| " \r \n`, CRLF, NUL, BOMs, invalid UTF-8 and multibyte UTF-8. |
| `strategies::csv` | The model-based generator: `csv_file(CsvConfig)` yields a `GeneratedCsv` with the model, the bytes, the expected `Layout`, the expected encoding and the expected diagnostics. `Messiness` switches each irregular construct on or off. `csv_file_utf16` writes the same models as UTF-16 LE or BE with a BOM, with spans as file byte offsets. |
| `strategies::edits` | `edit_case(CsvConfig)`: a generated file, a list of concrete `Edit`s (cell edits including values that need quoting and reverts to the original, row and column inserts and deletes), and the expected save from the save oracle. |
| `save` | The save oracle for tasks 2.1–2.4 (DESIGN §3.6–§3.7): `expected_field_bytes` for one edited field, and `Document`, which replays `Edit`s and gives the exact expected output as bytes and as `Change`s. |
| `layout` | `Layout` / `RowLayout` / `FieldLayout`: every row and field span, whether it is quoted, its display value (unescaped, or raw if there is text after the closing quote), and where that text begins. Also `check_tiles`, an invariant every parse must satisfy, and `quotes_every_field`. |
| `diagnostics` | `DiagnosticKind`, `Location`, `Diagnostic`, and `derive(layout, bytes, encoding)`, the testkit's definition of what counts as one occurrence of each kind and where it is (ADR-0003 decisions 4 and 7). |
| `dialect` | `Delimiter`, `LineEnding`, `Bom`, `Encoding`; `expected_encoding`, the ADR-0003 encoding rule; and `encode_value` / `decode_value` for UTF-8 and WHATWG Windows-1252. |
| `corpus` | `load()` walks `tests/corpus/`, pairs each data file with its sidecar, parses and validates the sidecar, and reports *every* problem at once. |

The testkit does not depend on `leal-core`. It is an independent statement
of the rules, so the real parser can be tested against it.

### Reference parser (test oracle)

`crates/leal-testkit/tests/oracle/mod.rs` is a naive, byte-at-a-time parser
of the §3.4 rules. It lives in the testkit's *integration tests* only, so it
cannot be used by product code, and is marked as a test oracle at the top.
It checks:

- the generator: for every generated file, the oracle's layout equals the
  generator's, the model rebuilt from the parse equals the generated model,
  and copying every parsed span back out gives identical bytes;
- the corpus: every sidecar's row count, field counts, trailing newline,
  line endings, BOM, diagnostics (kinds, counts and locations) and cell
  values match what the oracle finds.

The oracle does no detection. It takes the delimiter and encoding from the
sidecar. Delimiter, encoding and header *detection* are task 1.2's job,
tested against the same sidecars. The corpus tests do check each sidecar's
encoding against `expected_encoding`, the ADR-0003 rule.

For UTF-16 the oracle parses a UTF-8 transcoding and maps every offset back
to a byte offset in the file (ADR-0003 decision 6). A UTF-16 file with a
surrogate pair before a ragged row pins that mapping. Its own UTF-16
decoder finds U+0000 code units and unpaired surrogates (ADR-0003
decision 7), independently of the testkit's `derive`, so the UTF-16
generator's diagnostics are checked against a second implementation.
Two corpus files cover them.

### Save oracle (for tasks 2.1–2.4)

`save::Document` holds the original file and a list of cells per row, each
either an original field or an edited value. `Document::apply(&Edit)`
replays edits in logical coordinates; `Document::save()` writes the
expected output following §3.7, as `Change`s to the original and as bytes.
Cell edits in an otherwise unchanged row become one `Change` per edited
field, so `assert_only_changed` pinpoints F2 failures to the field. The
rules are at the top of `src/save.rs`; the edge cases follow ADR-0004 (see
"Save oracle and ADR-0004" below).

`SavedFile::bytes` is written out directly (the BOM, then every row), and
`SavedFile::changes` is computed separately from the original; the unit
tests and properties check that `apply_changes(original, changes) == bytes`,
so each guards the other. `SavedFile::fixes` lists the extra changes a save
made to keep the structure (ADR-0004 decisions 6, 7 and 10).

It is checked several ways: hand-computed unit tests; a property that the
expected bytes of any edited clean file *parse back* (with the reference
parser) to exactly the document's values, which tests the quoting rule
against the parser rather than against itself; the reopen property
(ADR-0004 decision 10) over clean and messy files; a property that setting
cells and then setting them back restores the original bytes (F3); and a
fixed-seed coverage test (`every_save_rule_and_edge_operation_is_exercised`)
requiring each fix, the encoding hint, and each edge operation (the only
row or column, first and last rows and columns) in at least 1% of 3,000
generated cases. To make the rarer rules likely, the edit values include
BOM-like starts, one edit kind targets the first cell, and three messy
files in ten are runs of `x CR`, `y LF`, blank `LF` rows.

### Corpus (`tests/corpus/`)

42 data files and 42 sidecars, about 52 KB in all, written byte for byte by
`tests/corpus/generate.py` (standard-library Python). `--check` verifies the
committed files match the script. `tests/corpus/README.md` documents the
layout, sidecar format, conventions and how to add a file.

- `dialect/` (23): comma, semicolon, tab, pipe; LF, CRLF, CR, mixed; UTF-8
  with and without BOM, UTF-16 LE and BE with BOM, Windows-1252; all quoted;
  no trailing newline; empty; single column; single row; header and no
  header; quoted newlines (LF, CRLF and CR), quoted delimiters (all four),
  escaped quotes.
- `diagnostics/` (12): one per kind in §3.5, plus a blank line at the end of
  the file, a ragged row in UTF-16 LE, U+0000 code units in UTF-16 LE, and
  unpaired surrogates in UTF-16 BE.
- `exports/` (7): `imitation-excel-utf8-bom` (Windows),
  `imitation-excel-mac-utf8-bom`, `imitation-excel-windows-1252`,
  `imitation-google-sheets`, `imitation-numbers`, `imitation-pandas-to-csv`,
  `imitation-postgresql-copy`. These are stand-ins, not real exports; see
  "Imitation exports: sources".

Writing the oracle check caught my own mistake in a sidecar (off-by-one rows
in the pandas cells), which is the point of the cross-check.

**Byte-exactness.** `.gitattributes` marks the corpus `-text`. After staging,
the blob id of every corpus file in the index (`git ls-files -s`) was
compared with `git hash-object --no-filters` of the file on disk. All
matched (78 files at the first commit, 86 now),
including the CR-only, CRLF, NUL, BOM, UTF-16 and invalid-UTF-8 files, so
git stores exactly the bytes the script wrote.

### Tests

90 testkit tests via nextest (108 in the workspace) plus 5 testkit doctests, about
3 s in `just check`.

- Unit tests for every module, including exact failure-report tests for the
  fidelity helper (a full-report snapshot, a 10 MB input whose report stays
  under 1 KB, escaping, each `Origin`, and invalid change lists).
- Property tests: fidelity helper (accepts exactly the expected output;
  pinpoints a flipped byte and its origin; notices an inserted or dropped
  byte); clean and messy generator round trips; each `Messiness` flag
  produces only its own diagnostic; the oracle tiles arbitrary bytes.
- Coverage tests with a fixed seed: 2,000 messy files reach every
  diagnostic kind and both encodings, and 1,000 clean files reach every
  delimiter, line ending,
  quoting style, empty file, single row, single column, BOM, and quoted
  values containing each special byte. 500 byte inputs contain every special
  byte and sequence. These stop a generator from silently going dull.
- Save oracle: unit tests with hand-computed output (quoting, quote-all
  files, reverts, row and column inserts and deletes, the trailing-newline
  rule, F5 and read-only UTF-16); the parse-back and revert properties
  above; UTF-16 generator round trips; and coverage tests that 1,000 edit
  cases reach every kind of edit, reverts, F5 failures and single-field
  changes, and that the parse-back property checks at least half of its
  cases rather than skipping them.
- Corpus: loads, every file has a sidecar, sidecars match the oracle, each
  sidecar's encoding follows ADR-0003, the corpus covers every dialect and
  diagnostic kind and all the imitations,
  total size under 1 MB, and the loader reports missing sidecars, orphan
  sidecars and bad sidecars together.

`just test-deep` runs every test with `PROPTEST_CASES=20000` (about 25 s
for the testkit today); `just test-deep 100000` for more. Normal runs use
proptest's default of 256 cases.

A 20,000-case run passes. Earlier runs found three kinds of real problem, and
proptest saved their seeds in the committed `*.proptest-regressions` files
so they re-run first every time:

- a generator bug (a blank last row with no line ending was repaired into
  `""`, which then counted as ragged), now fixed;
- §3.7 gaps, all now in ADR-0004: a field that starts with U+FEFF moved to
  the start of the file reads as a BOM (decision 7); reverting a swallowed
  cell can reopen an unterminated quote over new bytes (decision 8); and
  deleting a row can join CR and LF (decision 10);
- the encoding flipping on reopen after an edit, now handled by an
  encoding hint (ADR-0004 decision 11; see "Encoding hint").

## Conventions

These follow ADR-0003 (accepted on 2026-09-30) and are documented
in `tests/corpus/README.md` and in the testkit's docs.

- **Coordinates:** 0-based physical row index; 0-based byte offsets into the
  file as stored, *including the BOM*, for every encoding including UTF-16.
  Spans are half-open (`start..end`).
- **Encoding:** a BOM decides; otherwise pure ASCII is UTF-8, a file with at
  least one valid multibyte sequence and more of them than invalid bytes is
  UTF-8 (with `invalid_encoding`), and anything else is Windows-1252.
- **Rows:** a line ending at EOF ends the last row and doesn't start another;
  an empty or BOM-only file has no rows; a row's span excludes its line
  ending; a field's span includes its quotes and any text after the closing
  quote.
- **Text after a closing quote:** part of the field; the field displays raw
  (`"a"b`); quotes in that text are literal.
- **Blank line:** a row with no bytes before its line ending, anywhere,
  including at the end. It has one empty field and is never ragged.
- **Trailing newline:** the last row has a line ending (structural). A file
  ending in an unterminated quote has none.
- **Ties** (most common line ending, field-count mode): the one seen first.
- **One occurrence** of each diagnostic: per row (ragged, blank, mixed line
  endings), per field (text after quote, invalid encoding, NUL), per file
  (unterminated quote, BOM). Offsets are listed per kind in the README.
- **Sidecar diagnostics are exhaustive:** a kind not listed must not be
  reported.

## How later tasks use the testkit

Add to the crate's `Cargo.toml`:

```toml
[dev-dependencies]
leal-testkit.workspace = true
proptest.workspace = true
```

**Parser against the model (1.3, 1.4).** Convert the parser's output into a
`Layout` in test code and compare:

```rust
use leal_testkit::strategies::csv::{CsvConfig, csv_file};
use proptest::prelude::*;

proptest! {
    #[test]
    fn rows_match_the_model(file in csv_file(CsvConfig::messy())) {
        let index = RowIndex::build(&file.bytes, file.delimiter().byte());
        let starts: Vec<usize> = file.layout.rows.iter().map(|r| r.span.start).collect();
        prop_assert_eq!(index.row_starts(), starts);
    }
}
```

**Diagnostics (1.5):** compare against `file.diagnostics`, or
`leal_testkit::diagnostics::derive(&layout, &bytes, encoding)`. Generated
files carry `file.encoding` (by the ADR-0003 rule). `csv_file_utf16` gives
UTF-16 files whose spans and locations are file byte offsets.

In the examples below, `CoreDocument` stands for leal-core's editing API,
which doesn't exist yet; everything else is the testkit's real API.

**F1 on any bytes (2.2):**

```rust
use leal_testkit::{fidelity::check_identical, strategies::bytes::csv_bytes};

proptest! {
    #[test]
    fn save_with_no_edits_is_identical(bytes in csv_bytes()) {
        let out = CoreDocument::from_bytes(bytes.clone()).save_to_vec();
        check_identical(&bytes, &out)?; // `?` fails the case with the report
    }
}
```

**F2, F3, F5, F6 (2.1–2.4):** replay the strategy's edits on the real
document and compare its save with the oracle's:

```rust
use leal_testkit::fidelity::check_only_changed;
use leal_testkit::save::{Edit, SaveError};
use leal_testkit::strategies::{csv::CsvConfig, edits::edit_case};

proptest! {
    #[test]
    fn save_matches_the_oracle(case in edit_case(CsvConfig::messy())) {
        let mut doc = CoreDocument::from_bytes(case.file.bytes.clone());
        for edit in &case.edits {
            match edit {
                Edit::SetCell { row, column, value } => doc.set_cell(*row, *column, value),
                // ... InsertRow, DeleteRow, InsertColumn, DeleteColumn
                _ => todo!(),
            }
        }
        match (&case.saved, doc.save_to_vec()) {
            (Ok(expected), Ok(out)) => {
                check_only_changed(&case.file.bytes, &out, &expected.changes)?
            }
            (Err(SaveError::Unencodable(cells)), Err(e)) => prop_assert_eq!(e.cells(), cells.clone()),
            (expected, got) => prop_assert!(false, "{:?} vs {:?}", expected, got),
        }
    }
}
```

For one hand-written edit, `leal_testkit::save::expected_field_bytes` gives
a field's expected bytes:

```rust
use leal_testkit::fidelity::{Change, check_only_changed};
use leal_testkit::save::expected_field_bytes;

let field = &file.layout.rows[r].fields[c];
let quote_all = file.layout.quotes_every_field();
let new_bytes =
    expected_field_bytes(new_value, file.encoding, file.delimiter(), field.quoted, quote_all)
        .expect("encodable");
check_only_changed(&file.bytes, &out, &[Change::replace(field.span.clone(), new_bytes)])?;
```

Or build a `Document` directly: `file.document()`, then `apply` and `save`.

**Detection (1.2) against the corpus:**

```rust
for case in leal_testkit::corpus::load().unwrap() {
    let d = detect(&case.bytes);
    assert_eq!(d.delimiter, case.sidecar.dialect.delimiter.byte(), "{}", case.name);
}
```

`CsvConfig { messiness: Messiness { ragged_rows: true, ..Messiness::NONE },
..CsvConfig::clean() }` asks for one construct only. `CsvConfig::clean()`
has none; `CsvConfig::messy()` has them all. Row, field and value sizes are
in `CsvConfig` too.

## Ambiguities in DESIGN §3.2, §3.4 and §3.5

Writing the generator and the oracle turned up these. ADR-0003 (accepted on
2026-09-30) resolved the main ones, and the testkit, corpus and README
follow it:

| # | Question | ADR-0003 answer |
|---|---|---|
| 1 | §3.2 "UTF-8 if valid, else single-byte" meant the invalid-UTF-8 warning could never fire | UTF-8 if ≥ 1 valid multibyte sequence and they outnumber invalid bytes; ASCII is UTF-8; else Windows-1252 |
| 2 | Display value of `"a"b` | Raw: `"a"b` (as ADR-0002 question 6 had decided). *I had chosen `ab`; changed.* |
| 3 | Quotes in text after a closing quote | Literal: `"a"b"c",` is one field, raw `"a"b"c"` |
| 4 | What one occurrence is; tie-breaks | Per row, per field or per file (see Conventions); ties go to the first seen. *Invalid encoding and NUL were per sequence and per byte; now per field.* |
| 5 | Blank lines only "in the middle"? | Anywhere, including the end; the final line ending is not a blank line |
| 6 | UTF-16 offsets | Byte offsets into the file as stored. *Previously only counts were compared; now locations are too.* |
| 7 | UTF-16 NUL and invalid text | A NUL is a U+0000 code unit; an unpaired surrogate is `invalid_encoding`, once per field, shown as U+FFFD; the location is the code unit's first byte |
| – | Is a blank line ragged? | No: blank lines are left out of the dominant field count (the testkit already did this) |

Open when written, with the choice made here. Items marked *settled* were
answered later by ADR-0004; the rest are testkit conventions that no ADR
records yet, and task 1.2 confirms them or takes them to Rob (PLAN 1.2):

- **Trailing newline with an unterminated quote:** structural; the final
  newline is inside the field, so there is none. §3.7 rule 4 holds either
  way, because the bytes are kept. *Settled: ADR-0004 decision 4.*
- **CR followed by a blank LF line** (`a\r\nb`) is always CRLF, so a CR row
  followed by a blank LF row cannot be written. Worth knowing for edits:
  inserting a blank LF row after a CR row changes the file's structure (F6).
  *Settled: ADR-0004 decision 10 gives the later row a CR.*
- **Files with no delimiter or no line ending.** One-column, empty and
  single-row files expect `,` and (single row) `header = false`. *Testkit
  convention, not in an ADR.* What line ending new rows get in a file with
  none (§3.7 rule 3) was unspecified. *Settled: LF, ADR-0004 decision 3.*
- **A BOM-like start without a BOM.** The generator never starts a BOM-less
  file with `EF BB BF`, `FF FE` or `FE FF`. A real file whose first field
  begins with U+FEFF is ambiguous. *Settled for saving: ADR-0004 decisions
  7 and 10 quote such a field.*
- **The encoding rule counts invalid *bytes*, not sequences.** So
  `\xE2\x82` (a truncated `€`) counts as two. `Utf8Census` in `dialect.rs`
  implements that reading.
- **A final odd byte in a UTF-16 file** is an incomplete code unit. The
  testkit reports it as `invalid_encoding` at its offset, and displays it as
  U+FFFD. *Testkit convention, not in an ADR.*

## Save oracle and ADR-0004

The nine §3.7 questions the save oracle raised are answered by **ADR-0004
(save edge cases)**, accepted on 2026-09-30. The oracle follows it; the rules are
listed at the top of `crates/leal-testkit/src/save.rs`.

| ADR-0004 decision | In the oracle | Tested by |
|---|---|---|
| 1. "Quotes every field" = every field of every non-blank row | `Layout::quotes_every_field`; unchanged | `a_file_that_quotes_every_field_quotes_new_values`; `a_blank_line_does_not_stop_a_file_quoting_every_field` (added in the phase 0 review) |
| 2. New fields also quoted if their column is always quoted | **Not yet**: only the whole-file check. Marked `TODO(ADR-0004 #2)` in `save.rs`; task 2.4 adds it | — |
| 3. New rows in a file with no line ending use LF | Unchanged | `new_rows_in_a_file_with_no_line_ending_use_lf` (added in the phase 0 review: until then no unit test used a file with no line ending) |
| 4. Trailing newline kept; the line ending next to the change moves; an unterminated last row counts as no final line ending | Unchanged (confirmed: `a\n"b\nc\n` with row 1 deleted gives `a`) | `rows_insert_and_delete_with_the_trailing_newline_kept`; `deleting_an_unterminated_last_row_drops_the_line_ending_before_it` |
| 5. Short (ragged) rows untouched by column insert and delete; blank lines count as too short for every column | Blank lines are skipped by column inserts and deletes (while their one cell is unedited) | `columns_apply_to_rows_that_have_them`; `blank_lines_never_gain_or_lose_a_column`; `a_blank_line_survives_a_column_delete_then_insert` (added in the phase 0 review) |
| 6. A row that would have no bytes is written `""`; an original blank row stays blank | **New.** A blank row that would end up last in a file with no trailing newline (and so vanish) is written `""` too | `rows_that_would_have_no_bytes_are_written_as_empty_quotes`; the parse-back property, which no longer skips empty rows |
| 7. A U+FEFF field moved to offset 0 of a BOM-less file is quoted | **New** | `a_first_field_that_would_read_as_a_bom_is_quoted`; the parse-back property, which now asserts the BOM never changes |
| 8. No row inserted at or after an unterminated quote | **New**: `SaveError::AfterUnterminatedQuote`; the edit strategy drops refused edits | `nothing_can_be_inserted_inside_an_unterminated_quote` (corpus file); `edits_never_land_inside_an_unterminated_quote` (property) |
| 9. An edit equal to the original display value is no edit, invalid bytes included | Unchanged | `setting_the_displayed_value_keeps_invalid_bytes` (corpus file); `setting_cells_back_restores_the_original` (property) |
| 10. Reopening gives the same structure; the serializer makes the smallest extra change next to the edit | **New**: BOM-like first fields (`EF BB BF`, `FF FE`, `FE FF`) are quoted; a blank LF row after a lone CR gets CR. `SavedFile::line_endings` lists the rows a reopen must find | `reopening_a_saved_file_gives_the_same_structure` (property over every generated edit case, clean and messy); `a_lone_cr_never_joins_a_following_lf`; `utf16_bom_bytes_moved_to_the_start_are_quoted` (both `FF FE` and `FE FF` since the phase 0 review, which also added "þÿ" to `EDIT_VALUES` and counts each BOM kind in the coverage test) |
| 11. Remember a guessed encoding in `com.apple.TextEncoding` | **New**, as a model: `SavedFile::encoding_hint` and `dialect::reopen_encoding`. No real extended attributes | `an_encoding_hint_is_written_only_when_the_guess_would_differ`; `a_hint_beats_the_guess_but_not_a_bom`; the reopen property (reopens with the hint, no flip allowed); `encoding_can_flip_on_reopen` (without the hint) |

How decision 8 is implemented (both readings are now confirmed in
ADR-0004):

- **One invariant, checked after every edit:** an original, unedited
  unterminated field must stay the last thing in the file. An edit that
  breaks it is refused and the document is left unchanged. This covers a
  row inserted after the quote's row and a column inserted after the field.
  It also covers a case proptest found: edit the swallowed cell (which
  closes the quote), add a column after it, then set the cell back to its
  original value. That would reopen the quote over the new column, so the
  revert is refused.
- **Inserting a row at the quote's own row index** puts the new row before
  the opening quote, which is safe, so it is allowed.
- **A column inserted after the unterminated field** would also land inside
  the quote, so it is refused too.

### Reopen invariant (ADR-0004 decision 10)

The property `reopening_a_saved_file_gives_the_same_structure` saves every
generated edit case, reopens the bytes with the reference parser, and checks
the BOM, the encoding, every row's line ending and every value against the
document. It ran 90,000 cases clean after the fixes below.

- **Can a non-blank LF row merge with a lone CR before it?** No. A row's
  first byte is its first field's first byte: an unquoted field never
  contains LF, a quoted one starts with `"`, and a row that would be empty
  is written `""` (decision 6). Only an original blank row can start with
  LF, and that is the case decision 10 handles. `a_lone_cr_never_joins_a_following_lf`
  also checks a run of blank LF rows and a non-blank row after the CR.
- **No other structural merge cases turned up.** Moved rows keep their raw
  bytes, and quote-sensitivity only applies to a field's first byte, which
  column deletes don't change. The unterminated quote is decision 8.

### Encoding hint (ADR-0004 decision 11)

Without a BOM, the encoding is a whole-file heuristic (ADR-0003 decision 1).
An edit anywhere can tip it between UTF-8 and Windows-1252, and no splice
next to the edit can prevent that. ADR-0004 decision 11 has Leal record the
encoding in the macOS `com.apple.TextEncoding` extended attribute when that
happens. The testkit models the attribute as an **encoding hint**; it never
reads or writes real extended attributes (that is product work in tasks
1.1/1.2 and 2.5).

- `SavedFile::encoding_hint` is the hint a save must write: the document's
  encoding when a reopen without a hint would guess differently, or when the
  file already had a hint (`Document::with_existing_hint`), which is then
  updated. Otherwise `None`.
- `dialect::reopen_encoding(bytes, hint)` is how a reopen chooses: a BOM
  decides; otherwise a UTF-8 or Windows-1252 hint is always honoured; a
  UTF-16 hint on a file without a UTF-16 BOM is ignored. Invalid bytes
  under a UTF-8 hint get the usual `invalid_encoding` diagnostic
  (`diagnostics::derive` with the reopened encoding); the reopen property
  and `encoding_can_flip_on_reopen` both check this.
- The reopen property now reopens *with* the hint and requires the
  encoding to match exactly: no flip is allowed. It also checks that the
  hint is written exactly when needed: when the guess would differ, or to
  update a hint the file already had. The edit strategy gives one file in
  five an existing hint (`EditCase::existing_hint`).

Without the hint (another app, or a file that travelled by email or git),
the guess can still flip. Proptest found three ways, kept as a documented
test in `encoding_can_flip_on_reopen`, which also checks that each one
reopens correctly with the hint:

1. A Windows-1252 file loses its last high byte, becomes pure ASCII, and
   reopens as UTF-8. The text decodes the same, but later edits would be
   encoded as UTF-8.
2. A UTF-8 file that already has invalid bytes loses a valid multibyte
   character, so valid sequences no longer outnumber invalid bytes, and it
   reopens as Windows-1252. The remaining `é` then reads as `Ã©`.
3. A Windows-1252 file loses its only byte that isn't part of a valid UTF-8
   sequence, and what is left (for example `C3 A9`, "Ã©") is valid UTF-8, so
   it reopens as UTF-8 and reads as `é`.

### Obligations for later tasks

The save oracle's properties stop at what the testkit can know. These are
left to the tasks that build the real thing:

- **Task 1.2 (detection):** the reopen property reopens with the file's
  *own* delimiter and never checks delimiter or header detection, because
  the testkit has no detector. Once 1.2 exists, reopening an edited file
  must also give the same delimiter and the same header decision. *Detection
  alone can't promise that, since both are guessed from the whole file;
  ADR-0005 decision 1 (proposed) remembers them in an attribute instead, so
  the check is made with that attribute modelled, like the encoding hint.*
  1.2 should add that check to the reopen property, and test the encoding hint
  on real reads: a hint that contradicts the guess (the generated existing
  hints always equal the document's encoding), a UTF-16 hint without a BOM,
  and a UTF-8 hint over invalid bytes.
- **Task 2.2 (serializer):** replay `EditCase` edits on the real document

## Rust notes

- **Dev-dependencies.** A crate's `[dependencies]` are compiled into it and
  everything that uses it. `[dev-dependencies]` are only compiled for its
  tests, examples and benchmarks. So when `leal-core` lists `leal-testkit`
  under `[dev-dependencies]`, `cargo build` and release builds never see the
  testkit or proptest. The testkit itself lists proptest as a normal
  dependency because its public functions return proptest strategies.
- **Unit tests vs integration tests.** A `#[cfg(test)] mod tests` block at
  the bottom of a source file is a *unit test*: it is compiled into the
  crate, so it can use private functions (see `normalize` in
  `src/strategies/csv.rs`). Each file in a crate's `tests/` directory is an
  *integration test*: a separate crate that sees only the public API, like a
  user would. Shared test code goes in a subdirectory module
  (`tests/oracle/mod.rs`) that each test file includes with `mod oracle;`.
  That is why the oracle can't leak into product code: it is not part of
  the library at all.
- **Property-based testing.** Instead of writing example inputs, you say
  what *kind* of input to generate and a property that must hold for all of
  them. Proptest generates 256 random inputs per test (or `PROPTEST_CASES`).
  When one fails, it *shrinks* it: it tries smaller and simpler versions
  until it finds the smallest input that still fails, and prints it. The
  blank-row bug above shrank to a 5-byte file. Failing seeds are saved in a
  `.proptest-regressions` file and re-run first next time.
- **Strategies.** A `Strategy` is a recipe for generating values, and knows
  how to shrink them. Small ones combine into big ones: `vec(s, 0..10)` is a
  list of `s`, `(a, b)` is a pair, `select(&[..])` picks from a list,
  `prop_oneof![3 => a, 1 => b]` picks a strategy with weights, `prop_map`
  transforms the value, and `prop_flat_map` makes one choice depend on
  another (the number of fields decides the row strategy in `csv_file`).
  Inside `proptest! { ... }`, prefer `prop_assert!` to `assert!`. Proptest
  catches panics and shrinks a failing `assert!` too, but `prop_assert!`
  returns an `Err` instead of panicking. That keeps panic messages from
  flooding the output on every shrink step, and it works alongside `?`.
- **Why a model.** `csv_file` generates the *meaning* first (rows of values,
  a dialect), then writes the bytes and records where everything went. Tests
  get both the input and the right answer, so they can check a parser
  without a second parser.
- **`impl Trait`.** `pub fn csv_file(config: CsvConfig) -> impl
  Strategy<Value = GeneratedCsv>` means "returns some type that implements
  `Strategy`". The real type is a long nest of combinator types nobody wants
  to write; `impl Trait` hides it while keeping it fully typed and fast. In
  argument position, `Change::replace(range, replacement: impl Into<Vec<u8>>)`
  means "any type convertible to `Vec<u8>`", so callers can pass `"text"`,
  `b"bytes"` or a `Vec<u8>`. When two branches would return *different*
  strategy types, they are boxed into one type with `.boxed()`
  (`BoxedStrategy`, see `line_endings` in `csv.rs`).
- **Generics.** `fn mode<T: PartialEq + Copy>(items: impl Iterator<Item = T>)`
  in `layout.rs` works for any item type that can be compared and copied: it
  finds the most common line ending and the most common field count with
  the same code. `fn sample<S: Strategy>(strategy: S, n: usize) ->
  Vec<S::Value>` in `tests/generator.rs` uses the strategy's *associated
  type* `Value` to name what it produces.
- **`?` with test failures.** `check_only_changed` returns `Result<(),
  FidelityError>`. `FidelityError` implements `std::error::Error`, and
  proptest converts any `Error` into a test failure, so `check_...(..)?`
  inside a proptest body fails the case with the full report.
- **`#[track_caller]`** on `assert_only_changed` makes a panic report the
  line in *your* test that called it, not a line inside the testkit.
- **Serde.** `#[derive(Deserialize)]` generates the code that reads a Rust
  struct from TOML. `#[serde(deny_unknown_fields)]` makes a typo in a
  sidecar an error rather than silently ignored, and
  `#[serde(try_from = "String")]` on `Delimiter` reads it as a string first
  and converts it with our own `TryFrom`, which can reject bad values.
- **`Range<usize>`** (`3..6`) is half-open: it includes 3, 4 and 5. Spans
  use it throughout, and `bytes[span.clone()]` slices the bytes. It needs
  `.clone()` because a `Range` is an iterator, so Rust doesn't copy it
  implicitly.
- **Borrowing and lifetimes.** `save::Document<'a>` doesn't copy the file:
  it holds *references* (`&'a [u8]`, `&'a Layout`) to bytes and a layout
  owned by someone else, usually a `GeneratedCsv`. The `'a` is a
  *lifetime*: a name for "as long as those borrowed values live". The
  compiler uses it to guarantee a `Document` can never outlive the file it
  points into, so there is no dangling pointer to catch at run time. That
  is why `GeneratedCsv::document(&self)` returns `Document<'_>`: the
  document borrows from `self`. In `strategies/edits.rs`, `resolve` builds
  the document from `&file`, finishes with it, and only then moves `file`
  into the result; the compiler checks that order.
- **Enums with data.** `save::Edit` is an enum whose variants carry
  different fields (`SetCell { row, column, value }`, `DeleteRow { row }`).
  A `match` must handle every variant, so adding a new kind of edit makes
  the compiler point at every place that needs updating.
- **Struct update syntax.** `FieldLayout { span: new_span, ..f.clone() }`
  in `tests/oracle/mod.rs` builds a new struct with the fields listed and
  copies every other field from `f`. The oracle uses it to swap UTF-16 spans
  for file offsets while keeping each field's other properties.
- **`if let ... && ...`** (in `normalize`, `csv.rs`) chains pattern matches
  and conditions in one `if`; the body runs only if every part matches. It
  is new in the 2024 edition.
