# 0.2 Test harness and corpus

## What was built

### `crates/leal-testkit` (dev-only, `publish = false`)

A library crate that other crates use as a `[dev-dependencies]` entry. No
product crate depends on it normally, so it is never part of a release build
(`cargo tree -p leal-core -e normal` shows nothing).

| Module | What it holds |
|---|---|
| `fidelity` | `assert_identical` (F1), `assert_only_changed` (F2, F3, F6), `apply_changes`, `Change`, and `check_*` twins that return a `FidelityError` for use in proptest bodies. |
| `strategies::bytes` | `csv_bytes()`: arbitrary bytes built from chunks biased towards `, ; \t \| " \r \n`, CRLF, NUL, BOMs, invalid UTF-8 and multibyte UTF-8. |
| `strategies::csv` | The model-based generator: `csv_file(CsvConfig)` yields a `GeneratedCsv` with the model, the bytes, the expected `Layout`, the expected encoding and the expected diagnostics. `Messiness` switches each irregular construct on or off. |
| `layout` | `Layout` / `RowLayout` / `FieldLayout`: every row and field span, whether it is quoted, its display value (unescaped, or raw if there is text after the closing quote), and where that text begins. Also `check_tiles`, an invariant every parse must satisfy. |
| `diagnostics` | `DiagnosticKind`, `Location`, `Diagnostic`, and `derive(layout, bytes, utf8)`, the testkit's definition of what counts as one occurrence of each kind and where it is (ADR-0003 decision 4). |
| `dialect` | `Delimiter`, `LineEnding`, `Bom`, `Encoding`, and `expected_encoding`, the ADR-0003 encoding rule. |
| `corpus` | `load()` walks `tests/corpus/`, pairs each data file with its sidecar, parses and validates the sidecar, and reports *every* problem at once. |

The testkit does not depend on `leal-core`. It is an independent statement
of the rules, so the real parser can be tested against it.

### Reference parser (test oracle)

`crates/leal-testkit/tests/oracle/mod.rs` is a naive, byte-at-a-time parser
of the §3.4 rules. It lives in the testkit's *integration tests* only, so it
cannot be used by product code, and is marked as a test oracle at the top.
It checks:

- the generator: for every generated file, the oracle's layout equals the
  generator's, the model rebuilt from the parse equals the generated model,
  and copying every parsed span back out gives identical bytes;
- the corpus: every sidecar's row count, field counts, trailing newline,
  line endings, BOM, diagnostics (kinds, counts and locations) and cell
  values match what the oracle finds.

The oracle does no detection. It takes the delimiter and encoding from the
sidecar. Delimiter, encoding and header *detection* are task 1.2's job,
tested against the same sidecars. The corpus tests do check each sidecar's
encoding against `expected_encoding`, the ADR-0003 rule.

For UTF-16 the oracle parses a UTF-8 transcoding and maps every offset back
to a byte offset in the file (ADR-0003 decision 6). A UTF-16 file with a
surrogate pair before a ragged row pins that mapping.

### Corpus (`tests/corpus/`)

40 data files and 40 sidecars, 50 KB in all, written byte for byte by
`tests/corpus/generate.py` (standard-library Python). `--check` verifies the
committed files match the script. `tests/corpus/README.md` documents the
layout, sidecar format, conventions and how to add a file.

- `dialect/` (23): comma, semicolon, tab, pipe; LF, CRLF, CR, mixed; UTF-8
  with and without BOM, UTF-16 LE and BE with BOM, Windows-1252; all quoted;
  no trailing newline; empty; single column; single row; header and no
  header; quoted newlines (LF, CRLF and CR), quoted delimiters (all four),
  escaped quotes.
- `diagnostics/` (10): one per kind in §3.5, plus a blank line at the end of
  the file and a ragged row in UTF-16 LE.
- `exports/` (7): `imitation-excel-utf8-bom` (Windows),
  `imitation-excel-mac-utf8-bom`, `imitation-excel-windows-1252`,
  `imitation-google-sheets`, `imitation-numbers`, `imitation-pandas-to-csv`,
  `imitation-postgresql-copy`. These are stand-ins, not real exports; see
  "Imitation exports: sources".

Writing the oracle check caught my own mistake in a sidecar (off-by-one rows
in the pandas cells), which is the point of the cross-check.

**Byte-exactness.** `.gitattributes` marks the corpus `-text`. After staging,
the blob id of every corpus file in the index (`git ls-files -s`) was
compared with `git hash-object --no-filters` of the file on disk. All
matched (78 files at the first commit, 82 after the ADR-0003 update),
including the CR-only, CRLF, NUL, BOM, UTF-16 and invalid-UTF-8 files, so
git stores exactly the bytes the script wrote.

### Tests

61 tests via nextest plus 3 doctests, about 2 s in `just check`.

- Unit tests for every module, including exact failure-report tests for the
  fidelity helper (a full-report snapshot, a 10 MB input whose report stays
  under 1 KB, escaping, each `Origin`, and invalid change lists).
- Property tests: fidelity helper (accepts exactly the expected output;
  pinpoints a flipped byte and its origin; notices an inserted or dropped
  byte); clean and messy generator round trips; each `Messiness` flag
  produces only its own diagnostic; the oracle tiles arbitrary bytes.
- Coverage tests with a fixed seed: 2,000 messy files reach every
  diagnostic kind and both encodings, and 1,000 clean files reach every
  delimiter, line ending,
  quoting style, empty file, single row, single column, BOM, and quoted
  values containing each special byte. 500 byte inputs contain every special
  byte and sequence. These stop a generator from silently going dull.
- Corpus: loads, every file has a sidecar, sidecars match the oracle, each
  sidecar's encoding follows ADR-0003, the corpus covers every dialect and
  diagnostic kind and all the imitations,
  total size under 1 MB, and the loader reports missing sidecars, orphan
  sidecars and bad sidecars together.

`just test-deep` runs every test with `PROPTEST_CASES=20000` (about 22 s for
the testkit today); `just test-deep 100000` for more. Normal runs use
proptest's default of 256 cases.

A 20,000-case run found no failures. An earlier 256-case run found a real
generator bug (a blank last row with no line ending was repaired into `""`,
which then counted as ragged). It is fixed, and proptest saved the seed in
`crates/leal-testkit/tests/generator.proptest-regressions`, which is
committed so the case re-runs first every time.

## Conventions

These follow ADR-0003 (proposed, applied provisionally) and are documented
in `tests/corpus/README.md` and in the testkit's docs.

- **Coordinates:** 0-based physical row index; 0-based byte offsets into the
  file as stored, *including the BOM*, for every encoding including UTF-16.
  Spans are half-open (`start..end`).
- **Encoding:** a BOM decides; otherwise pure ASCII is UTF-8, a file with at
  least one valid multibyte sequence and more of them than invalid bytes is
  UTF-8 (with `invalid_encoding`), and anything else is Windows-1252.
- **Rows:** a line ending at EOF ends the last row and doesn't start another;
  an empty or BOM-only file has no rows; a row's span excludes its line
  ending; a field's span includes its quotes and any text after the closing
  quote.
- **Text after a closing quote:** part of the field; the field displays raw
  (`"a"b`); quotes in that text are literal.
- **Blank line:** a row with no bytes before its line ending, anywhere,
  including at the end. It has one empty field and is never ragged.
- **Trailing newline:** the last row has a line ending (structural). A file
  ending in an unterminated quote has none.
- **Ties** (most common line ending, field-count mode): the one seen first.
- **One occurrence** of each diagnostic: per row (ragged, blank, mixed line
  endings), per field (text after quote, invalid encoding, NUL), per file
  (unterminated quote, BOM). Offsets are listed per kind in the README.
- **Sidecar diagnostics are exhaustive:** a kind not listed must not be
  reported.

## How later tasks use the testkit

Add to the crate's `Cargo.toml`:

```toml
[dev-dependencies]
leal-testkit.workspace = true
proptest.workspace = true
```

**Parser against the model (1.3, 1.4).** Convert the parser's output into a
`Layout` in test code and compare:

```rust
use leal_testkit::strategies::csv::{CsvConfig, csv_file};
use proptest::prelude::*;

proptest! {
    #[test]
    fn rows_match_the_model(file in csv_file(CsvConfig::messy())) {
        let index = RowIndex::build(&file.bytes, file.delimiter().byte());
        let starts: Vec<usize> = file.layout.rows.iter().map(|r| r.span.start).collect();
        prop_assert_eq!(index.row_starts(), starts);
    }
}
```

**Diagnostics (1.5):** compare against `file.diagnostics`, or
`leal_testkit::diagnostics::derive(&layout, &bytes, utf8)`. Generated files
carry `file.encoding` (by the ADR-0003 rule); `invalid_encoding` is only
expected when that is UTF-8.

**F1 on any bytes (2.2):**

```rust
use leal_testkit::{fidelity::check_identical, strategies::bytes::csv_bytes};

proptest! {
    #[test]
    fn save_with_no_edits_is_identical(bytes in csv_bytes()) {
        let out = Document::from_bytes(bytes.clone()).save_to_vec();
        check_identical(&bytes, &out)?; // `?` fails the case with the report
    }
}
```

**F2 on one field (2.2):** the expected change is that field's span, replaced
by the new value quoted as §3.7 says:

```rust
use leal_testkit::fidelity::{Change, check_only_changed};

let field = &file.layout.rows[r].fields[c];
let change = Change::replace(field.span.clone(), expected_bytes_for(new_value, field));
check_only_changed(&file.bytes, &out, &[change])?;
```

**Detection (1.2) against the corpus:**

```rust
for case in leal_testkit::corpus::load().unwrap() {
    let d = detect(&case.bytes);
    assert_eq!(d.delimiter, case.sidecar.dialect.delimiter.byte(), "{}", case.name);
}
```

`CsvConfig { messiness: Messiness { ragged_rows: true, ..Messiness::NONE },
..CsvConfig::clean() }` asks for one construct only. `CsvConfig::clean()`
has none; `CsvConfig::messy()` has them all. Row, field and value sizes are
in `CsvConfig` too.

## Ambiguities in DESIGN §3.2, §3.4 and §3.5

Writing the generator and the oracle turned up these. ADR-0003 (proposed,
applied provisionally) resolved the main ones, and the testkit, corpus and
README follow it:

| # | Question | ADR-0003 answer |
|---|---|---|
| 1 | §3.2 "UTF-8 if valid, else single-byte" meant the invalid-UTF-8 warning could never fire | UTF-8 if ≥ 1 valid multibyte sequence and they outnumber invalid bytes; ASCII is UTF-8; else Windows-1252 |
| 2 | Display value of `"a"b` | Raw: `"a"b` (as ADR-0002 question 6 had decided). *I had chosen `ab`; changed.* |
| 3 | Quotes in text after a closing quote | Literal: `"a"b"c",` is one field, raw `"a"b"c"` |
| 4 | What one occurrence is; tie-breaks | Per row, per field or per file (see Conventions); ties go to the first seen. *Invalid encoding and NUL were per sequence and per byte; now per field.* |
| 5 | Blank lines only "in the middle"? | Anywhere, including the end; the final line ending is not a blank line |
| 6 | UTF-16 offsets | Byte offsets into the file as stored. *Previously only counts were compared; now locations are too.* |

Still open, with the choice made here:

- **Is a blank line ragged?** ADR-0003 says the dominant field count is "the
  most common field count", without saying whether blank rows count. The
  testkit leaves blank rows out of the mode and never reports them as
  ragged, so a blank line is reported once, as a blank line.
- **Trailing newline with an unterminated quote:** structural; the final
  newline is inside the field, so there is none. §3.7 rule 4 holds either
  way, because the bytes are kept.
- **CR followed by a blank LF line** (`a\r\nb`) is always CRLF, so a CR row
  followed by a blank LF row cannot be written. Worth knowing for edits:
  inserting a blank LF row after a CR row changes the file's structure (F6).
- **Files with no delimiter or no line ending.** One-column, empty and
  single-row files expect `,` and (single row) `header = false`. What line
  ending new rows get in a file with none (§3.7 rule 3) is unspecified.
- **A BOM-like start without a BOM.** The generator never starts a BOM-less
  file with `EF BB BF`, `FF FE` or `FE FF`. A real file whose first field
  begins with U+FEFF is ambiguous.
- **The encoding rule counts invalid *bytes*, not sequences.** So
  `\xE2\x82` (a truncated `€`) counts as two. `Utf8Census` in `dialect.rs`
  implements that reading.

## Dependencies

- **`proptest` 1.11** (workspace dependency, default features off, `std`
  only). Already on the preferred list. With `fork` and `timeout` off, it
  doesn't pull in `rusty-fork` or `tempfile`; nextest already isolates each
  test in its own process. It is a *normal* dependency of the testkit,
  because strategies are part of its API, and a dev-dependency everywhere
  else.
- **`serde` 1 (derive) and `toml` 1.1** (`parse` and `serde` only, no
  writer): parse the sidecars. Allowed by the brief.

These add 36 package entries to `Cargo.lock`, all dev-only.

## Deviations

- **`.gitattributes`:** the corpus's `generate.py`, `README.md` and
  `*.expected.toml` get `diff merge` back, so reviewers can read their diffs.
  They stay `-text`, so git still never converts line endings; data files
  stay `binary`.
- **Root `Cargo.toml`:** `leal-testkit` and `proptest` were added to
  `[workspace.dependencies]` (5 lines). `justfile`: one recipe,
  `test-deep`.
- **Oracle diagnostics:** the oracle's diagnostics use the testkit's shared
  `diagnostics::derive`, so it is the layout (spans, quoting, text after
  quote, unterminated) that is checked independently. `derive` itself is
  checked against the hand-written sidecars.

## Imitation exports: sources

The imitations follow documented or reported behaviour. None is a real
export.

| File | Line endings | Source |
|---|---|---|
| `imitation-pandas-to-csv` | LF | pandas `DataFrame.to_csv` docs: `lineterminator` "Defaults to os.linesep" (LF on macOS); `quoting` defaults to `QUOTE_MINIMAL`; `index=True`. <https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.to_csv.html> |
| `imitation-postgresql-copy` | LF | PostgreSQL `COPY` docs: "`COPY TO STDOUT` always sends `\n` regardless of server platform"; NULL is an unquoted empty string and an empty string is `""`. <https://www.postgresql.org/docs/current/sql-copy.html> |

| `imitation-numbers` | LF | **Unverified.** No source found for Numbers' line endings or quoting. |

## Rust notes

- **Dev-dependencies.** A crate's `[dependencies]` are compiled into it and
  everything that uses it. `[dev-dependencies]` are only compiled for its
  tests, examples and benchmarks. So when `leal-core` lists `leal-testkit`
  under `[dev-dependencies]`, `cargo build` and release builds never see the
  testkit or proptest. The testkit itself lists proptest as a normal
  dependency because its public functions return proptest strategies.
- **Unit tests vs integration tests.** A `#[cfg(test)] mod tests` block at
  the bottom of a source file is a *unit test*: it is compiled into the
  crate, so it can use private functions (see `normalize` in
  `src/strategies/csv.rs`). Each file in a crate's `tests/` directory is an
  *integration test*: a separate crate that sees only the public API, like a
  user would. Shared test code goes in a subdirectory module
  (`tests/oracle/mod.rs`) that each test file includes with `mod oracle;`.
  That is why the oracle can't leak into product code: it is not part of
  the library at all.
- **Property-based testing.** Instead of writing example inputs, you say
  what *kind* of input to generate and a property that must hold for all of
  them. Proptest generates 256 random inputs per test (or `PROPTEST_CASES`).
  When one fails, it *shrinks* it: it tries smaller and simpler versions
  until it finds the smallest input that still fails, and prints it. The
  blank-row bug above shrank to a 5-byte file. Failing seeds are saved in a
  `.proptest-regressions` file and re-run first next time.
- **Strategies.** A `Strategy` is a recipe for generating values, and knows
  how to shrink them. Small ones combine into big ones: `vec(s, 0..10)` is a
  list of `s`, `(a, b)` is a pair, `select(&[..])` picks from a list,
  `prop_oneof![3 => a, 1 => b]` picks a strategy with weights, `prop_map`
  transforms the value, and `prop_flat_map` makes one choice depend on
  another (the number of fields decides the row strategy in `csv_file`).
  Inside `proptest! { ... }`, use `prop_assert!` rather than `assert!`, so
  that proptest can shrink the failure instead of just crashing.
- **Why a model.** `csv_file` generates the *meaning* first (rows of values,
  a dialect), then writes the bytes and records where everything went. Tests
  get both the input and the right answer, so they can check a parser
  without a second parser.
- **`impl Trait`.** `pub fn csv_file(config: CsvConfig) -> impl
  Strategy<Value = GeneratedCsv>` means "returns some type that implements
  `Strategy`". The real type is a long nest of combinator types nobody wants
  to write; `impl Trait` hides it while keeping it fully typed and fast. In
  argument position, `Change::replace(range, replacement: impl Into<Vec<u8>>)`
  means "any type convertible to `Vec<u8>`", so callers can pass `"text"`,
  `b"bytes"` or a `Vec<u8>`. When two branches would return *different*
  strategy types, they are boxed into one type with `.boxed()`
  (`BoxedStrategy`, see `line_endings` in `csv.rs`).
- **Generics.** `fn mode<T: PartialEq + Copy>(items: impl Iterator<Item = T>)`
  in `layout.rs` works for any item type that can be compared and copied: it
  finds the most common line ending and the most common field count with
  the same code. `fn sample<S: Strategy>(strategy: S, n: usize) ->
  Vec<S::Value>` in `tests/generator.rs` uses the strategy's *associated
  type* `Value` to name what it produces.
- **`?` with test failures.** `check_only_changed` returns `Result<(),
  FidelityError>`. `FidelityError` implements `std::error::Error`, and
  proptest converts any `Error` into a test failure, so `check_...(..)?`
  inside a proptest body fails the case with the full report.
- **`#[track_caller]`** on `assert_only_changed` makes a panic report the
  line in *your* test that called it, not a line inside the testkit.
- **Serde.** `#[derive(Deserialize)]` generates the code that reads a Rust
  struct from TOML. `#[serde(deny_unknown_fields)]` makes a typo in a
  sidecar an error rather than silently ignored, and
  `#[serde(try_from = "String")]` on `Delimiter` reads it as a string first
  and converts it with our own `TryFrom`, which can reject bad values.
- **`Range<usize>`** (`3..6`) is half-open: it includes 3, 4 and 5. Spans
  use it throughout, and `bytes[span.clone()]` slices the bytes. It needs
  `.clone()` because a `Range` is an iterator, so Rust doesn't copy it
  implicitly.
- **Struct update syntax.** `FieldLayout { span: new_span, ..f.clone() }`
  in `tests/oracle/mod.rs` builds a new struct with the fields listed and
  copies every other field from `f`. The oracle uses it to swap UTF-16 spans
  for file offsets while keeping each field's other properties.
- **`if let ... && ...`** (in `normalize`, `csv.rs`) chains pattern matches
  and conditions in one `if`; the body runs only if every part matches. It
  is new in the 2024 edition.
