# 2.5.3a App: Save

⌘S, and Save from the close and quit alerts, now save through the core's
save job (ADR-0012) instead of `NSDocument`'s own writing. The job runs
inside a coordinated write (`NSFileCoordinator`, `.forReplacing`), one
file access at a time (`performAsynchronousFileAccess`). The main thread
never waits for it. Edits carry on during a save; edits made after its
snapshot stay unsaved. Each refusal has its own wording and buttons.
Adopting the rebased reading and `keptOldFile` are 2.5.3b. Save As and
Revert are 2.5.3c.

## How it works

**Entry point.** AppKit's ⌘S (`saveDocument:`) and its close and quit
alerts all call `saveDocumentWithDelegate:didSaveSelector:contextInfo:`.
Leal overrides that method for any document with a file. It never reaches
`NSDocument`'s `save(to:…)`, so `NSDocument`'s own checks (changed by
another app, locked file) never run. The user sees only Leal's prompts.
Any open edit is committed first. Saves run one after another: a second
Save waits for the first. The delegate is told whether the save worked.

**One save, step by step** (`saveInPlace`):
1. If `canSave` is false (UTF-16, drive gone, an incomplete read, or the
   core reading an un-adopted UTF-8 copy), the matching refusal is shown.
2. If the watcher saw a change (`original.diverged`, which stays set
   after Keep Editing), Leal asks before writing. Save Anyway sets
   `overwriteChanged`. It doesn't ask for a file the watcher saw deleted.
3. `performAsynchronousFileAccess`. Inside it, `CoordinatedWrite.begin`
   coordinates a `.forReplacing` write, with the document as file
   presenter. The coordinator's accessor runs on an `OperationQueue`
   thread. It hands back the URL, which follows a move made while waiting
   for access, then blocks on a semaphore until the save ends. No main
   thread or Swift-pool thread waits.
4. `DocumentModel.save`, on `FileWork`'s queue, asks `FileManager` for two
   item-replacement folders on the file's volume: one for the new file,
   one for the snapshot. Then the core's job starts. Every 100 ms its
   progress is read for the status bar.
5. When the save succeeds:
   - `fileModificationDate` is set from `SaveOutcome.modified`;
   - the change-count token noted at `snapshotVersion` is applied
     (`updateChangeCount(withToken:for: .saveOperation)`);
   - the journal drops the commands up to that version
     (`savedThrough`);
   - the model takes the watcher's new status, so `diverged` is cleared,
     and reads the core's dirty state again;
   - `updateDirtyState()` runs. An edit made during the save keeps the
     document edited.
   - `skippedMetadata`, `rereadError` and `keptOldFile` are logged.
6. When the save fails, `SaveText.saveFailure` gives the alert:

| Failure | Title | Buttons |
|---|---|---|
| `ChangedElsewhere` | "“a.csv” changed on disk since Leal opened or last saved it." | Save Anyway (destructive), Cancel |
| `Locked` | "“a.csv” is locked." | Unlock, Duplicate, Cancel |
| `NotWritable` | "You don’t have permission to save “a.csv”." | Duplicate, Cancel |
| `Unencodable` | "Some cells can’t be saved in Windows-1252." Lists up to 8 cells ("• Row 3, column 2"), then "and N more", or "and more" when `more` is set. | Save As UTF-8…, Cancel |
| `Missing` | "“a.csv” can’t be found." | Save As…, Cancel |
| `Moving` | Retried 3 times, 250 ms apart, then "wasn’t saved… Try again in a moment." | Try Again, Cancel |
| `Unavailable`, `Incomplete`, `DriveDisconnected`, `ChangedOnDisk`, `DeletedElsewhere` | "“a.csv” wasn’t saved." with the reason | Save As… (and Cancel) |
| `ReadOnly` | as above | Save As UTF-8…, Cancel |
| `TooLarge`, `NotAFile`, `Io`, `Internal`, `Unconvertible` | as above | OK |
| `Cancelled`, `DocumentFailed` | nothing (the failure alert speaks for itself) | |

   The core's English goes only to the log. Unlock clears `UF_IMMUTABLE`
   and `UF_APPEND` with `chflags`, off the main thread, then saves again.
   If that fails, Leal says so and offers Duplicate. When the core says
   `ChangedElsewhere` and nothing is at the path any more, Leal shows
   Missing instead, so the user is never asked whether to overwrite a
   file and then told it's gone.

**What Save does for a deleted file** (PLAN): it says "can’t be found" and
offers Save As…. It doesn't recreate the file.

**Item-replacement folders and their fallback.** Both folders come from
`FileManager.url(for: .itemReplacementDirectory, appropriateFor:)`, which
a sandboxed app may write to. There are three fallbacks:
- Where no folder can be made, or the one made is on another volume, the
  core uses its own hidden `.leal-save-<id>` folder next to the file.
- A network share never gets a snapshot folder, so the snapshot is the
  tee copy on the internal disk (task 2.0).
- After the save, any folder the core didn't take over (it refused before
  writing) is removed with `rmdir`. That only removes empty folders.

The exFAT and APFS hosted test checks that the item-replacement folder was
used and nothing was left on the drive.

**Progress.** The status bar shows "Saving…", "Reading the file before
saving…", "Checking the file before saving…" (`SavePhase::Checking`, a
step with its own 0–100%), "Waiting to save…" or "Finishing saving…". The
progress bar shows the save's fraction. It appears at the first poll
(100 ms), so a quick save doesn't flash. While saving, these are off with
"Wait for the save to finish.": Treat As, Reopen with Encoding, the Header
row toggle, Reload, and a second Save. Cell edits and their undo carry on.

**Cancel.** ⌘. or Escape (`cancelOperation`) cancels the save task.
`SaveJob.outcome()` passes that to `job.cancel()` (ADR-0005 decision 6).
Before the new file is in place, nothing is written. Leal shows no alert,
and the edits stay unsaved.

**Seams closed.**
- `SEAM(2.5.3)` in `EditHistory` and `CSVDocument.canRecover`: the
  journal is reset at the save's snapshot.
- `canClose`: closing's Save now saves through the core.
- Save As UTF-8's declined adopt: until a Reload, `readsUTF8Copy` turns
  Save off and asks for Save As UTF-8 again. 2.5.3c's adoption removes
  this.
- `PendingOpens.Facts.modified` being `nil` doesn't matter: Save never
  relies on it, because the core's check always opens the file afresh and
  compares its identity (ADR-0008 decision 9).
- `SEAM(2.5)` in `DocumentViewController`: Save As UTF-8's progress now
  shows, because it uses the same `DocumentModel.save`.

## Tests

`SaveTests` has 13 hosted tests, against the real core and sandboxed.
- **Bytes.** A Save gives byte-for-byte the same file as the core's own
  save (`DocumentModel.save`, without NSDocument or coordination) of the
  same edits. Quoting is checked too. Afterwards the document is clean,
  the journal is empty, `fileModificationDate` matches the file, and undo
  still works.
- **Held save** (`debugHoldNextSave`). The save is held after its
  snapshot:
  - ⌘S returns at once;
  - an edit and a read while held finish in under 0.5 s;
  - "Saving…" and the progress bar show;
  - Header row, Treat As, Reload and Save are off.
  
  After release, the edit made during the save isn't in the file and
  stays unsaved, and the journal holds only that edit. A second Save then
  writes it with no prompt.
- **Cancel** while held (`cancelOperation`): the file is unchanged, no
  alert, still edited.
- **Close's Save** (`save(withDelegate:…)` with a delegate): saved, and
  the delegate hears `true`.
- **Changed before the watcher said so:** one prompt, no sheet from
  `NSDocument`, Save Anyway writes. **Changed after the watcher said so**
  (`diverged`): asks first, and Cancel writes nothing.
- **Locked** (`chflags UF_IMMUTABLE`): Duplicate leaves the file locked
  and untouched, and calls the follow-up. Unlock clears the flag and
  saves.
- **Read-only** (`chmod 0444`): Duplicate or Cancel; Cancel changes
  nothing.
- **Unencodable** (a Windows-1252 file with 😀 and ✓): both cells named,
  Save As UTF-8… offered, nothing written. A unit test checks 8 cells
  named then "and 2 more", and "and more" with 1,000 cells and `more`.
- **Missing:** only "can’t be found", and Save As… offered.
- **Wording:** every `SaveFailure` has its own text, never the core's
  English, and the last button is the way out.
- **Status bar:** each step, with `Checking` at 25%.

`RemovableDriveTests.testSaveOnARemovableDriveWritesTheFileAndLeavesNothing`:
Save on APFS (swap) and exFAT (rename) disk images, through the
disk-image helper. The bytes are right and nothing is left on the drive.
Its images are detached (`hdiutil info` shows none).

`SaveAsUTF8Tests`: a declined adopt sets `readsUTF8Copy` and Save stays
off.

Results:
- `just check-all` passes: 913 Rust tests, and `app-test` Debug 280
  passed.
- `just app-test release`: 280 passed.
- `just check-no-test-exports` and `just check-no-bench` pass.

No hot path changed: the status bar reads a save's progress every 100 ms,
and only while a save runs.

## Deviations and notes for Rob

- **The override is `saveDocumentWithDelegate:…`**, not `save(to:…)`.
  This skips `NSDocument`'s own checks, so only one prompt about a
  changed file ever shows (PLAN).
- **Duplicate opens Save As** (`saveAs(nil)`): a Leal document is always
  a file. Save As through the core is 2.5.3c. Until then, Duplicate and
  Save As… from these alerts fail with AppKit's error.
- **No rebased-reading adoption (2.5.3b).** After a Save, edited-cell
  triangles stay on cells already drawn until their tiles are read again.
  The new reading's diagnostics are picked up only when `checkOriginal`
  next restarts the model. The title's "— Edited" and the dirty state are
  correct.
- **No Cancel button.** Cancel is ⌘. and Escape; the mockups have no save
  progress UI. Rob: say if you want a stop button by the progress bar.
- **On-screen check for Rob:**
  - ⌘S on an edited file;
  - Save while another app has changed it;
  - a locked file (Finder ▸ Get Info ▸ Locked): Unlock;
  - an emoji in a Windows-1252 file;
  - a large file, to see the progress (and Checking after a column
    insert, once 2.5a's UI exists);
  - ⌘. during a long save;
  - **a network share**, if you have one. No share was available here, so
    the SMB swap or rename, `.TemporaryItems` on the share, and
    coordination there are untested.

## Rust notes

- `#[cfg(any(test, feature = "test-hooks"))]`
  (`crates/leal-core/src/document/saving.rs`): code inside is compiled
  only for the crate's own tests or when another crate turns on the
  `test-hooks` feature. leal-ffi's `test-exports` turns it on, for the
  app's tests only. The shipped library has neither, so the hook
  (`save_hooked`) isn't in it (`just check-no-test-exports`).
- The hold (`crates/leal-ffi/src/document/saving.rs`, `mod hold`):
  - `static NEXT: Mutex<Option<Arc<Hold>>>` is a global that any thread
    can lock. `Mutex::new` is a `const fn`, so a static can start with it.
  - The save thread waits on a `Condvar` (condition variable) until
    `released` is true. `wait` gives up the lock while it sleeps and takes
    it back on waking. The `while` loop guards against waking for no
    reason.
  - `OnceLock` holds the save job, set once after it starts, so the hook
    can see whether the snapshot has been taken.
  - `AtomicBool` makes sure the save is held only once.
