# 2.G-c — Phase 2 gate fixes, round C: saving, reconnecting, paste, tests

The phase 2 gate's confirmed should-fixes in saving, network shares,
paste and test strength, and the cheap Rust, Swift and test nits.

## Should-fixes

1. **A file created before 1970 saves** (`source/sys.rs`,
   `set_creation_time`). A pre-epoch creation date was turned into an
   `InvalidInput` error with no errno, which the best-effort metadata
   step doesn't skip, so the save failed outright. It is now a negative
   `tv_sec` with the nanoseconds counted forward (`timespec_of`), and a
   date that doesn't fit a `time_t` is `EINVAL`, which a save skips and
   names. Tests: `a_creation_date_before_1970_is_a_negative_timespec`,
   `a_file_created_before_1970_saves_and_keeps_its_date` (whole seconds
   and with nanoseconds).
2. **Reconnecting a share opens its file before taking the writer lock**
   (`document/mod.rs`, `reconnect_and_restart`; ADR-0009). The reopen is
   now two steps: `Source::reopen` (opens the clone or the user's file
   and compares inode, size and modification time, with no lock held)
   and `Source::finish_reconnect` (no I/O: takes the streaming and
   external locks, checks again that a reconnect is still wanted and, for
   the clone, that no other reconnect fell back meanwhile, then swaps the
   file in). The document reopens, then takes the writer lock, re-checks
   the save and that the reading is the same, and installs.
   `Source::reconnect` keeps both steps for its other callers. Test:
   `edits_while_a_share_stalls_on_reopening_dont_wait` holds the reopen
   with a test-only hook (`set_reopen_hook`, `cfg(test)`): an edit and an
   undo meanwhile return within a second. It fails with the reopen moved
   back under the lock.
3. **Leal's own Copy pastes back whole** (`document/values.rs`,
   `end_copy`). The rule: Paste still drops one line break at the end
   (2.6 decision 1, decision D); Copy ends with a line break *only when its
   last line is empty* (a one-column copy ending in an empty cell, or one
   empty cell, which becomes a lone line break: a spreadsheet's copy of an
   empty cell). So `["a", ""]` copies as `"a\n\n"`, two rows, and is no
   longer read as the one value `"a"` that fills the selection; two empty
   cells (`"\n\n"`) clear two cells, not the selection. Every other copy is
   byte for byte as before (a one-cell copy still pastes into a text field
   as just the value; no existing exact-text test changed). DESIGN §4.2 and
   `edit/paste.rs` say so. Tests: `a_copy_whose_last_cell_is_empty_pastes_back_whole`
   and the property `copy_then_parse_gives_back_the_cells` (any rectangle,
   values with tabs, quotes, line breaks and empties); the edit property's
   Copy check follows the rule.
4. **Duplicate Row in the oracle, the properties and the fuzz target.**
   `leal-testkit`: `Edit::DuplicateRows { at, count }` and a new
   `Cell::Copy` (a copy of an edited field or hatched cell, quoted as its
   row quotes it, or of padding, dropped at the row's end once its hatched
   cell's column is gone, ADR-0014 decision 5; an edited copy is a new
   field, set back to how it reads it is a copy again). The edit strategy
   makes Duplicate Row edits of one to three rows, so the edit and save
   properties (undo after a save: the copies deleted by value) compare
   them with the real document; they agreed first time. `fuzz/`:
   `Op::DuplicateRows`. Example tests: the Windows-1253 Save As UTF-8
   refusal naming a copy's cell (kills the walk.rs `out_row += 1` mutants;
   the properties now do too, with `PROPTEST_CASES=1000`), and the
   oracle's cases on the real document.
5. **A hatched cell in an inserted or rewritten row**:
   `a_hatched_cell_in_a_new_or_rewritten_row_is_quoted_only_if_it_needs_it`,
   in a file with one column that quotes every field (a quote-all file
   can't tell the two rules apart). It fails with either `Hatched` arm in
   walk.rs deleted.

## Rust notes

- **Splitting work around a lock** (`Removable::reopen` and `install`,
  source/removable.rs). A `Mutex` guard unlocks when it is dropped, at the
  end of its scope. `reopen` takes the `external` lock in a block of its
  own just to copy out the clone's path and inode, so the guard is
  dropped before the slow `File::open`; `install` takes the locks only for
  the swap. Holding a lock across I/O is what made the main thread wait.
- **Passing an owned value between steps** (`Reopened`). `reopen` returns
  the opened `File` inside a struct; `install(reopened: Reopened)` takes it
  by value (moves it), so the file can't be installed twice, and if the
  document decides not to install it, dropping the struct closes the file.
- **`?` on `Option`** (`reopen`, `timespec_of`): in a function returning
  `Option`, `x?` returns `None` early when `x` is `None`, as it returns an
  `Err` early in a function returning `Result`.
- **`let ... else`** (`carry_over`): `let Some(values) = ... else { ...;
  continue; };` binds the value or runs the `else` block, which must leave
  the loop iteration or function.
- **A generic retry helper** (`retrying_erange<T>`, source/sys.rs) takes
  any closure `impl FnMut() -> io::Result<T>`: `FnMut` because the closure
  may change what it captured (the tests count calls).
- **A test-only hook** (`reopen_hook: Mutex<Option<Arc<dyn Fn() + Send +
  Sync>>>`, `#[cfg(test)]`): a shared, thread-safe callback that only test
  builds have, so the shipped library has neither the field nor the call.
  `Arc` lets `reopen` clone it out of the mutex and call it unlocked.
- **Matching on tuples of references** (`Document::copy_of` in
  leal-testkit/src/save.rs): `match (&r.cells[column], r.source)` matches a
  borrowed cell and a copied `Option<usize>` at once, with `_` for "any".
