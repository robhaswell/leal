# 2.3 Encoding on save

Edits are written in the file's own encoding, whichever of ADR-0005
decision 5's it is; a value the encoding can't hold stops the save, naming
the cells, and nothing is ever substituted (F5). **Save As UTF-8** writes a
file in any encoding as UTF-8 (ADR-0008 decision 7), streaming, and
refuses, naming the cells, when some of the file's bytes aren't text in its
encoding. The UTF-16 banner's **Save As UTF-8…** button (mockup 06a) works.
Also: `Document::unencodable(value)` for 2.5's check before an edit is
committed; the testkit's encodings, oracle and generators; a detection fix
the new UTF-16 generator found; Leal trusting encoding tags it wrote itself
(ADR-0013 decision 2); three benchmarks.

## Commits

### Encoding a value

For a single-byte encoding, `encode` uses a table of what each byte means,
built from the decoder that shows the file's values, and inverts it: each
character is written as the byte that reads back as it, and only then. So a
saved value shows again exactly, a value shown from the file encodes to its
own bytes, and an unassigned byte (shown as U+FFFD, which no single-byte
encoding has) is refused rather than written as something else. Every
edited value is checked before anything is written.

### Save As UTF-8

1. The edited rows' splices as for any save, in UTF-8; a fix that rewrites
   a row (`""`, a BOM-like first field) converts its unedited fields.
2. The bytes between splices converted as they are copied, 1 MiB at a time
   with a checkpoint before each (`encoding_rs` for UTF-16, which may split
   a pair between chunks; the tables for single bytes). A stretch between
   splices always ends on a whole character.
3. A UTF-8 BOM if the file had any BOM. Line endings, quotes and
   delimiters are ASCII in UTF-8, so they keep their meaning.
4. A sequence that isn't text (unpaired surrogate, final odd byte,
   unassigned single byte) names its cell; from then nothing is written,
   but the file is read on to name the rest (up to 1,000, then it stops
   with `more`), and the save is refused. Bytes inside an edited cell are
   never read, so editing a named cell lets the file convert.
5. `com.apple.TextEncoding` set to UTF-8; the interpretation attribute
   decided for the new bytes.
6. The rebase reads the new file as UTF-8 (a chosen encoding no longer
   applies). Every byte moved, so it waits for the new index pass (about
   60 ms per 100 MB) rather than shifting the old index: rows read at once
   and edits made during the save carry over.

From a UTF-8 file it is Save As with the attribute set; invalid bytes are
kept (F4).

### Leal's own encoding tags (ADR-0013 decision 2)

ADR-0004 decision 11 ignores a single-byte tag (not UTF-8 or 1252) when a
byte doesn't decode in it. Now the save (`AttributePlan::decide`) records
`encoding=<IANA name>`, with the fingerprint, in the interpretation
attribute when a reopen with the tag alone would use another encoding, or
when the file is over 64 KB and its encoding leaves a byte unassigned (only
the review would see it); delimiter and header as before, decided by a
reopen that reads the encoding as it will be. Detection then honours the
tag over undecodable bytes while the fingerprint matches
(`Detection::own_encoding_tag`), and the review doesn't second-guess it.
Other apps' tags keep decision 11. The fingerprint covers the length and
the first 64 KB, so an edit past 64 KB that keeps the length keeps Leal's
own tag (an ADR-0007 limit). An `encoding` Leal doesn't read from a tag
(unknown, malformed or UTF-16) is ignored with a status-bar note and the
rest of the attribute is kept. Older attribute values read as before;
older Leal ignores the key. The testkit models it with
`reopen_encoding(bytes, hint, HintWriter::Leal)`.

## Decisions and interpretations

- **UTF-16 is editable, Save off** (ADR-0013 decision 1, accepted): Save As
  UTF-8 is the only way to save it, so the cells it names can be fixed and
  the copy tried again. The core already allows it; the app's part is 2.5.
- **Edits are allowed whatever the encoding holds**; Save refuses them
  (DESIGN §3.7). `unencodable(value:)` lets 2.5 warn before committing.
- **Tables invert the display decoder**, so what is saved reads back as
  what was shown. The testkit encodes with `encoding_rs`'s encoder instead,
  so the two check each other.
- **At most 1,000 cells named**, as many as a diagnostic locates (§3.5).
- **A converted file's rebase waits for its index pass.** The index pass
  is P1 work, which never pauses for the user (DESIGN §3.10), so a save's
  end doesn't wait for a scroll.
- **The app follows the copy by reading it again** (save, then a Reload at
  the new URL), not by adopting the core's rebased reading: that is 2.5's
  after-a-save path (SEAM(2.5)). UTF-16 documents have no edits to carry.
- **Save panel:** the file's name with "(UTF-8)" before the extension, in
  its folder.
- **Budget `save/utf8_from_utf16`: 1,000 ms** (ADR-0013 decision 3).
- **No new screenshots:** the banner is as in 1.6's approved 06a shot; the
  button now acts. The hosted tests check both states.

## What 2.4 and 2.5 need

- **2.4:** inserted rows and fields go through `RowRules` like edited
  cells, so Save As UTF-8 writes them in UTF-8 with nothing more. The
  converted rebase already waits for the index pass.
- **2.5:** word `Unencodable` (with `unencodable(value:)` for each cell's
  character) and offer Save As UTF-8 from it; warn while typing; replace
  `CSVDocument.saveAsUTF8`'s read-again with adopting the rebased reading;
  UTF-16 documents editable with Save off (ADR-0013 decision 1); show Save
  As UTF-8's progress (SEAM(2.5) at `savingAsUTF8`).
- **2.5, Windows-1258:** it refuses precomposed Vietnamese (typed "ế" is
  one character, which 1258 writes only as a base letter plus a combining
  mark). That is right under F5 (nothing substituted), so the warning for
  such a value should point to Save As UTF-8 rather than suggest retyping.

## DESIGN wording, for the docs merge

§3.7, after "…Leal never drops or substitutes characters.": "Values are
written in the file's own encoding, as the bytes that read back as them; a
character it has no byte for is refused, naming every such cell, before
anything is written."

§3.7, Save As UTF-8, replacing its last two sentences: "Text that can't be
converted (…) makes it refuse and name the cells (the first 1,000, and
whether there are more), as F5 requires; nothing is written. It streams,
converting a chunk at a time between the edited rows' splices, and the
document then reads the new file in UTF-8. From a UTF-8 file it is Save As
with the attribute set." DESIGN §1 and §4.3 change as ADR-0013 says.

## Rust notes

- **`Result<Cow<'_, [u8]>, Unencodable>`** (`save::encode`). `Cow` holds a
  borrowed slice (ASCII, UTF-8: no copy) or an owned `Vec` (other
  single-byte text). `Result` replaces `Option` so the refusal carries the
  character.
- **`static OnceLock`** (`SingleByte::of`): built the first time any thread
  asks, then shared read-only.
- **A stateful decoder** (`Transcoder`). A chunk can end mid-character;
  `encoding_rs::Decoder` keeps the unfinished part until the next call, and
  `last = true` turns a leftover half into an error. Each stretch between
  splices ends with `last` set; a fresh decoder starts the next.
- **`&mut dyn FnMut(usize)`** (`Transcoder::push`'s `bad`): a callback that
  changes what it captures. The sink collects offsets first and names cells
  after, since it can't be borrowed twice at once.
- **`std::mem::take`** (`FileSink`): moves a buffer or list out of a field,
  leaving an empty one, so it can be passed on without a copy.
- **A new trait method** (`Sink::refuse`): every sink must say what it does
  with unconvertible cells, or the code doesn't build.
