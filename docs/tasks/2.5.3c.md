# 2.5.3c App: Save As and Revert

Save As, Duplicate and Save As UTF-8 now save through the core's save
job (ADR-0012), in the same coordinated write and file access as Save
(2.5.3a), and the document then *is* the new file (ADR-0008 decision 1).
AppKit never writes. Save As from a document Leal couldn't read all of
writes complete rows only and says so (ADR-0008 decision 6, ADR-0010).
Save As UTF-8 adopts the core's reading of the copy instead of reading it
again. Revert to Saved goes the way Reload does, off the main thread.
A save that ends with `SaveJob.restarted()` takes up the new reading.

## How it works

**Save As** (`saveAs(to:)`). File ▸ Save As…, the alerts' Save As…, the
file banners' Save As… and Recover changes' Save As… all go to
`chooseSaveAs(.saveAs)`. It commits an open edit, then asks where through
`chooseSaveAsDestination`: an `NSSavePanel` sheet with the file's name and
folder (the panel asks itself before replacing a file). The save is then
queued behind any Save under way (`enqueueSave`), so it is a `saving` that
closing, quitting and ⌘. know about. Once its turn comes:
1. `saveCoordinated(url, kind: .saveAs)`: the same path as Save. It takes
   `performAsynchronousFileAccess`, a `.forReplacing` coordinated write
   of the **destination** (the document as presenter), and the
   item-replacement folders for the destination's volume. The core's job
   runs, with no main-thread wait.
2. Still inside the access (`noteWritten`, through
   `continueAsynchronousWorkOnMainThread`), `NSDocument` hears the new
   file. Its `fileURL` is set to the name on disk the core reports
   (`SaveOutcome.path`), and its `fileType` (TSV or CSV) from the
   extension. `fileModificationDate` is set, and the token noted at the
   save's snapshot is applied (`.saveAsOperation`). This is where
   `NSDocument`'s own Save As does it.
3. `saveFinished` drops the journal up to the snapshot. Then
   `model.saved(_:kind:)`: the model takes the new URL and the watcher's
   status for the new file (the core's watcher already follows it,
   `Original::replace_with`) and adopts the core's reading of it
   (`adoptSaved`, 2.5.3b). The journal's choices follow the reading, and
   the file goes in Open Recent.
4. Edits made during the save carry over, unsaved, as with Save.

The old file is never touched. Over an existing file, the core copies that
file's metadata (attributes, mode) and swaps, as Save does (2.2). A Save
As to the document's own file is a Save, with Save's checks. A failure is
worded by `SaveText.saveAsFailure`. Unencodable text and UTF-16 offer Save
As UTF-8; the rest say why with OK. The core's English goes only to the
log.

**AppKit never writes.** `saveAs(_:)` and `duplicate(_:)` are overridden.
So is `runModalSavePanel` (for `.saveAsOperation` it runs Leal's Save As,
then tells the delegate; anything else is refused).
`save(to:ofType:for:completionHandler:)`, where every `NSDocument` save
ends, runs Leal's Save As for `.saveAsOperation` and refuses anything
else. Export (`saveTo:`) is off. `data(ofType:)` still throws.

**Duplicate** (Rob: please confirm). Leal's documents are always files,
because the core reads one, so there is no untitled copy. Duplicate is
**Save As with "name copy.csv" suggested**: the edits go into the copy,
and the window then edits the copy. The original is untouched. That is
what Save's alerts need when they offer Duplicate for a locked or
read-only file: the edits need somewhere to go. AppKit's
`duplicateDocument:` does the same, so a File ▸ Duplicate item (from
`task/2.5.3-savefix`) behaves this way too. The alternative is a new
window on the copy, with the original window keeping its unsaved edits
for a file it can't write.

**Incomplete Save As** (ADR-0008 decision 6, ADR-0010). The cases are the
disconnected banner (drive or share), the deleted-on-its-share banner and
the changed-while-reading banner. The last now has **Save As…** as its
second button, because its Reload would discard the edits. The File menu
covers the same cases. The save panel's message says it plainly: "Leal
has read only about N of M rows, so this copy will be incomplete…". When
M isn't known, because the file went before Leal could tell, it says
"…it gets only the N rows Leal has read in full". The core writes the
complete rows it trusts, with the edits. Afterwards an alert says "The
copy “x.csv” is incomplete. It has about N of M rows…", counted from the
outcome (`rowCount`, `estimatedRowCount`) with no header row. It names up
to 8 edits it couldn't keep (`skippedEdits`), then "and N more". The
window then edits the copy, which is complete in itself.

**Save As UTF-8.** `CSVDocument.saveAsUTF8(to:)` is a queued Save As with
kind `.saveAsUtf8`. The model adopts the core's reading of the copy and
takes its interpretation (UTF-8), so the window is no longer read-only.
Its progress shows in the status bar, as Save's does. The 2.3 and 2.5.2
reload is gone, along with what went with it: `readsUTF8Copy`, Save off
after a declined adopt, and the "edited during Save As UTF-8" alert.
Editing now carries on during it, as during any save: an edit after the
snapshot carries over to the copy, unsaved. The waiting task's cancel (the
window closing) cancels the save.

**Revert to Saved** (ADR-0008 decisions 4 and 10). `revertToSaved(_:)`
never calls `super`, so AppKit's alert and its `read(from:)` on the main
thread never run. It calls the window's `reload(.revert)`, the Reload
path. That commits an open edit, asks "Revert “a.csv” to the saved version
and discard your changes?" (Revert, Cancel) if there are unsaved edits,
then reads the file again off the main thread (`reloadInBackground`). It
is off while saving or reloading. AppKit's
`revert(toContentsOf:ofType:)` also reloads off the main thread, and never
over unsaved edits. `read(from:)`'s second-read branch is now
unreachable; it logs a fault if it is ever reached. Autosave in place
stays off and `preservesVersions` is false: no Versions browser.

**`SaveJob.restarted()`.** `DocumentModel.outcome(of:)` records it in
`Saved.restarted`.
- After a save that wrote the file, `saved(_:)` takes a generation equal
  to the restart's as a restart (`restarted`: new jobs, diagnostics and
  review, the index read on), not as the save's reading.
- After a save that didn't write (refused or cancelled), `saveEnded`
  takes any new generation as a restart, as before.

**Decision 4's other bullets** were built in 2.5.2: Treat As and Reopen
with Encoding are off with edits, the Header row stays on, and a drive
coming back keeps the edits. This task adds a test for the last one.

## Tests

`SaveAsTests` (14 hosted tests, sandboxed, real core):
- **Save As** writes the edits (quoted as needed) and leaves the old
  file as it was. The document follows: URL, title, window title, type
  (`.tsv`), the model's URL, the watcher's path, Open Recent,
  modification date, a new adopted reading, clean. A change to the new
  file is seen; one to the old file isn't. Undo, then Save, writes the
  new file.
- **Over an existing file:** cancelling the panel writes nothing. Saving
  replaces the file, keeping its extended attribute and `0640` mode; a
  quoted field stays quoted.
- Save As to the same file is a Save. Save As onto a folder says why.
- **Incomplete Save As from each banner** (disconnected,
  changed-while-reading, deleted on its share). The panel's message is
  checked. The copy is a prefix of the file with the edit, ends at a row
  end, and has fewer rows than the file. The alert's wording is checked.
  The window then edits the complete copy with no banner. The wording
  unit test covers named edits, "and 2 more", and the unknown total.
- **Duplicate** from a locked file's Save alert: "locked copy.csv"
  suggested, the copy saved and edited, the original untouched and still
  locked. AppKit's `duplicate(_:)` and `runModalSavePanel` go through the
  core (the delegate hears `true`). Export is off, and
  `save(to:…for: .saveToOperation)` is refused, writing nothing.
- **Revert:** asks (Cancel keeps the edits); Revert discards them and
  clears the history. The file is read once, off the main thread,
  recorded through `openForTesting`. AppKit's `revert(toContentsOf:)`
  does the same. Autosave in place and `preservesVersions` are off.
- **A drive coming back keeps the edits.**
- **`restarted()`:** a Save As from a disconnected drive is held; the
  drive comes back and `checkOriginal` runs (deferred by the core); the
  save is cancelled. Then `job.restarted()` is the model's generation,
  the drive is no longer disconnected, the file reads on to 20,000 rows,
  and the edit stays.
- **No main-thread waits:** with a Save As held inside its access and
  coordinated write, the main thread edits, reads, and reads `fileURL`,
  `isDocumentEdited`, `fileModificationDate` and `displayName`, and
  validates Save As, Duplicate and Revert (all off), in under 0.5 s.
  A background thread releases the hold after 1 s, so a wait fails
  rather than hangs.

`SaveAsUTF8Tests`: the edit-during test now checks adoption. The edit
after the snapshot carries over, nothing is read again, and the window
is the copy, in UTF-8, edited, with the journal's choices in UTF-8. Save
then writes the edit to the copy. `ExternalChangesTests`: the
changed-while-reading banner's Save As…, and AppKit's revert now
asynchronous.

Results: `just check-all` passes, with 915 Rust tests (1 skipped, as
before) and `app-test` Debug 314 passed. `just app-test release`: 314
passed. `just check-no-test-exports` and `just check-no-bench` pass.

No hot path changed.

## Deviations and notes for Rob

- **No File menu items here.** `task/2.5.3-savefix` adds Save, Save As,
  Duplicate and Revert to Saved with their standard selectors, which
  these overrides answer. This branch rebases onto that fix.
- **Sandbox.** Save As uses Save's path exactly: `placeForSaving` (the
  item-replacement folder for the destination's volume), `startSave`,
  and the coordinated write. Whatever replace mechanism the savefix
  settles on applies to Save As with no change here. One point for that
  fix: for Save As to a new name, the destination doesn't exist yet when
  `placeForSaving` asks `FileManager` for its item-replacement folder.
  The panel's sandbox extension covers the destination, not
  necessarily its folder, so the core's fallback folder next to the file
  can't be used there.
- New UI: the changed-while-reading banner's second button (Save As…),
  and Duplicate's meaning (above), are for you to confirm.

## Rust notes

No Rust changed. The app now uses `SaveJob::restarted()`
(`crates/leal-ffi/src/document/saving.rs`), which returns
`Option<u64>`, Rust's "maybe a value". `Some(generation)` means the save's
end read the file again at that generation, and `None` means it didn't.
UniFFI turns it into Swift's `UInt64?`. It is set once, by the save's own
thread, through a `OnceLock`: a cell that can be written once and then
read from any thread without a lock.
