# 2.5.3c App: Save As and Revert

Save As, Duplicate and Save As UTF-8 now save through the core's save
job (ADR-0012), in the same coordinated write and file access as Save
(2.5.3a), and the document then *is* the new file (ADR-0008 decision 1).
AppKit never writes. Save As from a document Leal couldn't read all of
writes complete rows only and says so (ADR-0008 decision 6, ADR-0010).
Save As UTF-8 adopts the core's reading of the copy instead of reading it
again. Revert to Saved goes the way Reload does, off the main thread.
A save that ends with `SaveJob.restarted()` takes up the new reading.

## How it works

**Save As** (`saveAs(to:)`). Every Save As… (File menu, alerts, file
banners, Recover changes) goes to `chooseSaveAs(.saveAs)`: it commits an
open edit, asks where (`chooseSaveAsDestination`, an `NSSavePanel`
sheet, which asks before replacing a file), and queues the save behind
any Save (`enqueueSave`), so closing, quitting and ⌘. know of it. Then:
1. `saveCoordinated(url, kind: .saveAs)`, as Save: the file access, a
   `.forReplacing` coordinated write of the **destination**, the
   item-replacement folders for its volume, and the core's job.
2. Inside the access (`noteWritten`), `NSDocument` hears the new file:
   `fileURL` (the name on disk, `SaveOutcome.path`), `fileType` from the
   extension, `fileModificationDate`, and the snapshot's change token
   (`.saveAsOperation`), where `NSDocument`'s own Save As does it.
3. `saveFinished` drops the journal up to the snapshot; `model.saved`
   takes the new URL and watcher status (the core's watcher follows it)
   and adopts the core's reading (`adoptSaved`, 2.5.3b); the file goes
   in Open Recent. Edits made during the save carry over, unsaved.

The old file is never touched. Over an existing file, the core copies
its metadata and swaps, as Save does (2.2). A Save As to the document's
own file, however spelt, is a Save, with Save's checks. Failures are
worded by `SaveText.saveAsFailure` (Save As UTF-8 offered for
unencodable text and UTF-16); the core's English goes only to the log.

**AppKit never writes.** `saveAs(_:)` and `duplicate(_:)` are overridden.
So is `runModalSavePanel` (for `.saveAsOperation` it runs Leal's Save As,
then tells the delegate; anything else is refused).
`save(to:ofType:for:completionHandler:)`, where every `NSDocument` save
ends, runs Leal's Save As for `.saveAsOperation` and refuses anything
else. Export (`saveTo:`) is off. `data(ofType:)` still throws.

**Duplicate** (Rob accepted, 2026-10-04). Leal's documents are always files,
because the core reads one, so there is no untitled copy. Duplicate is
**Save As with "name copy.csv" suggested**: the edits go into the copy,
and the window then edits the copy. The original is untouched. That is
what Save's alerts need when they offer Duplicate for a locked or
read-only file: the edits need somewhere to go. File ▸ Duplicate sends
`saveDuplicate(_:)` (AppKit hides a `duplicateDocument:` item), and
AppKit's own `duplicateDocument:` does the same. The alternative is a new
window on the copy, with the original window keeping its unsaved edits
for a file it can't write.

**Incomplete Save As** (ADR-0008 decision 6, ADR-0010), from the
disconnected banner (drive or share), the deleted-on-its-share banner
and the changed-while-reading banner, whose second button is now **Save
As…** (its Reload would discard the edits). The panel says "Leal has
read only about N of M rows, so this copy will be incomplete…" (or "…it
gets only the N rows Leal has read in full" when M isn't known). The
core writes the complete rows it trusts, with the edits; an alert then
says "The copy “x.csv” is incomplete. It has about N of M rows…" (no
header row), naming up to 8 edits it couldn't keep, then "and N more".
The window then edits the copy, which is complete in itself.

**Save As UTF-8.** `CSVDocument.saveAsUTF8(to:)` is a queued Save As with
kind `.saveAsUtf8`. The model adopts the core's reading of the copy and
takes its interpretation (UTF-8), so the window is no longer read-only.
Its progress shows in the status bar, as Save's does. The 2.3 and 2.5.2
reload is gone, along with what went with it: `readsUTF8Copy`, Save off
after a declined adopt, and the "edited during Save As UTF-8" alert.
Editing now carries on during it, as during any save: an edit after the
snapshot carries over to the copy, unsaved. The waiting task's cancel (the
window closing) cancels the save.

**Revert to Saved** (ADR-0008 decisions 4 and 10). `revertToSaved(_:)`
never calls `super`, so AppKit's alert and its `read(from:)` on the main
thread never run. It calls the window's `reload(.revert)`, the Reload
path. That commits an open edit, asks "Revert “a.csv” to the saved version
and discard your changes?" (Revert, Cancel) if there are unsaved edits,
then reads the file again off the main thread (`reloadInBackground`). It
is off while saving or reloading. AppKit's
`revert(toContentsOf:ofType:)` also reloads off the main thread, and never
over unsaved edits. `read(from:)`'s second-read branch is now
unreachable; it logs a fault if it is ever reached. Autosave in place
stays off and `preservesVersions` is false: no Versions browser.

**`SaveJob.restarted()`.** `DocumentModel.outcome(of:)` records it in
`Saved.restarted`.
- After a save that wrote the file, `saved(_:)` takes a generation equal
  to the restart's as a restart (`restarted`: new jobs, diagnostics and
  review, the index read on), not as the save's reading.
- After a save that didn't write (refused or cancelled), `saveEnded`
  takes any new generation as a restart, as before.

**Decision 4's other bullets** were built in 2.5.2: Treat As and Reopen
with Encoding are off with edits, the Header row stays on, and a drive
coming back keeps the edits. This task adds a test for the last one.

## Review fixes (fix round 3)

- **Save As during a Reload.** Save, Save As and Duplicate are off, and
  refused if asked, while a Reload or Revert reads the file
  (`isRereading`); a save's outcome carries the core document it started
  on (`Saved.handle`), and one about a document a Reload replaced isn't
  followed. Tests: a Reload held in the core's open; a held Save As
  overtaken by a Reload.
- **Save As onto its own file by another spelling.** The core decides
  by `st_dev`/`st_ino` (the opened file, or the one at its path now) and
  makes it a Save at the document's own path, with all of Save's checks.
  Save As UTF-8 there still converts, after the same checks (as a plain
  Save it would write the old encoding, or be refused for UTF-16). The
  app decides the same way, off the main thread, so the user gets Save's
  question. Tests: a link and a case-only difference, core and app.
- **AppKit's revert** takes the edit version with its check, so an edit
  made before its reading is adopted stops it (`EditedDuringReload`).
- **Duplicate missing from the File menu** (Rob's test): `NSDocument`
  hides a `duplicateDocument:` item when the app doesn't autosave in
  place (a probe of the running app: Rename…, Move To… and the rest
  stay shown). The item sends `CSVDocument.saveDuplicate(_:)` instead.
  Test: the running app's File menu, validated by an open document.
- **`sandbox-save-check`**: Save and Revert on Save As's file, Save As
  from the internal disk to FAT32 then Save there, and a missing
  item-replacement folder fails. Save As asks for the destination's
  volume's folder, so `Staged::create`'s fallback isn't reached.
- Nits: Duplicate's translator comment; Reload's and Revert's question
  refuses if a Save was queued meanwhile. Others are in PLAN 2.6a.

## Rust notes

`save_now` decides whether a Save As's destination is the document's own
file with `std::fs::metadata(path)` and the `MetadataExt` trait's `dev()`
and `ino()` (`crates/leal-core/src/document/saving.rs`,
`is_open_file`). A trait adds methods to a type that already exists:
`use std::os::unix::fs::MetadataExt` is what makes the Unix-only
`dev()` and `ino()` callable on `Metadata`. `SaveJob::restarted()` is set once through a `OnceLock`: a cell written
once, then read from any thread without a lock.
