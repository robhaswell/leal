# 2.0 Network shares stream

A file on a network share (SMB, NFS, AFP, WebDAV) now opens like a file on
a removable drive (ADR-0006 option C, ADR-0009). First paint reads the first
64 KB with `pread`. The index pass streams the file and copies it to Leal's
temporary folder on the internal disk. Once the copy is complete, Leal maps
it. Before this task, a share was read into memory or copied in full inside
`open`, before first paint. That took about a second for a 100 MB file.

ADR-0009's safety rules are on top:

- **The share is never read on the main thread.** That includes first
  paint: the app now opens every file's core document on a background
  thread.
- **Rows not yet copied show as loading.** The grid draws them as skeleton
  rows, and they fill in as the background copy brings them.
- **Network errors are retried with backoff,** within a 3.5 s window. If
  they don't pass, the share gets the existing "drive disconnected" state
  and banner, and the app keeps checking for it to come back.
- **`ESTALE` or `ENOENT` from a share is checked against the path.** Nothing
  there (its folder still there) means another computer deleted the file:
  its own state and banner, not a disconnection. The same file there means
  only the handle went stale (disconnected, and it reconnects); another
  file there means it was replaced (changed while reading, with Reload).

The review's findings and what changed for each are under "Changes after
review", at the end. The sections before it describe the code as it is now.

There is no real SMB share here. Everything is tested on a simulated share:
a test hook makes a file in an ordinary folder behave as if it were on a
share that can't clone, and can make its reads slow or fail. A manual test
script for a real share is under "Notes for Rob".

### Routing (the 1.1a switch)

`volume::kind` already returned `Network` when `MNT_LOCAL` was missing. Two
changes:

- **Detection.** A file system whose name (`f_fstypename`) is one of
  macOS's network ones is a share too, even if it claims `MNT_LOCAL`. Either
  signal is enough.
- **Routing.** `Source::open_with_options` sends every `VolumeKind` except
  `Fixed` to the removable path. A `Network` source gets `ShareRules`.

Everything else is the removable path from 1.1a and 1.9:

- A share is never cloned, or asked to: nothing is made on the user's
  share (review C5). The app gives no folder for a network volume
  (`TemporaryFolders.volume(for:)` checks `volumeIsLocal`), and the core
  skips the clone for `VolumeKind::Network`. The user's file is read itself
  (`Origin::Original`) and checked after every read.
- The share check runs before the "same volume as the scratch directory"
  shortcut (review C9), so a network home folder's files are shares too.
- The copy is streamed during the index pass, then mapped.
- A share that comes back reconnects through 1.9's `check_original`. The
  app already checks on `NSWorkspace.didMountNotification` and on app
  activation, and both fire for network mounts.


### Never on the main thread

**How rows are read today.** The grid reads tiles synchronously on the main
thread, through `Document.cells`. That is safe on a share, because of an
invariant the stream already had:

- `Removable::stream` writes each chunk to the internal copy, and stores
  `copied`, **before** it hands the chunk to the index.
- So every row the index has published is already in the copy.
- `Document::rows` and its siblings return only rows the index (or the
  first 64 KB in memory) has. Rows past that aren't returned. The grid
  draws them as skeletons (`GridCell.notLoaded`) and redraws on the next
  progress report (`reloadData` sets `needsDisplay`).
- Every reader goes through `Reading::rows_from` and `bytes_in`: the grid,
  the inspector, Copy, Find, and Previous/Next of a kind. None of them ever
  needs uncopied bytes.

Until now that held by accident. It is enforced now:

- **`Source::read_range` never reads a share**, on any thread. A range
  that isn't copied yet gives `ReadErrorKind::NotCopied`, without a system
  call.
- `NotCopied` can't happen today. If it ever did, the FFI maps it to
  `LealError.Io`.
- Only two things read the share:
  - `Source::read_head`, first paint's read;
  - `Source::stream`, the index pass on its own thread.
- **A use of the share on the main thread is caught.** `note_share_use`
  checks `pthread_main_np` on every read, on open, on `reconnect` and on
  `Document::check_original` (review C11). It applies in a process that
  said its main thread draws (`forbid_share_use_on_main_thread`, which
  leal-ffi calls when the app makes its scheduler), not in the CLI, whose
  main thread is its only one. Debug builds panic. The test hooks count it
  (`share_reads_on_main_thread`), and the hosted tests assert that the
  count stays 0. Release builds without hooks go on, rather than fail the
  open.
- **Closing never blocks the caller** (review C1): `Drop for Removable`
  hands a share's file (and any folder on it) to a thread of its own
  (`leal-share-close`), because a `close(2)` on a share that has stopped
  answering can block.

**The app's main-thread paths that reached the file, and what changed:**

| Path | Before | Now |
|---|---|---|
| Opening (Finder, File ▸ Open, Open Recent, Reopen after a failure, restoring windows) | `NSDocument.read(from:)` on the main thread ran first paint: `open`, `fclonefileat`, `fstatfs`, the xattrs, the 64 KB `pread`, and Foundation's volume queries (`TemporaryFolders.volume(for:)`). | `DocumentController` runs all of that on `FileWork`'s queue (`DocumentModel.openCore`), with the file's resolved path, type and modification date (`PendingOpens.Facts`), then calls `super`. `read(from:)` on the main thread takes the result from `PendingOpens` and only makes the model from the 64 KB already in memory. |
| AppKit's own metadata reads | `typeForContents(of:)` and `NSDocument.init(contentsOf:)`'s `fileModificationDate`. | `typeForContents` answers from the extension (or the background type); `makeDocument` builds the document and sets the background modification date (review A6). |
| Open Recent menu | `displayName` and `icon(forFile:)` of each file. | The URL's last component and the type's icon: no file-system calls (A6). |
| Reload (banner, File ▸ Reload from Disk) | `DocumentModel.reload` on the main thread. | Always `reloadInBackground`, on `FileWork`'s queue, for every file (A4). |
| Grid tiles, sizing, header titles, row flags | Copied or in-memory bytes only (the invariant above). | The same, now enforced. |
| Inspector, Find, Copy, Previous/Next | Already off the main thread. | The same, and copied bytes only. |
| `checkOriginal` (mounts, activation, the periodic share check) | Off the main thread, in `Task.detached`. | On `FileWork`'s queue (A1). |
| Status, `canSave`, `original()` | No system calls (1.9 review). | The same. |

**Why not AppKit's concurrent reading.** I tried
`canConcurrentlyReadDocuments = true` first. AppKit then makes the
`NSDocument` on its "NSDocumentController Opening" queue. `CSVDocument`'s
initializer is main-actor isolated (`NSDocument` is `NS_SWIFT_UI_ACTOR`,
and `init` isn't `NS_SWIFT_NONISOLATED`), and Swift 6's runtime check traps
there (`EXC_BREAKPOINT` in `_checkExpectedExecutor`, from
`CSVDocument.init()`). `makeDocumentWithContentsOfURL:` is main-actor
isolated too. So the controller opens the core first and leaves AppKit's
reading on the main thread.

**Every file is opened this way**, not only files on shares. Deciding
whether a file is on a share would itself ask its volume, and the open is
the same few milliseconds on either thread. The "Open to first rows"
signpost starts where the background open starts, so `just perf` still
measures the whole open.

**`FileWork`, not `Task.detached`** (A1): a share that stops answering
blocks a thread for as long as it likes, and Swift's cooperative pool has
one thread per core. A few hung shares would stall every `async` function
in the app. `FileWork.queue` is a concurrent Dispatch queue, which makes
more threads when these block; callers `await` it through a continuation.

**What still touches a file on the main thread:** a test's
`CSVDocument(contentsOf:)` (tests only), and Revert (`read(from:)` a
second time), which isn't reachable in phase 1 (nothing saves; SEAM(2.5)).
An open that doesn't come through `DocumentController` logs a `.fault`
outside tests (A9).

### Network errors: retry, then disconnected

On a share, `ETIMEDOUT`, `EHOSTDOWN`, `EHOSTUNREACH`, `ENETDOWN`,
`ENETUNREACH`, `ECONNRESET`, `ECONNREFUSED`, `ECONNABORTED`, `ENOTCONN`,
`EPIPE`, `ESHUTDOWN`, `EAGAIN` and `EIO` (SMB's timed-out request) are
`Failure::Network` (review C4). On a removable drive the network errnos
and `EIO` stay `Ambiguous`, as before.

A read that fails with one of them is tried again after each of
`NETWORK_RETRY_DELAYS`: 100, 200, 400, 800 and 1600 ms (3.1 s). A retry
is made only if it would start within `NETWORK_RETRY_WINDOW`, 3.5 s from
the first failure, the tries themselves included (review C7): quick tries
get all five retries, a share whose every try times out after a second
gets two or three.

- A retry repeats the whole read: the `pread`, and the `fstat` check
  afterwards.
- An `fstat` that fails with a network error is retried too.
- The wait is in 10 ms slices that check the cancel flag, so a cancelled
  index pass (closing the window, Treat As) stops at once.
- The stream (background) retries. `read_head` (first paint, background)
  retries too. Nothing can cancel first paint: no open can be cancelled
  (`NSDocumentController` has no way to), so the window bounds it. A single
  read that blocks (an NFS hard mount) can't be interrupted from user
  space; the open then waits on `FileWork`'s queue, with "Opening…" shown,
  and the app stays responsive.
- A reader that mustn't wait (`Wait::Never`) doesn't retry, and one
  failure there decides nothing. `read_range` never reads a share, so this
  doesn't happen today.

If the last retry still fails, the source is `Storage::Disconnected` and
the error keeps the share's own errno. From there it behaves exactly as an
unplugged drive (1.1a, 1.9):

- the rows copied stay;
- Save is off and Save As is offered;
- the "drive disconnected" banner shows;
- a mount, app activation, or the model's check every 5 s while a share
  is disconnected (`shareRecheckInterval`, review C4: an SMB session that
  comes back by itself fires no mount notification) reconnects it if the
  file is unchanged, and the copy carries on.

Any other failure on a share (`ENXIO`, `EBADF`, `EACCES`, …) makes it
disconnected at once, without retries, never an ordinary read error
(review C4). A share that keeps failing that way is looked at every 5 s
and restarted each time it reopens; the work each time is the copied part
again, from the internal copy.

A short read of the user's file (`UnexpectedEof`) means it shrank, whatever
`fstat` says: a change (review C2). And the copy's first chunks are checked
against first paint's bytes, which catches a same-size change between the
two with its modification time put back (review C6).

### Deleted elsewhere

On a share, `ENOENT` or `ESTALE` from a read (or from the `fstat` after it)
isn't taken on trust (review C3): an NFS server that restarted gives
`ESTALE` for a file that is still there. `confirm_deletion` looks at the
path, in the background:

| At the path | Means | Result |
|---|---|---|
| the file opened (same inode, size, modification time) | only the handle went stale | `Disconnected`; `check_original` reconnects it |
| another file | the file was replaced | changed while reading; the banner offers Reload |
| nothing, and its folder is there | another computer deleted it | `Deleted` |
| nothing, and the folder can't be seen, or the look fails | the share has gone | `Disconnected` |

A deletion:

- The source is the new **`Storage::Deleted`**, and the error is
  `ReadErrorKind::Deleted`.
- As for `Disconnected`, `available_len` is what was copied, reads within
  it work, reads past it give `Deleted`, and Save is refused.
- Unlike `Disconnected`, it is never retried, and never reconnected.
- The index and review jobs end with `JobError::Read(Deleted)`, which the
  FFI turns into `JobFailure::DeletedElsewhere`.
- The app stops the progress (`indexStopped`), with no skeleton rows past
  the rows read, and runs `checkOriginal`, so the file's own state says
  `Deleted` too.
- The banner `FileBanner.deletedWhileReading`: "This file was deleted on
  another computer while Leal was reading it. Leal shows the rows it had
  read; Save is off, and Save As keeps a copy." The tooltip says the same
  (A11). Its button is **Save As…**.
  - It comes second, after "changed while reading".
  - It replaces the plain "deleted" banner, which says the same thing less
    exactly.
- The status note says "Deleted" once, not twice.

**Replaced or changed elsewhere mid-copy** (A3): a share's watcher doesn't
see another computer's writes, so on a share a change found by a look at
the file (activation, a mount, the periodic check) marks the copy as
changed while reading (`changes_what_is_read` in `document/mod.rs`): the
rest of the copy would be the new version. The banner is "changed while
reading" with Reload, and the status bar keeps "Changed on disk" beside
"Changed while reading". Once the copy is complete, a change is the usual
1.9 "changed on disk" with Reload and Keep Editing.

After the review (C13), `open/first_paint_slow_share_small` (a 1 MiB
file) and `open/first_paint_slow_share` (the reference file) open on a

(27.1 to 27.9, and 27.3 to 28.2): one round trip, the same for both

These benchmarks time reads only. A real share's first paint also makes
metadata round trips (the `open`, `fstat` and `fstatfs`, and Foundation's
volume queries), so on a real share it takes several round trips, not one.
The 60 ms budget covers the reads, not those.

The simulated share is in the page cache, so this measures the code path:
one `pread` of 64 KB, one `fstat`, and no clone. On a real share, first
paint is one network round trip for the 64 KB. It used to be a read of the
whole file.

The copy runs at the share's speed, in the background. It uses internal
disk space equal to the file's size, as for a drive. Opening a local file
now runs the same core open on a background thread, plus two hops between
threads (well under a millisecond). The "Open to first rows" signpost
includes them.

## Decisions and interpretations

- **Every file opens off the main thread, not only shares.** See "Never on
  the main thread". `CSVDocument(contentsOf:)` (tests) and revert still
  open on the main thread, which is only safe for local files. Revert isn't
  reachable in phase 1 (nothing saves). The core's debug assertion would
  catch it, and `SEAM(2.5)` already marks it.
- **`read_range` refuses uncopied bytes of a share on every thread**, not
  only on the main thread. Nothing needs them, and refusing them keeps the
  rule independent of which thread asks. The main-thread check guards the
  two readers that may read the share.
- **The debug assertion is a panic in debug builds and a count with the
  test hooks.** With the hooks it does both, so a hosted Debug test that
  read a share on the main thread would fail its open. In release builds
  without hooks, the read goes on.
- **Retry schedule.** "Briefly with backoff": 100 ms doubling, five
  retries, 3.1 s. A guess for SMB reconnects and Wi-Fi blips. It is one
  constant if a real share says otherwise.
- **ENOENT/ESTALE are decided by the path** (review C3), not taken as a
  deletion.
- **`Storage::Deleted` is a new state,** not a flag on `Disconnected`. Its
  bytes behave the same, but it never reconnects, and every banner, note
  and error says something different. A new enum case also makes the
  compiler find every `switch` that needs it.
- **The disconnected banner and notes still say "drive"** for a share, as
  ADR-0009 asks ("the same banner"). Only the in-progress note says
  "Reading from the network".
- **First paint's 64 KB isn't written into the copy** (the 1.1a open
  question). A share that drops before the first chunk is copied shows the
  first screen with `available_len` 0, as for a drive.
- **A share's attribute caching** (ADR-0009) isn't changed here. The copy
  is checked with `fstat` after every read, as on a drive that can't
  clone, and a change the client's cache hides is the known v1 limit.

## Proposed DESIGN §3.1 wording

Replace the fallbacks paragraph and the removable-drives paragraph with:

> Fallbacks, only when the volume can't clone at all and can't vanish (an
> internal volume that isn't APFS). Removable drives and network shares
> follow the path below instead, whether or not they can clone. An EXDEV
> error means "clone elsewhere", not "no cloning":
> - up to 512 MB: read the file into memory, and show a small status bar
>   note;
> - above that: copy to the temporary directory, then map the copy.
>
> **Removable drives and network shares (ADR-0006, ADR-0009).** A file on a
> volume that can vanish (a removable drive, or a share: `MNT_LOCAL`
> missing, or an `smbfs`, `nfs`, `afpfs`, `webdav` or `ftp` file system) is
> never mapped from that volume. Touching mapped pages of a vanished volume
> crashes the process. First paint reads the first 64 KB with ordinary
> reads, which fail with an error, not a crash. The indexing pass copies the
> file to Leal's temporary folder on the internal disk, and once the copy is
> complete, Leal maps the internal copy. If the volume vanishes first, Leal
> shows a banner, keeps the rows it has read and the user's edits, blocks
> Save until the volume returns, and offers Save As.
>
> Shares have three more rules:
> - **The share is never read on the main thread,** where a share that
>   stops answering would freeze the app. Files are opened on a background
>   thread; rows are only ever read from the internal copy, and rows not
>   copied yet show as loading until the index pass brings them.
> - **Network errors** (`ETIMEDOUT`, `EHOSTDOWN`, `EHOSTUNREACH`, `ENETDOWN`,
>   `ENETUNREACH`, `ECONNRESET`, `ECONNREFUSED`, `ECONNABORTED`, `ENOTCONN`,
>   `EPIPE`, `ESHUTDOWN`, `EAGAIN`, `EIO`) are retried with backoff for at
>   most about 3.5 s; then, as after any other failure on a share, the share
>   is treated as disconnected, and Leal looks for it every few seconds.
> - **`ESTALE` or `ENOENT`** from a share is checked against the path: the
>   same file there is a stale handle (disconnected); another file means it
>   was replaced (changed while reading, Reload); nothing there, with its
>   folder present, means another computer deleted it, which is reported as
>   deleted, not as a disconnection, and Save As keeps the rows read.
>
> **Known v1 limit (SMB and NFS):** network clients cache file details, so
> a change another computer makes during the copy may go unnoticed until
> the cache expires. Each read is followed by an `fstat` check, and the
> pre-save re-check (ADR-0008 decision 9) opens the file afresh, but a
> change hidden by the client's cache can be missed.

## Rust notes

- **One function for every read of the drive or share**
  (`Removable::read_origin`). Before, `read_range` and `copy_chunk` each
  did their own read, check and classification. Now they share one `loop`.
  Each pass makes one attempt (`attempt`, which returns `Result<(),
  Attempt>`) and classifies a failure. On a share, a network error waits
  (`pause`) and goes round again with `continue`-like flow. Anything else
  `return`s. `retries` is an iterator over the delays, so
  `retries.next()` gives the next wait, or `None` once they are used up:
  the loop needs no counter.
- **A private enum for "what went wrong, before deciding what it means"**
  (`Attempt::Read`, `Stat`, `Changed`). The raw `io::Error` is kept, so
  the classification sees the errno, and the final `ReadError` still
  carries it (`raw_os_error()` gives the share's own `ETIMEDOUT`).
- **`&'static [Duration]`** (`SimulatedShare::retry_delays`). It is a
  borrowed slice that lives for the whole program, such as a `const`
  array. That keeps `SimulatedShare`, and so the test `Options`, `Copy`:
  a `Vec` can't be `Copy`, because copying it would have to duplicate the
  heap memory it owns. `ShareRules` turns it into its own `Vec` once
  (`to_vec()`).
- **`#[cfg(test)] thread_local!`** (`PRETEND_MAIN_THREAD`). A
  `thread_local!` is a static that each thread has its own copy of, so a
  test that sets it doesn't affect tests running in parallel on other
  threads. `Cell<bool>` lets it change through a shared reference.
  `with(|cell| …)` borrows this thread's copy.
- **`std::panic::catch_unwind`** (the main-thread test). It runs a closure
  and turns a panic inside it into an `Err`, so a test can check that the
  debug assertion fired and then carry on. `AssertUnwindSafe` tells the
  compiler that nothing half-changed is used after the panic.
- **`cfg!(debug_assertions)`** versus `#[cfg(…)]` (`note_share_read`).
  `cfg!` is an expression, `true` or `false` at compile time, inside
  ordinary code. The optimiser deletes the dead branch, but both branches
  must compile. `#[cfg]` removes the code before compiling. The counter is
  `#[cfg]`, because its field doesn't exist without the test hooks. The
  panic is `cfg!`, because it compiles everywhere.
- **`#[cfg_attr(not(…), expect(clippy::unused_self))]`.** Without the test
  hooks, `note_share_read` doesn't use `self`. `expect` silences that lint
  only in that build, and would itself warn if the lint stopped firing.
- **Swift: `nonisolated(unsafe) static var`**
  (`DocumentModel.openForTesting`). The hook is read on a background
  thread, and tests set it on the main thread before opening.
  `nonisolated(unsafe)` says "I promise those never overlap". The closure
  is `@Sendable`, so it can only capture values that are safe to share.

### Rust notes (review changes)

- **`impl Drop` that moves a field out** (`Drop for Removable`).
  `self.external.get_mut()` gives the `Mutex`'s value without locking
  (`&mut self` proves nobody else holds it), and `.take()` moves the
  `External` out, leaving `None`. The closure given to
  `thread::Builder::spawn` takes it with `move`, so it is dropped (the file
  closed) on the new thread. If the thread can't start, `spawn` drops the
  closure, and with it the file, here instead.
- **`Option<fn()>`** (`SimulatedShare::on_close`). A plain function
  pointer, not a closure: it captures nothing, so it is `Copy`, and the
  test's function records into a `static Mutex`. Comparing function
  pointers isn't meaningful, so `SimulatedShare` no longer derives
  `PartialEq`.
- **`Condvar`** (the hold hook). A held read waits on a condition variable
  until `released` is true. `wait` releases the mutex while sleeping and
  takes it back on waking. The `while` loop guards against spurious
  wake-ups.
- **`get_or_insert_with`** (`first_failure` in `read_origin`). It sets the
  `Option` the first time and returns a reference to its value every time.
