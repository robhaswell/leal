# 2.6 App: paste and clear

Status: review fixes done; awaiting re-review. Paste (⌘V), Clear (Delete)
and Cut (⌘X) in the grid, on top of the core's cell batches (2.1) and the
undo history and journal (2.5.2).

## What was built

**Core** (`crates/leal-core`):
- `edit/paste.rs`: `parse_tsv`, clipboard text as cells (below).
- `document/pasting.rs`: `Document::paste(rows, columns, columns_shown,
  text, line_ending)` → `Pasting` (the command and the block's size),
  `clear_cells(rows, columns)`, `can_paste()`, `can_clear_cells(..)`. Each
  makes one `Edit::SetCells` command through the same code as typing
  (`change_in`), so overlay, undo/redo, replay, saving and Find's catch-up
  treat it as cell edits. `Pasted::line_breaks_as` turns line breaks in
  values into the file's.
- New limits and refusals (`edit/command.rs`): `CELL_BATCH_LIMIT`
  (100,000 cells), `PASTE_BYTE_LIMIT` (32 MB: the text pasted, and the old
  values replaced), `EditError::TooManyCells`, `TooMuchText`,
  `TooMuchReplaced`, `PastLastRow`, `PastLastColumn`. `change_in` takes a
  `budget`: it adds up the old values' bytes as it reads them (before
  copying each) and refuses past it, before anything is applied.

**FFI** (`leal-ffi/src/document/editing.rs`): `paste` (returns `Pasting`:
command, rows, columns, so the app selects the block without parsing the
text again), `can_paste`, `clear_cells`, `can_clear_cells`,
`cell_batch_limit()`, `paste_byte_limit()`, the five new `EditRefusal`s,
and **`CellBatch`**: a command of more than 256 cells (any batch) keeps
its changes in Rust (`EditCommand.cells`), as `StructuralEdit` does for
rows. Handing Swift 100,000 `ValueChange`s took ~115 ms, five times the
edit; Swift sees only `count`, `first`, `rows`, `clears()` (to name a
step after Recover) and `longest(undone, perColumn)` (ranked by UTF-8
length: free, and the widest value is nearly always among them).

**App**:
- `GridView`: `cut(_:)`, `paste(_:)`, `delete(_:)`, and
  `deleteBackward`/`deleteForward` (⌫, ⌦) → `onCut` / `onPaste` /
  `onClear`; menu validation through `validateCellItem`. A held Delete
  clears once.
- `Window/CellCommands.swift`: running them (commit an open edit first;
  one undo step named "Paste" / "Clear Cells" / "Cut" via `asOneStep`),
  enabling with the reason as tooltip, refusals, and the words
  (`PasteText`). Paste asks `pasteRefusal()` before reading the
  clipboard, and refuses text over `pasteByteLimit()` before the core.
- **Cut** (`cutSelection`): `GridView.cut(_:)` (the Edit menu's standard
  item). Whole rows picked by their numbers (`GridSelection.wholeRows`,
  set by `selectRow`/`extendRows`, kept by ⇧↑/⇧↓, dropped by ⇧←/⇧→; ⌘A is cells,
  Rob agreed 2026-10-05) → Copy + Delete Rows; else Copy + Clear. Copy is made
  first (`prepareCopy`: the text, or a core job that copies the edits as
  they are when it starts) and placed on the clipboard only if the delete
  or clear went through; a refused one discards it (`discard`). Copy uses
  the same `prepareCopy`/`place`.
  Cut works from one `CutPlan`. Whole rows are copied whole: column 0 to
  the larger of the grid's and the file's column count (the selection's
  columns are fixed when picked, so may be stale), the rows deleted, to
  the last row if `throughLastRow`. After the large-copy sheet the plan is
  recomputed; if it differs or is now refused, Cut beeps and stops.
- After Recover, a several-cell command's step is named "Clear Cells" if
  it empties every cell, else "Paste" (`EditHistory.recoveredName`).
- `Document/DocumentCells.swift`: the model's calls; `cellArea` (the
  selection as logical rows, within the rows and the grid's columns).
- `EditCommand` helpers (`cellCount`, `firstChange`, `changedRows`,
  `valuesShown`) used by `valuesChanged`, the undo name and the recovery
  report, for both inline and batched commands. `valuesChanged` now works
  from the row span, and widens columns from each column's 16 longest
  values of a batch (measuring all 100,000 took 46 ms).
- DESIGN §3.6 and §4.2 updated; the shortcut sheet's line too.

## Decisions

Rob's (2026-10-04):

- **A. Past the last row or column: refused** with an alert ("The copied
  cells run past the last row. Paste them higher up, or insert rows
  first."), not extended. The last column is the grid's (`columnCount`);
  one value into a selection wider than that is refused too (core).
- **B. Cut (⌘X):** whole rows (row-number selection) → Copy those rows
  (Copy's format) + Delete Rows; otherwise Copy + Clear Cells; one undo
  step "Cut". Refused as Delete Row or Clear would be (reading, saving,
  unterminated quote, too many cells, too much text), and then nothing is
  copied. A copy over ~100 MB (whole rows of a big file) asks first, as
  Copy does. The header row is never a grid row, so never cut.
- **C. Line breaks inside pasted values** become the file's own line
  ending (`lineEnding`, the one ⌥↩/⇧↩ typing uses via `lineBreak`), not
  as pasted.
- **D. Empty clipboard text** pastes nothing (beep). A lone line break is
  still one empty value (a spreadsheet's copy of an empty cell).

Earlier choices, unchanged:

1. **Clipboard format: always TSV.** The tab-separated type if present,
   else plain text: cells split by tab, rows by CRLF/LF/CR; a cell
   starting with `"` and closed by `"` before a tab, line break or the end
   is quoted (`""` → `"`); anything else literal; one final line break
   dropped. CSV is not detected (a CSV line pastes as one cell).
2. **One value** fills every selected cell; **a block** goes in once from
   the selection's top-left cell (no tiling), and is then selected.
3. **Refused while reading or saving**, and while Reload replaces the
   document (cell typing is still allowed then).
4. **Hatched cells** (ADR-0005 decision 2): pasting `""`, or clearing,
   leaves a missing cell missing; clearing an edited hatched cell makes it
   missing again. Pasting a value pads the row as typing does. After a
   Save, undo empties such cells instead (they are fields of the file
   now; `holds`, task 2.2).
5. **Refusal UI:** wait-it-out refusals are the menu item's tooltip, a
   beep and a VoiceOver announcement; the others an alert.
6. **Limits:** 100,000 cells and 32 MB of new text per paste or clear
   (one value counts value × cells), and 32 MB of old values replaced
   (`TooMuchReplaced`: "The selected cells hold more than 33.6 MB of text
   … To empty a whole column, delete it and insert an empty one.").
7. **2.1's far columns:** a paste never pads a row past the widest row
   shown, and can't widen the grid through row 0.

## Manual checks for Rob (on screen)

1. Copy a 3×2 block in Numbers or Excel; click a cell in Leal, ⌘V: the
   block goes in from that cell and is selected. Undo says "Undo Paste".
2. Copy one cell; select a range; ⌘V: every cell gets the value.
3. Select cells, Delete (and Fn-Delete): they empty; "Undo Clear Cells".
   On a short row the hatched cells stay hatched.
4. Select cells, ⌘X: they empty, "Undo Cut"; ⌘V elsewhere pastes them.
   Click a row number, ⇧-click another, ⌘X: the rows go; ⌘V into another
   app pastes them; Undo brings them back.
5. Paste a block near the bottom or right edge: an alert, no change.
6. ⌘A on a large file: Delete and Cut are off with the limit as tooltip;
   the keys show the alert, and the clipboard keeps what it had.
7. While a big file is "Indexing…", or during a save: Cut, Paste and
   Delete are off with a tooltip; the keys beep.
8. In the in-cell editor, the inspector, the find bar and Go to Row,
   ⌘X, ⌘V and Delete edit the text, not the cells.
9. Paste a multi-line cell from Numbers into a CRLF file, save, open in a
   text editor: only that field changed, quoted, its line break CRLF.

## Rust notes

- `Pasted<'a>` holds `Cow<'a, str>` cells: "copy on write". A cell is
  usually a *borrowed* slice of the clipboard text (no copy); only a
  quoted cell with `""` inside needs an *owned* `String`. The `'a` is a
  lifetime: it tells the compiler the cells can't outlive the text they
  borrow from (`edit/paste.rs`).
- `paste` and `clear_cells` run inside `change_rows(|reading| …)`: a
  closure called with the writer lock held, so they call `change_in`
  (lock held) rather than `change` (which would wait on itself).
- `CellBatch` is a `uniffi::Object`: Swift gets a handle to a Rust value
  behind an `Arc` (a shared, reference-counted pointer), not a copy of
  its 100,000 values.
- `longest` keeps each column's longest values in a `BTreeMap` of small
  sorted `Vec`s (`partition_point`: a binary search; `truncate`).
