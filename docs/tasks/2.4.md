# 2.4 Row and column insert/delete: design (2.4d)

For 2.4a (rows), 2.4b (columns) and 2.4c (saving). Refines DESIGN §3.6,
§3.7, §3.9 and the 2.1/2.2 handovers. Four choices change DESIGN:
**ADR-0014 (proposed)**; product code relying on them waits for it.

## Ground rules

- **Commands stay logical; the overlay keys by identity.** Undo is LIFO,
  so a command always meets the coordinates it was made in, and logical
  coordinates survive saves and replays. Identities (`RowId`, `CellId`)
  are internal: they move cells without rewriting them, and let a
  same-base undo restore original bytes.
- **Structural edits need the whole file** (ADR-0014 d1): refused until
  the index pass (and a drive's or share's copy) is complete and trusted
  (`EditError::StillReading`), and during a save (`EditError::Saving`).
  So `N` (physical rows) is fixed and the marks final whenever one exists.
- **Original rows never reorder** (sorting is a view, §3.8): rows only
  appear and disappear, so two rows' logical order never changes.

## 1. Rows (2.4a)

**Row ids.** `RowId(u64)`: an original row's is its physical row (< 2³²);
an inserted row's is 2³² + n from a per-base counter, never reused. An
inserted row records its **gap** (the physical row it precedes, `N` at the
end), fixed for life. `Overlay.inserted: BTreeMap<u32, Arc<InsertedRow {
gap, fields }>>`; cell edits to inserted rows go in `RowEdits` like any
row's, and `Overlay.rows` is keyed by `RowId`.

**The piece list** (`edit/rows.rs`: `RowMap`, in the `Overlay` snapshot):
`Piece::Original { start, len } | Inserted { gap, first, len }` (16 bytes)
in logical order; gap keys never decrease, inserted first at equal keys;
continuing neighbours merge, so an empty map is identity and costs
nothing. Stored as `leaves: Vec<Arc<Leaf>>` of ≤ 512 pieces with
cumulative row ends, plus top arrays of each leaf's first row and gap key.

| Operation | Cost |
|---|---|
| logical → piece (`slot`): search top array, then leaf | O(log P) |
| physical → logical (`logical_of`; `Err(next)` if deleted): by gap key | O(log P) |
| inserted id → logical: its gap, then that gap's inserted pieces | O(log P + r) |
| `segments(range)`: original stretches and inserted runs | O(log P + pieces) |
| insert/delete k rows: one leaf (split if full), rebuild top arrays | O(512 + P/512) |
| snapshot: clone leaf `Arc`s; the next edit copies one leaf | O(P/512) |

E edits give P ≤ 2E + 1: for 1M rows and 100k edits, ≤ 200k pieces, ~400
leaves, ~3.5 MB, ~20 comparisons a lookup. r = inserted runs in one gap
(repeated "insert above" at one place); only Find and the carry-over need
that lookup, never the grid. Logical count = N − deleted + inserted.

## 3. Columns (2.4b)

**Cell identity.** `RowEdits.cells` keys by `CellId`: `Field(k)` (own
field k), `Inserted(op)` (the cell a column insert gave the row) or
`Appended(j)` (a hatched cell at base position j, as 2.1's column past the
end). `Overlay.columns: Arc<[ColumnOp { id, at, kind: Insert { value } |
Delete, exceptions: Arc<[(RowId, bool)]>, inserted_before: u32 }]>`.

**A row's layout is a fold** of the ops over `[Field(0..n),
Appended(n..e)]` (n own fields, e past its last appended edit): where an op
applied, an insert puts `Inserted(op)` at `at`, a delete removes the cell
at `at`. Whether it applied: the row's `exceptions` entry, which covers
every edited and every inserted row at the op's time (so an op costs
O(edited rows), not O(N)); no for an inserted id ≥ `inserted_before`;
otherwise oracle rule 6 (ADR-0004 d5) on the length so far (insert at c
needs ≥ c cells, delete > c, never a blank line). An unedited row's length
depends only on its marks field count, so `fold_len(n)` is a 128-entry
table per op list. A new hatched edit at logical c ≥ folded length L takes
j = c − L + e: applied ops act at or before the row's end, so everything
past it moves alike.

`column_count()` = `fold_len(mode)`; a row is ragged when its folded
length differs (the marks' ragged scans use the table). A deleted column's
edits stay in `RowEdits`, hidden by the fold, for undo. The command records
the logical rows the op applied to as run-length ranges (one pass over the
marks, ~1 ms per million rows).

**Per-column quoting** (ADR-0004 d2, ADR-0005 d3, ADR-0014 d4). Column c
is logical column c now; its fields are the original fields there in rows
that aren't original blank lines, edited ones by their original bytes. A
new cell (an inserted row's, or `Inserted(op)`) is quoted if it needs it,
the file quotes every field, or c has a non-empty field and all of them
are quoted. Hatched cells keep 2.2's rule. Oracle: drops `TODO(ADR-0004
#2)`, and the CSV strategy gains quoted text columns. Product:
`save::ColumnQuoting::census`, one pass shared with `quotes_every_field`.

## 4. Commands

`Edit` gains `InsertRows`/`DeleteRows { at, rows: Arc<Rows> }` and
`InsertColumn`/`DeleteColumn { at, column: Arc<Column> }`; `inverse` swaps
insert and delete, same payload; lineage checks unchanged. Row commands are
contiguous (a gapped selection is one undo group, bottom first). The FFI's
`EditCommand` carries the payload as an opaque `StructuralEdit` object.
`Rows { count, base, ids: Vec<Range<RowId>>, values }`: an insert holds
its values; a delete moves the removed rows' `RowEdits` and `InsertedRow`s
into the payload (so they don't keep the document dirty). `Column { base,
op, applied: Vec<Range<u32>>, values }`. A delete's values are read later,
as they read then, from the base.

**Base epoch.** Each `EditStore` gets a new `BaseId` per split and per
save's rebase (2.2's `rebased` stays for cell commands).
- **Same base** (in-session undo/redo): by identity. A row delete's undo
  restores the same `RowId`s, edits and inserted rows, so original bytes
  return (F3); a column op's undo removes or re-adds it (it must be last).
  Checks (ids absent/present, edited `Inserted(op)` cells hold the value)
  cost O(edited rows) and read no file bytes.
- **Other base** (after a save; replay, which ignores lineage): by value
  (ADR-0012 d4). Inserted rows are new rows (new ids and quoting); deleted
  rows are checked to read as recorded first. Column ops act on the
  recorded rows, a delete checking each cell first: a pass over the rows,
  on this rare path only. Values are read lazily, so a command keeps its
  base reading alive while the undo history holds it (ADR-0014 d3).

New refusals: `StillReading`, `Saving`; `NoSuchRow` covers past the end.

## 5. Find

- **Original rows keep their physical number as key**: `Found.rows` stays
  a sorted `Vec<u32>`, also logical order; nothing is remapped, and row
  edits never restart a search. A chunk takes its rows' edits and deleted
  stretches in one look at one version, and skips the deleted.
- **Inserted rows**: `Found.inserted: Vec<(id, cells)>` in logical order
  (via `RowMap`) with prefix sums, searched first (in memory).
- **The catch-up log keys by `RowId`**: cell edits log their row, inserts
  new ids, deletes removed ones, undos restored ones. Catch-up recounts
  each (0, unread, if gone) and merges in O(M + K) as today; `behind`
  counts rows, so a big delete goes to the catch-up job.
- **Queries** take logical places (`physical_at_or_after` for originals)
  and add both prefix sums; with the header on, logical row 0 is left out.
- **Column ops restart the search** (ADR-0014 d2): a search that sees the
  store's column generation change starts over, as after `used_head`.

## 6. Saving (2.4c)

**The walk.** `stream` walks the snapshot's pieces in logical order (file
order for original rows), making the oracle's `changes` splice for splice:
original rows copied in bulk, except edited rows or rows whose layout isn't
identity, which go through `row_splices` (per field if the shape holds,
else one whole-row replace with line ending); each deleted original row
(skipped between original pieces) one delete of its whole extent; a run of
inserted rows (`RowRules`, per-column quoting, encoded as in 2.3) one
insert at the next original row's start (deleted or not), or at the end.

**Line endings.** An inserted row ends with the whole file's most common
ending (ties to the first seen, LF if none; ADR-0004 d3), from the index
pass's tally, agreeing with the oracle's `Layout::line_endings`; in a mixed
file, neighbours keep theirs. The last output row has an ending only if the
file had a final newline (ADR-0004 d4; an unterminated last row has none):
appending gives the old last row the common ending and the new one none;
deleting the last row strips the new last row's (a whole-row replace).
Fixes, as the oracle: an empty row becomes `""` (d6); a blank LF row after
a lone-CR row, which deletes can cause, becomes CR (d10); a new first row's
BOM-like first field is quoted in a file without a BOM (d7).

**The rebase builds its index from the plan**, replacing
`RowIndex::shifted`: the writer pushes each output row's new start into
`RowIndex::from_starts(starts, len, mode, unterminated)` (old start plus
running shift for copies; 4 bytes a row; mode = `column_count()`). A
property checks it equals `RowIndex::build` of the output.

**Carry-over.** No structural edit runs during a save, so the map at its
end is the snapshot's: each touched `RowId` maps to a logical row, its row
in the new file; the new store is a new base. **Save As from an incomplete
document** skips rows past the cut, inserted ones too, in `skipped_edits`.

**F6.** `tests/saving/properties.rs` and `tests/edits/properties.rs`
replay every `EditCase` kind against the oracle, unfiltered. Plus: undo-all
is byte-identical (F3); undo after a save matches the oracle on the saved
file; reopen keeps rows and line endings.

## 7. Edge cases

- **Header row**: logical row 0 (the toggle is display only, ADR-0008 d4):
  deleting it promotes the next row; a row inserted at 0 becomes the
  header. The app can't select the header, so "Insert Row Above" on the
  first data row inserts at 1; to change the header row, toggle it off.
- **Above row 0**: allowed, after the BOM. **Every row deleted**: allowed;
  saves as the BOM alone (as the oracle); `column_count` 0. **Ragged rows,
  hatched cells**: rule 6 and the fold (§3).
- **Unterminated quote at end of file**: after each structural op, rule 10
  is checked in O(log P): the field, if present and unedited, must be the
  last cell of the last row. So a row inserted after it, or a column after
  it, is refused; inserting at its row index or deleting it (which lifts
  the rule) is fine. `can_insert_rows`/`can_insert_column` tell the app.
- **Still indexing**: refused; allowing the indexed rows only would bring
  an open-ended piece, unfinished marks and untrusted head rows (1.9).
- **Rows with diagnostics deleted**: the report still describes the file
  as read (§3.6); the gutter and every Previous/Next skip deleted rows, so
  a kind's Next can find nothing until the save's index pass.

## 8. Split of work

**2.4a Rows** (first): §1, §2, §4's row commands, §5 without the column
restart; FFI methods, `StructuralEdit`, logical counts. Tests: `RowMap`
against a `Vec` model over 100k random edits; the edits property with row
edits; undo-all leaves `has_edits()` false; Find counts equal a fresh
search. Benches: screen read over 100k pieces; insert/delete < 16 ms.

**2.4b Columns** (after 2.4a): §3, §4's column commands, the Find restart.
Tests: the edits property with column edits; ragged and hatched rows; a
quoting unit test. Benches: column insert < 16 ms; screen read with 10 ops.

**2.4c Saving** (after 2.4a; built alongside 2.4b, lands after it): §6,
replaying row edits first, column edits once 2.4b is in. Benches: save
after one row insert (500 ms budget); after a column insert, recorded.

**Interfaces fixed now**, so 2.4b and 2.4c don't wait on each other:
`RowMap::{len, slot, segments, logical_of, physical_at_or_after,
logical_of_inserted, rows_within}` with `Segment::{Original(Range<u32>),
Inserted(Range<u32>)}`; `RowView::{id, len, cell, cell_id, same_shape}`
with `ViewCell::{Field, Edited, New, Padding}`, from which the writer
builds rows (`same_shape` is always true in 2.4a); and
`save::ColumnQuoting::{census, quoted(column)}`, "not quoted" until 2.4b.
