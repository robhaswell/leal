# 2.4b Columns

Insert and delete columns in the core, with undo, redo and replay, every
reader going through each row's layout; per-column quoting of new fields
in the save oracle and the product's model. Not saved yet: a save with a
column inserted or deleted is refused (`SaveError::RowsChanged`) until
2.4c. Design: `docs/tasks/2.4.md` §3, §4's column commands, §5's restart,
§7; ADR-0014 decisions 1 to 6.

## What was built

- **Cell identities** (`edit/columns.rs`). `CellId::{Field(k),
  Inserted(op), Appended(j)}`; `RowEdits.cells` keys by it, so a column
  operation moves cells without rewriting an edit, and a deleted column's
  edits stay, hidden, for its undo. `ColumnOp { id, at, kind:
  Insert(value) | Restore(values by row) | Delete, inserted_before }`;
  `Overlay.columns: Arc<Columns>` (the operations, and the default layout
  of each field count below 128).
- **Layouts.** A row's default layout is its own fields with each
  operation applied where oracle rule 6 says (insert at `c`: ≥ `c` cells;
  delete: > `c`; never a blank line), then its hatched cells, which no
  operation reaches: a function of its field count, so unedited rows cost
  a table look-up. An edited row the rule decides otherwise for (its
  hatched cells count, an edited blank line isn't one) keeps its layout
  written out (`RowEdits::layout`), which later operations change
  directly (`edit::Layout`).
- **Operations** (`document/columns.rs`). `insert_column(at, value)`,
  `delete_column(at)`, `can_insert_column`, `can_delete_column`. One walk
  over the marks' field counts (the logical rows it applied to, as runs,
  for undo by value) plus a look at each edited row. Refusals:
  `StillReading`, `Saving` (as rows), `NoSuchColumn` (past the widest row),
  `AfterUnterminatedQuote` (a cell after the open quote, O(1) row).
- **Commands.** `Edit::InsertColumn`/`DeleteColumn { at, column:
  Arc<Column> }`; `inverse` swaps them. Same base: by identity (the
  operation list and each changed row's edits, before and after; a row
  must *read as* it was left, since an undo by value may give a hatched
  cell a new id). Other base (replay, after a save): by value on the
  recorded rows; a delete checks each cell (read lazily from the reading
  and overlay it was made on, ADR-0014 d3); the undo of a delete puts the
  cells back (`OpKind::Restore`, each row its own value).
- **Readers.** `RowView` lays the row out (grid, window, inspector, editor,
  Copy now and the job, number sample, first screen, the by-value
  checks); `column_count` is the mode's folded length. Marks: unedited
  rows by field count (ragged against the folded mode, NUL in an inserted
  value), flagged rows read (a delete may have taken the flagged field);
  edited rows from their layout; each kind's Previous/Next by the same
  walk. With no column operation every path is as before.
- **Find** restarts on a column operation (ADR-0014 d2): a search
  compares the store's column generation at each step and catch-up; one
  whose job has finished searches again in a catch-up job (`catching_up`
  until then). With operations, rows are counted through their layout,
  every row when an inserted value matches.
- **For 2.4c**: `RowView::{id, cell_id, same_shape, fields_now,
  is_blank_line, file_fields}`; `save::ColumnQuoting::{census(reading,
  overlay), quoted(column), every_field}` (one pass over the file's rows:
  every row for the every-field check, live rows for their columns now;
  it takes a checkpoint and stops early, see *Review fixes*).
- **Oracle** (`leal-testkit/src/save.rs`): per-column quoting of new
  fields (rule 3, `Document::column_quoting`), `TODO(ADR-0004 #2)` gone;
  the CSV strategy's `QuotingStyle::Columns` ("quote text columns").
- **FFI**: `insert_column`, `delete_column`, `can_insert_column`,
  `can_delete_column`; `StructuralEdit::{is_column, column}` (`row_count`
  is the rows a column operation applied to); `EditRefusal::NoSuchColumn`.

## Deviations from `docs/tasks/2.4.md`

1. **Written-out layouts instead of exception lists.** The design keeps,
   per operation, `exceptions: [(RowId, applied)]` for every edited and
   inserted row, and folds each row through them. Here a row whose
   decision differs from its default layout's keeps its layout written
   out; every other row (unedited, or edited but laid out by default) is
   folded by the table. Same cost (O(edited rows) per operation, nothing
   per unedited row), but trimming padding and putting cells back by
   value are plain list operations, which the fold made fragile (a
   property case: padding trimmed, then an earlier operation's position
   falling past the row's end). A written-out layout stays until the
   operations it went its own way for are undone.
2. **Oracle: a column delete drops padding left at a row's end.** Rule 12
   says padding is only before an edited hatched cell; the oracle kept it
   when a delete took that cell (`a,,x` → `a,`). It now drops it, so the
   row's own bytes come back, as setting the cell back to `""` does. This
   changes the oracle's expected output in that corner only; no fidelity
   test is weakened. Rob decided it: ADR-0014 decision 5.
3. **`has_edits`** stays true while any column operation is in effect,
   even if an insert and a delete cancel out (as 2.4a's rows).
4. **By value, cells put back into a row now shorter** (a delete of its
   last hatched cell took the padding) are padded again with empty hatched
   cells; the cell is an inserted one, not a hatched one.
5. **Inserted rows put back by value may have no cells** (a column delete
   emptied them): `InsertedRow::exactly`.
6. **`NoSuchColumn`** is a new refusal (the design named only
   `NoSuchRow`).
7. **Find**: the restart is lazy (at the search's next step or query), not
   pushed by the edit.

## Interfaces for 2.4c

As fixed in the design, with additions: `RowView::{id, cell_id,
same_shape}` (added here, not by 2.4c); `ViewCell::New` also covers an
unedited inserted cell; `ColumnQuoting::census` takes the reading, the
overlay (the snapshot written) and **a checkpoint** (`&dyn Fn() ->
Result<(), E>`, `E: From<ReadError>`, e.g. the save's, returning
`SaveError`: changed in the review fixes), and `quoted(column)` already includes
the file's every-field rule (`every_field()` alone, for hatched cells).
`RowEdits::cells()` now keys by `CellId`; saving's pre-2.4c code uses
`RowEdits::base_cells()` (positions, valid with no column operation).

## Review fixes

- **`same_shape`** was true for a row whose own last field a column
  delete took (its explicit layout's cells all in place, but too few):
  it now needs every own field in its place. Signature unchanged.
- **Hatched ids with no column operation**: `Layout::hatched` gave
  `base(c, 0)` where `get` reads `base(c, fields)`; an edit to a row
  edited from a stale first 64 KB (more fields then than now) was
  invisible. Fixed; unit test.
- **ADR-0014 decision 5** (padding comes back off) was already what the
  oracle and the product did; both cite it now.
- **ADR-0014 decision 6**: a row that edits and column deletes leave with
  no cells is a blank line, and a column insert skips it (oracle rule 6;
  `ColumnOp::applies`: an insert needs a cell; a restore, always by value,
  still puts a delete's cells back into the rows it emptied). It still
  saves as `""` (rule 8, ADR-0004 decision 6): unchanged here, for 2.4c
  to confirm. The reviewer's case now reads `[["z","b"],[],["z","e"]]`.
- **`ColumnQuoting::census`**: a checkpoint before each batch of 4,096
  rows (its error stops it), and an early stop once the file doesn't
  quote every field and every column up to the widest row's end (the
  marks' walk, as an operation's) has an unquoted non-empty field. A
  column insert's column has no field, so with one it never stops early:
  2.4c makes the census only when a save writes a new field. Bench
  `column_census/*` through a `test-hooks`-only `bench_quoting_census`
  (`check-no-test-exports` looks for it).
- **By value, a column insert** applies to exactly its recorded rows: a
  row gone (fewer applied than recorded) or a blank line now is refused
  with `ValueChanged`.
- **Find** clears `turning` under the counts' lock, where it sets
  `complete`; a turn that completed no longer clears it after a catch-up
  job may have set it again. No regression test: no existing test hook
  reaches the window after `complete` is set.
- **`edited_cells()`** counts only the edits a row shows: hidden ones (a
  deleted column's) don't count. A column operation marks the count stale
  and the next call counts every edited row again, so the operation
  itself costs nothing more.
- **Replay (2.4a bug, on main too)**: a blank line's hatched edit, its row
  deleted and the delete undone, then set back to `""`, is a command that
  makes the cell missing; replayed, the row is back by value as an
  inserted row whose own value the cell is, and the command was refused.
  In a replay a missing cell a command means may be an empty field (as
  after a save, `holds`); the replayed command says `""`, so its undo
  works. The replay property compares cells one way: the replay may add
  trailing empty cells, and nothing else may differ.

## Benchmarks

`column_edits` (new, reference file, 1M rows; M-series laptop, quick run):

| benchmark | median |
|---|---|
| `column_edits/screen` (no column operation) | 16.2 µs |
| `column_edits/screen_10_ops` | 21.9 µs |
| `column_edits/insert_column_100k_edits` (insert + undo) | 5.70 ms |
| `column_edits/delete_column_100k_edits` (delete + undo) | 6.14 ms |

An insert or delete is well inside the 16 ms budget with 100,000 edited
rows; most of it is the walk over a million rows' field counts (the
applied rows, for undo by value) and the look at each edited row.

budget failure. With no column operation: `edits/screen` −8.7%,

## Rust notes

- **An enum as an identity** (`edit/columns.rs`, `CellId`). Deriving
  `Ord` orders the variants as written, then by their contents, so a
  row's edits sort fields first, then inserted cells, then hatched ones,
  and a binary search finds a cell's edit.
- **`Cow`** (`Layout::ids`, `Fold::as_slice`): "clone on write" hands back
  either a borrowed slice (a table entry, a written-out layout) or a new
  `Vec` (an identity layout made on the fly), with one type for both.
- **Borrowing a `static`** (`view.rs`, `NO_COLUMNS`): `RowView::own` needs
  a `&Columns` that lives as long as the view; a `static` of an empty list
  (`Columns::NONE`, a `const` because `Vec::new()` is one) lives for the
  whole program, so any lifetime fits.
- **Trait objects for lazy reads** (`ColumnSource`): a delete command holds
  `Arc<dyn ColumnSource>`, the reading and overlay it was made on, and
  reads the deleted cells only if an undo by value needs them.
- **`&mut dyn FnMut` callbacks under a lock** (`Diagnostics::for_each_code`):
  the marks are walked under their read lock, each row's code handed to a
  closure that updates the walk's state; nothing in it reads the file.
