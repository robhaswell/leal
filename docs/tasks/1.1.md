# 1.1 Source

## What was built

### `leal_core::source` (`crates/leal-core/src/source/`)

The module that turns a path into the file's bytes (DESIGN §3.1).

| File | What it holds |
|---|---|
| `mod.rs` | `Source`, `Storage`, `RawAttributes`, `FileIdentity`, the open sequence and the fallbacks. |
| `error.rs` | `OpenError` and `OpenErrorKind`. |
| `temp.rs` | `TempFolders`: temporary folders, their records, and crash cleanup. |
| `sys.rs` | The only `unsafe` code in leal-core: `fclonefileat`, `fgetxattr`, `fcntl` and the memory map. |
| `tests.rs` | 33 tests (one a property test), including disk-image tests. |

**Public API** (everything else is private):

```rust
let temp = TempFolders::new(scratch_dir, records_dir);
temp.remove_leftovers()?;                      // at launch: io::Result<usize>

let source = Source::open(&path, &temp, volume_folder)?;   // Result<Source, OpenError>
source.bytes()        // &[u8]: the snapshot
source.storage()      // Storage::{Clone, Memory, Copy}
source.attributes()   // &RawAttributes { text_encoding, interpretation }: Option<Vec<u8>> each
source.identity()     // &FileIdentity { device, inode, len, modified }
source.path()

error.kind()          // OpenErrorKind::{NotFound, PermissionDenied, Directory, NotAFile, Other}
error.path()          // the path that was opened
error.raw_os_error()  // Option<i32>, an errno
```

Constants: `MEMORY_FALLBACK_MAX_BYTES` (512 MiB), `ATTRIBUTE_MAX_BYTES`
(64 KiB), `TEXT_ENCODING_ATTRIBUTE`, `INTERPRETATION_ATTRIBUTE`.

**How `Source::open` works:**

1. Open the file read-only with `O_NONBLOCK` (so a named pipe can't hang
   it), `fstat` the open file, refuse a folder or anything that isn't a
   regular file, then clear `O_NONBLOCK`. The `fstat` result is the
   `FileIdentity`: it is taken *before* the clone, so if the file changes in
   between, saving later sees a change and asks, rather than missing one.
2. Read the two extended attributes from the open file with `fgetxattr`,
   as raw bytes (see "Interface with 1.2").
3. Clone with `fclonefileat` from the open file, so the clone is of exactly
   the file that was checked:
   - into `volume_folder`, an empty folder on the file's own volume that
     the app got from `FileManager.url(for: .itemReplacementDirectory, …,
     appropriateFor:)` (ADR-0005 decision 7);
   - if none was given, or cloning there failed other than with `ENOTSUP`
     (for example, `EXDEV` because it wasn't on the file's volume after
     all), into a new folder in Leal's scratch directory: "clone
     elsewhere";
   - `ENOTSUP` (the volume can't clone), or `EXDEV` from the scratch
     directory (the file is on another volume and no folder there was
     usable), means fall back.
4. Clone: make it mode 0400 and map it read-only (`Storage::Clone`).
   Fallback: up to 512 MiB, read into memory (`Storage::Memory`, for the
   status bar note); larger, copy into a scratch folder and map the copy
   (`Storage::Copy`). Both read exactly the size from step 1.

**Temporary folders** (`temp.rs`). Before anything goes in a temporary
folder, a record `<records>/<id>.record` is written with the folder's path,
and kept open with an exclusive `flock` lock for as long as the folder is in
use. The folder holds one file, `leal-<id>`. Dropping the `Source` deletes
that file, the folder, then the record. `remove_leftovers` locks each record
in turn: a record it *can* lock belongs to a process that has exited (the
kernel drops `flock` locks when a process dies, however it dies), so its file
and folder are deleted. A record still locked belongs to a running Leal and
is skipped. There are no PIDs to go stale, and two Leal processes (the app
and, later, the CLI) can share the records folder.

Cleanup is deliberately narrow:
- It deletes only `leal-<id>` in each recorded folder, then the folder with
  `rmdir`, which fails if anything else is in it. Nothing is ever deleted
  recursively, so a corrupted record can't remove a user's files.
- A recorded folder under `/Volumes/<name>` whose volume isn't mounted keeps
  its record for a later launch. "Checks every folder Leal recorded"
  includes other volumes.
- If `Drop` can't remove a folder, its record stays and the next launch
  tries again.

### `inspect_file`

The 0.3 skeleton's `inspect_file` is still what the app's window calls; 1.6
switches the app to `Source` and removes it (PLAN 1.1). It now opens through
`source::open_regular`, so it returns the same structured `OpenError`, and a
named pipe no longer hangs it.

### `leal-ffi`

- `LealError` is structured (Phase 0 review rust-4):
  `NotFound { path, code }`, `PermissionDenied { path, code }`,
  `NotAFile { path, is_directory }` and `Io { path, code, message }`. `code`
  is `raw_os_error()`. `message` is English, for logs only.
- `open_source(path, volume_folder, temp) -> Source` (an object with
  `byte_count()` and `storage()`), `remove_leftover_temp_folders(temp)`,
  and the `TempLocations` record (`scratch_dir`, `records_dir`). The app
  doesn't open files through these yet (1.6 does); the XCTests use them, and
  the app calls the cleanup at launch.

### App

- `Sources/OpenErrorText.swift`: the alert's title and a sentence for each
  `LealError` case, from a new String Catalog
  (`Resources/Localizable.xcstrings`, DESIGN §4.4). `Io` is worded from its
  code via `NSError(domain: NSPOSIXErrorDomain, code:)`, for example "No
  space left on device (error 28).". The switch is still exhaustive with no
  `default`. `AppDelegate.describe` moved here.
- `Sources/TemporaryFolders.swift`: the macOS side. `volumeFolder(for:)`
  asks `FileManager` for the item replacement directory; `locations()` gives
  `FileManager.temporaryDirectory` as scratch and
  `Application Support/<bundle id>/Temporary folders` for the records. Both
  are places a sandboxed app may write (DESIGN §4.3); 1.6 checks with the
  sandbox on.
- `AppDelegate` runs `removeLeftoverTempFolders` on a background queue at
  launch, and logs the core's English error text with `os.Logger` instead
  of showing it.
- Both new Swift files are also compiled into `LealTests` (in
  `project.yml`), so the wording is tested against real errors. They hold no
  AppKit state, and the test bundle doesn't import the app module, so the
  copies can't clash. (The alternative, a hosted test target, is 1.6's.)
- `SWIFT_EMIT_LOC_STRINGS: YES` on the app target, so Xcode can keep the
  catalog in step with the code. I checked that the extracted keys match
  the catalog's exactly.

What `FileManager` returns, checked on this Mac (unsandboxed):

| File on | Item replacement directory |
|---|---|
| The boot volume | `/var/folders/…/T/TemporaryItems/NSIRD_<app>_XXXXXX` |
| An APFS disk image | `<mount>/.TemporaryItems/folders.501/TemporaryItems/NSIRD_<app>_XXXXXX` |
| An exFAT disk image | the same layout on the exFAT volume (cloning there gives `ENOTSUP`) |

## Tests

- **Rust, `leal-core`**: 33 in `source/tests.rs` and 4 in
  `source/error.rs`, plus a doctest on `Source::open`.
  - Bytes: every corpus file reads back byte for byte as a clone; a
    property test over the testkit's `csv_bytes()` (256 cases); empty file;
    the snapshot survives the original being rewritten, truncated and
    deleted.
  - Errors: not found (`ENOENT`, and `ENOTDIR`), permission denied (mode
    000, `EACCES`), a folder (`EISDIR`), a named pipe, a socket and
    `/dev/null` (`NotAFile`), an unwritable scratch directory (`Other`, not
    "permission denied", since it isn't the user's file), and a given
    folder being removed when opening fails.
  - Attributes: raw values including non-UTF-8 bytes, missing, empty, and
    over the limit.
  - Volumes, with real disk images (`hdiutil`, 16 MB, mounted inside a
    temp folder with `-nobrowse`, detached on drop):
    - **a file on a second APFS volume is cloned into the folder on that
      volume** (`st_dev` checked), and the folder is gone after drop;
    - without a folder there, it falls back to memory (`EXDEV`);
    - a given folder on the wrong volume: clone elsewhere (scratch);
    - HFS+ (can't clone): memory, and the given folder is removed; above
      the limit (lowered for the test), a mode-0400 copy in scratch; the
      limit is inclusive.
  - Cleanup: a crashed clone (the record's lock released without `Drop`)
    is removed, also on another volume; a live source's folder is left
    alone; other files in a recorded folder are never deleted; a record on
    an unmounted volume is kept, one for a vanished folder is deleted.
  - `Source` is `Send + Sync`.
- **Rust, `leal-ffi`**: the error mapping for each case (path and code),
  `open_source`, cleanup.
- **XCTest** (10, was 6): permission denied and a folder through both
  `inspectFile` and `openSource`, with their alert wording; not found;
  wording from a code and with none; `openSource` with the folder
  `FileManager` gives, which is deleted when the source is released; and
  **a file on a second APFS volume (a disk image) cloned through
  `FileManager`'s folder on that volume**, the production path end to end.

`just check-all` passes: 169 Rust tests, 10 XCTests.

## Performance

Open is on the first-paint path (budget: first rows < 150 ms, independent
of file size). `Source::open` from open to the first byte readable, on the
boot volume (M-series, release build, median of 20, with a throwaway
example program that isn't committed):

| File | Open | Drop (delete clone, folder, record) |
|---|---|---|
| 1 MB | 0.40 ms | 0.16 ms |
| 100 MB | 0.93 ms | 0.12 ms |
| 1 GB | 0.45 ms | 0.11 ms |

Cloning is independent of size, as expected. The memory fallback is
proportional to size (a full read, up to 512 MiB), which is why it is the
fallback. No criterion benchmark: 1.2b sets up the benchmark harness.

## Decisions and deviations

- **The app makes the volume folder; the core uses it.** Only Foundation
  knows where a sandboxed app may make a folder on another volume, so Swift
  calls `FileManager.url(for: .itemReplacementDirectory, …)` and passes the
  folder to `open_source`, which takes it over (and deletes it, including
  when opening fails). I considered a UniFFI callback interface instead,
  so Rust could ask only when needed, but a plain argument is simpler and
  `FileManager` is cheap. The folder is made even for files on the boot
  volume, where it is in the same temporary directory anyway.
- **Without a volume folder** (the CLI, Rust tests), a file on another
  volume gets `EXDEV` from the scratch directory and falls back to memory
  or a copy. That is the one case where `EXDEV` leads to a fallback; the
  app always passes a folder. Mirroring Foundation's `.TemporaryItems`
  layout in Rust for the CLI seemed fragile, so I didn't.
- **512 MB is 512 MiB.**
- **`FileIdentity`** isn't in the PLAN entry, but saving (2.5) and the
  file watcher (1.9) need the original's identity at open, and only `open`
  can take it at the right moment (before the clone). It is four plain
  fields.
- **`inspect_file` returns `OpenError`** instead of `io::Error`, so the
  skeleton's alerts are structured now, not only after 1.6.
- **The String Catalog has only the alert strings.** The menu titles are
  still plain strings; they belong with the real menus (1.6).
- **Error kinds only for the user's file.** A "permission denied" or "no
  such file" while making Leal's own clone (a temporary folder) is
  `OpenErrorKind::Other` with its code, so the app doesn't tell the user
  they can't read a file they can.
- **Sockets**: `open` fails on a socket with `EOPNOTSUPP`; that is reported
  as `NotAFile` too.

## Interface with 1.2 (detection)

1.2's detection is a pure function over `&[u8]` plus optional hints. The
join is:

```rust
let source = Source::open(&path, &temp, volume_folder)?;
let attrs = source.attributes();
detect(source.bytes(), attrs.text_encoding.as_deref(), attrs.interpretation.as_deref());
```

`RawAttributes` holds each attribute's bytes exactly as stored: no UTF-8
check, no parsing. `None` means absent, unreadable (for example, a volume
without extended attributes) or longer than 64 KiB; 1.2 decides what an
unreadable or unsupported value means.

## Open questions

- **The sandbox.** `FileManager`'s folder on another volume, and the
  records folder in Application Support, should be writable sandboxed. 1.6
  turns the sandbox on and checks (PLAN 1.6).
- **A status bar note for `Storage::Copy`?** DESIGN §3.1 asks for one only
  for the memory fallback.
- **Records for volumes that never come back** stay forever. They are a
  few dozen bytes each; an age limit could be added if it matters.
- A crash in the moment between `FileManager` making the folder and Rust
  recording it leaves one empty folder in a temporary directory. I judged
  that not worth closing.

## Rust notes

- **`unsafe` and why mmap needs it** (`source/sys.rs`). Rust checks that
  memory is used safely, but it can't check calls into C or what the
  operating system does to memory. Code that does either is marked
  `unsafe { … }`, which means "I, the programmer, promise this is sound",
  and each block has a `// SAFETY:` comment explaining the promise.
  - For `fclonefileat`, `fgetxattr` and `fcntl`, the promise is ordinary:
    the pointers we pass point at buffers of the right size that outlive
    the call.
  - For `Mmap::map`, it is about the file. A map makes the file's bytes look
    like a `&[u8]` in memory, and Rust assumes a `&[u8]` never changes. If
    another program changed or truncated the file, the bytes would change
    under us (undefined behaviour) or reading them would crash (SIGBUS).
    So we only ever map Leal's private clone, never the user's file. That's
    the whole reason for cloning.
  - The workspace denies `unsafe` everywhere; `#[allow(unsafe_code)]` on
    `mod sys;` in `source/mod.rs` lifts it for that one file. Each function
    there wraps one unsafe call in a safe signature, so the rest of the
    module has no `unsafe` at all.
- **RAII and `Drop`.** "Resource acquisition is initialisation": a value
  that owns a resource cleans it up when it goes away. Implementing the
  `Drop` trait gives a type a destructor that Rust runs automatically when
  the value goes out of scope, on every path: normal return, `?` early
  return, or a panic unwinding.
  - `TempFolder` (`temp.rs`) owns a temporary folder; its `drop` deletes
    the clone, the folder and the record. `Source` holds an
    `Option<TempFolder>`, so dropping the `Source` (in Swift: releasing the
    last reference to it) cleans up.
  - Struct fields are dropped in the order they are declared, so `Source`
    declares `bytes` (the map) before `temp`: the map is unmapped before
    its file is deleted.
  - `GivenFolder` (`mod.rs`) is a small RAII guard: it removes the app's
    folder if `open` fails before a `TempFolder` takes it over. `release`
    hands it over without running `drop`, using `ManuallyDrop`.
  - `Drop` can't return an error, so cleanup failures are left for the
    launch cleanup.
- **errno and `io::Error`.** C functions report failure by returning -1
  and setting the thread's `errno` to a code (`ENOENT` = 2, `EACCES` = 13,
  …). `io::Error::last_os_error()` captures it, and `raw_os_error()` gives
  the number back. `error.kind()` is Rust's portable grouping of codes
  (`EACCES` and `EPERM` are both `PermissionDenied`). `OpenError` keeps both,
  so Swift can word the common kinds and use the number for the rest.
- **`flock` through the standard library.** `File::lock` and
  `File::try_lock` (stable since Rust 1.89) are `flock(2)`, so record
  locking needs no `unsafe`. `try_lock` returns
  `Err(TryLockError::WouldBlock)` if another open file holds the lock.
- **`Option<Vec<u8>>`, `as_deref`.** An attribute is `Option<Vec<u8>>`:
  maybe absent, otherwise owned bytes. `attrs.text_encoding.as_deref()`
  turns `&Option<Vec<u8>>` into `Option<&[u8]>`, a borrowed view, which is
  what a detection function wants.
- **`Send` and `Sync`.** These marker traits say a type may move to
  (`Send`) or be shared between (`Sync`) threads. The compiler works them
  out from the fields; `source_is_send_and_sync` makes it a test, because
  1.3's background indexing will share a `Source` in an `Arc`.
- **`#[cfg_attr(not(test), expect(dead_code, …))]`** on `Source::temp`:
  the field is never read in product code (it exists for its `Drop`), so
  the compiler would warn. `expect` silences that warning and itself warns
  if the field ever becomes used, so the attribute can't go stale.
