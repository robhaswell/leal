# 2.4c Saving rows and columns

The writer walks the piece list, so rows and columns inserted and
deleted are saved splice for splice as the save oracle makes them; the
rebase builds the new reading's index from the save's plan; the
carry-over maps rows through the piece list. Design: `docs/tasks/2.4.md`
§6; ADR-0012 decision 4, ADR-0014 decisions 1 and 3–6.

Built for rows while 2.4b (columns) was built alongside, then rebased
onto 2.4b and finished for columns (*Columns*, below).

## What was built

- **The walk** (`document/saving.rs`, `stream` and `Walk`). The snapshot's
  logical rows, segment by segment (`RowMap::segments`):
  - a stretch of original rows is copied in bulk, but for the rows that
    need a look of their own: its edited rows, its first row (which may
    now follow other rows, or start the file), and its last if it now
    ends the output or used to end the file. A blank line split from a CR
    before it (decision 10) brings its next row in too;
  - each deleted original row is one delete of its whole extent;
  - a run of inserted rows (`save::new_row_bytes`) is one insert at the
    start of the next original row after the previous live one (deleted
    or not), or at the end, as the oracle places them.
- **The rules** (`save/mod.rs`). `row_splices` takes the row's output line
  ending and whether the row before ends in a lone CR. An unedited row
  gets no splice unless something changes it; a row whose line ending
  changes is rewritten whole. Line endings (ADR-0004 d3, d4): an inserted
  row takes the file's most common ending (`Report::line_ending`, from
  the index pass's tally, ties to the first seen, LF if none); the last
  output row has one only if the file had a final newline. Fixes as the
  oracle: `""` for an empty new row or a blank line that now ends a file
  with no final newline (d6); `Fix::CrSplit`, new in the product (d10);
  the BOM-like first field of whichever row is first (d7). Fixes are
  listed in the oracle's order (`Fix::rank`).
- **Refusals by logical row**: `check_encodable` names edited cells and
  inserted rows' own values by logical row; Save As UTF-8's unconvertible
  cells are mapped to logical rows (`FileSink::map`); `skipped_edits`
  (Save As from an incomplete document) skips rows past the cut, inserted
  ones too.
- **The rebase** (`Document::rebuilt`). The walk notes each output row's
  start (old start plus the running shift for copied stretches,
  `RowIndex::extend_starts`; 4 bytes a row), and
  `RowIndex::from_starts(dialect, starts, len, mode, unterminated)`
  replaces `RowIndex::shifted` (removed). The new reading serves its rows
  from that index, complete at once; its index pass fills an index of its
  own for the diagnostics, and the field count mode is taken from it when
  it ends (`RowIndex::adopt_field_count_mode`, in `start_index`).
- **2.4a's limit lifted**: rows can be inserted and deleted as soon as a
  save ends, since the reading's index is complete (ADR-0014 d1's "the
  whole file read and trusted"). `IndexProgress` reports every row once
  the index is complete.
- **Carry-over** (`touched_cells`): no structural edit runs during a save,
  so each row touched since the snapshot is at its logical row in the
  snapshot's map, its row in the new file; cells are matched by
  `RowId`, inserted rows included.
- **`SaveError::RowsChanged`** and the FFI's `SaveFailure::RowsChanged`
  are gone: rows and columns save.

## Columns

- **Census** (`Walk::census`): 2.4b's `ColumnQuoting::census`, through
  the save's checkpoint, made the first time a row writes a new field (an
  inserted row's own value, or a column insert's cell; about 0.6 s per 1M
  rows), never otherwise. It answers whether the file quotes every field
  too, so the cheaper `quotes_every_field` scan isn't made as well.
- **Rows a column operation changed** (`Walk::original`, `Walk::whole`):
  with any column operation in effect every original row is looked at. A
  row that isn't `RowView::same_shape` (or reads longer than its own
  fields and edits) is written whole from its view by
  `save::whole_row_bytes`, which inserted rows use too: unedited fields'
  bytes copied (converted for Save As UTF-8, or named if they can't be),
  edited fields quoted by their own quoting, new fields by their column,
  hatched cells by 2.2's rule; the oracle's fixes (`""`, CR split,
  BOM-like). No splice if the bytes come out as the file has them, as the
  oracle. The open quote's new place is the end of the row's content less
  its field (nothing can follow it, 2.4b's `AfterUnterminatedQuote`).
  Same-shape rows keep `row_splices`, with their edits as shown
  (`RowEdits::shown`: a deleted column's edits are hidden).
- **Inserted rows** classify cells by `RowView::cell_id`: an appended
  edit is a hatched cell, anything else with a value a new field.
- **Refusals by logical column**: `check_encodable`, `skipped_edits` and
  `touched_cells` use the cells each row shows. A column insert's value
  is checked first; only if it can't be encoded is the file read (one
  pass) to name every cell it gave.
- `RowEdits::base_cells` and `base_end` are gone (nothing used them).
- **Confirmed in saved bytes**: a row left with no cells is written `""`
  (ADR-0014 d6, ADR-0004 d6) and reads back as one empty field; padding
  goes with its hatched cell's column until a save, then stays (d5);
  column commands undone after a save work by value (`Restore` puts a
  delete's cells back; an insert's undo refuses `ValueChanged` if a cell
  it gave was changed).

## Deviations and interpretations

1. **Structural edits right after a save**, before the saved file's index
   pass ends. ADR-0014 d1 asks for the whole file indexed and trusted: the
   index built from the plan is both, and the properties check it equals
   `RowIndex::build` of the saved file, column saves included. The
   diagnostics' marks (by physical row) fill in as the pass runs, as they
   do after opening. `progress().complete` is true from the start; 2.5
   should wait for the diagnostics report's own `is_complete` for the
   banner, not `IndexProgress.complete`. Column operations likewise.
2. **A by-value row delete ignores empty cells at the end** when it checks
   the rows read as recorded (`document/structural.rs`, `filled`). Undoing
   an edit past a row's end after a save leaves an empty field there
   (ADR-0012 d4: after a save the padding is a real field), so undoing the
   insert that made the row then failed with `ValueChanged`, though the
   row reads the same. The property found it.
3. **The BOM-like fix applies to whichever row is first in the output**,
   edited or not, inserted or written whole, as the oracle's rule 9 says;
   before 2.4c only an edited row 0 was checked. An unedited first row can
   start with BOM-like bytes only when rows before it were deleted (or the
   encoding was chosen), which 2.4a made possible.
4. **`Report::line_ending`** is new public API on the diagnostics report,
   for the whole file's most common line ending.
5. **The bench "save after one row insert"** of the design is
   `save/rows_deleted` (1,000 rows deleted, as the brief asks), under the
   same 500 ms budget.
6. **Every row is looked at once a column operation is in effect**, not
   only the rows it changed (finding those would mean folding each row's
   field count anyway). A save after a column delete that reaches few rows
   still reads them all: about the cost of the census.
7. **A column insert whose value can't be encoded names every cell it
   gave** (as the oracle does), which can be a million cells; not capped at
   `MAX_NAMED_CELLS` as Save As UTF-8's refusals are. For Rob: cap it, or
   name the column instead, when 2.5 shows the refusal?
8. **Oracle additions** (`leal-testkit`): `Document::delete_column_from`
   and `restore_column`, the by-value inverses of column commands after a
   save, for the undo-after-save property.

## Tests

- **Saving property** (`saving/properties.rs`, F6): every edit kind the
  strategy made (cells, rows, columns), unfiltered, a sixth of the
  commands undone at once (by identity) and half of those redone; saved
  (Save, Save over a change, Save As) and compared byte for byte and
  splice for splice, fixes included; the rebase's index equals
  `RowIndex::build` of the saved bytes (every extent, the unterminated
  quote, then the mode once the pass ends); the reopen property; then
  **undo after a save**: every command undone by value, and the same
  undos on an oracle of the saved file (columns through the oracle's new
  by-value inverses), saved again and compared splice for splice.
  Coverage (fixed seed): 110 of 366 compared cases change rows (floor
  57), 111 change columns (floor 55). Save As UTF-8 replays every kind.
- **Incomplete Save As** (new property): the copy cut at a random byte (a
  drive unplugged); cell edits taken, row and column edits refused
  `StillReading`, as the oracle is told; Save As writes the oracle's
  bytes up to the cut, says it is incomplete, and the document reads the
  copy, every row, no edits. Structural edits can't meet an incomplete
  document, so this is its F6.
- **Edit property** (`edits/properties.rs`): after edits, row and column
  runs, undos and redos, `save_plan` makes the oracle's splices or names
  its cells.
- **Oracle** (`leal-testkit`): `SavedFile::layout`, the saved file's rows
  and fields, so the saved file can be edited in its turn; checked equal
  to the reference parser's on clean and messy files, and saving it
  unedited gives the same bytes.
- Unit tests: line endings of inserted and deleted rows (mixed endings, no
  final newline either way, a blank last line, the CR split, an empty
  row, every row deleted leaving the BOM); a save with rows deleted and a
  carried-over cell, rows changeable at once after a save;
  `RowIndex::from_starts`. Columns: an insert writes the rows it reaches
  (not a blank line), a new field quoted by its column as it is now; a
  row left with no cells written `""`; padding and decision 5 before and
  after a save; column commands undone by value after a save.

## Benchmarks

New, reference file (1M rows, 100 MB), from `just bench-compare main`:

| benchmark | median | |
|---|---|---|
| `save/one_edit` | 102 ms (−1.6%) | budget 500 ms |
| `save/rows_deleted` (1,000 rows deleted, ~1,000 pieces) | 100 ms | budget 500 ms, budget-only |
| `save/rows_deleted_no_disk` | 74.9 ms | compared from now on |
| `save/write_no_disk` | 78.0 ms (+1.9%) | |

`bench-compare main` passed on its first run, no regression or budget
failure. The walk with no row edits costs what the shifted index did
(`write_no_disk` +1.9%, within its canaries' +2.0%). Elsewhere changes
are within ±5% but `find/screen_during_find` +12.2% (18.7 µs, budget
1 ms; no code it runs changed) and `rows/screen_long_field_escaped`
+7.2%, both under the 20% gate; another agent's build ran alongside.

## Rust notes

- **A struct for a walk** (`Walk<'w, 's>` in `document/saving.rs`). The
  writer's state (where it is in the file and in the output, the running
  shift, the rows waiting to be inserted) lives in one struct with a
  method per kind of piece, instead of a long function with many local
  variables. It holds borrowed things, so it has lifetime parameters:
  `'w` for what it only reads (the reading, the edits), `'s` for the
  sink it writes to through `&'s mut dyn Sink`. They are separate because
  a `&mut` reference can't be shortened the way a shared one can.
- **`std::mem::take`** (`Walk::flush`) moves a vector out of the struct
  and leaves an empty one in its place, so the bytes can be handed on
  without copying them while `self` stays usable.
- **Stable sorting** (`Walk::finish`): `sort_by_key` keeps items with
  equal keys in their order, so sorting the fixes by kind keeps each
  kind's rows in order, as the oracle lists them.
- **`Option<Vec<u32>>` as "still valid"** (`Walk::starts`): if a row's
  start can't be noted (past 4 GiB), the list becomes `None`, and the
  rebase reports it instead of building a wrong index.
