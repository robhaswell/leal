# 2.4c Saving rows and columns

The writer walks the piece list, so rows inserted and deleted are saved
splice for splice as the save oracle makes them; the rebase builds the
new reading's index from the save's plan; the carry-over maps rows
through the piece list. Design: `docs/tasks/2.4.md` §6; ADR-0012
decision 4, ADR-0014 decisions 1, 3 and 4.

Built for rows on `main` while 2.4b (columns) was built alongside. The
column parts are marked `STUB(2.4b)` or `TODO(2.4b)` and are finished
after rebasing onto 2.4b (below).

## What was built

- **The walk** (`document/saving.rs`, `stream` and `Walk`). The snapshot's
  logical rows, segment by segment (`RowMap::segments`):
  - a stretch of original rows is copied in bulk, but for the rows that
    need a look of their own: its edited rows, its first row (which may
    now follow other rows, or start the file), and its last if it now
    ends the output or used to end the file. A blank line split from a CR
    before it (decision 10) brings its next row in too;
  - each deleted original row is one delete of its whole extent;
  - a run of inserted rows (`save::new_row_bytes`) is one insert at the
    start of the next original row after the previous live one (deleted
    or not), or at the end, as the oracle places them.
- **The rules** (`save/mod.rs`). `row_splices` takes the row's output line
  ending and whether the row before ends in a lone CR. An unedited row
  gets no splice unless something changes it; a row whose line ending
  changes is rewritten whole. Line endings (ADR-0004 d3, d4): an inserted
  row takes the file's most common ending (`Report::line_ending`, from
  the index pass's tally, ties to the first seen, LF if none); the last
  output row has one only if the file had a final newline. Fixes as the
  oracle: `""` for an empty new row or a blank line that now ends a file
  with no final newline (d6); `Fix::CrSplit`, new in the product (d10);
  the BOM-like first field of whichever row is first (d7). Fixes are
  listed in the oracle's order (`Fix::rank`).
- **Per-column quoting**: `save::ColumnQuoting::quoted(column)` is used for
  an inserted row's own values. `STUB(2.4b)`: it quotes no column until
  2.4b's census replaces it, as the oracle's `TODO(ADR-0004 #2)` has it.
- **Refusals by logical row**: `check_encodable` names edited cells and
  inserted rows' own values by logical row; Save As UTF-8's unconvertible
  cells are mapped to logical rows (`FileSink::map`); `skipped_edits`
  (Save As from an incomplete document) skips rows past the cut, inserted
  ones too.
- **The rebase** (`Document::rebuilt`). The walk notes each output row's
  start (old start plus the running shift for copied stretches,
  `RowIndex::extend_starts`; 4 bytes a row), and
  `RowIndex::from_starts(dialect, starts, len, mode, unterminated)`
  replaces `RowIndex::shifted` (removed). The new reading serves its rows
  from that index, complete at once; its index pass fills an index of its
  own for the diagnostics, and the field count mode is taken from it when
  it ends (`RowIndex::adopt_field_count_mode`, in `start_index`).
- **2.4a's limit lifted**: rows can be inserted and deleted as soon as a
  save ends, since the reading's index is complete (ADR-0014 d1's "the
  whole file read and trusted"). `IndexProgress` reports every row once
  the index is complete.
- **Carry-over** (`touched_cells`): no structural edit runs during a save,
  so each row touched since the snapshot is at its logical row in the
  snapshot's map, its row in the new file; cells are matched by
  `RowId`, inserted rows included.
- **`SaveError::RowsChanged`** and the FFI's `SaveFailure::RowsChanged`
  are gone.

## Deviations and interpretations

1. **Structural edits right after a save**, before the saved file's index
   pass ends. ADR-0014 d1 asks for the whole file indexed and trusted: the
   index built from the plan is both, and the property checks it equals a
   scan of the saved file. The diagnostics' marks (by physical row) fill
   in as the pass runs, as they do after opening. `progress().complete`
   is true from the start; 2.5 should wait for the diagnostics report's
   own `is_complete` for the banner, not `IndexProgress.complete`.
2. **A by-value row delete ignores empty cells at the end** when it checks
   the rows read as recorded (`document/structural.rs`, `filled`). Undoing
   an edit past a row's end after a save leaves an empty field there
   (ADR-0012 d4), so undoing the insert that made the row then failed
   with `ValueChanged`. The property found it.
3. **The BOM-like fix** now applies to the first output row whether it is
   edited or not, as the oracle's rule 9 says; before, only an edited row
   0 was checked (an unedited one can't start with BOM-like bytes unless
   rows before it were deleted, or the encoding was chosen).
4. **`Report::line_ending`** is new public API on the diagnostics report,
   for the whole file's most common line ending.
5. **The bench "save after one row insert"** of the design is
   `save/rows_deleted` (1,000 rows deleted, as the brief asks), under the
   same 500 ms budget.

## Tests

- **Saving property** (`saving/properties.rs`): the strategy's row inserts
  and deletes are replayed with its cell edits, saved (Save, Save over a
  change, Save As) and compared splice for splice, fixes included; the
  rebase's index equals `RowIndex::build` of the saved bytes (every
  extent, the unterminated quote, then the mode once the pass ends); the
  reopen property; then **undo after a save**: every command undone by
  value, and the same undos on an oracle of the saved file, saved again
  and compared splice for splice. Coverage: 115 of 353 compared cases
  change rows (floor 57). Save As UTF-8 replays row edits too.
- **Edit property** (`edits/properties.rs`): after edits, row runs, undos
  and redos, `save_plan` makes the oracle's splices or names its cells.
- **Oracle** (`leal-testkit`): `SavedFile::layout`, the saved file's rows
  and fields, so the saved file can be edited in its turn; checked equal
  to the reference parser's on clean and messy files, and saving it
  unedited gives the same bytes.
- Unit tests: line endings of inserted and deleted rows (mixed endings, no
  final newline either way, a blank last line, the CR split, an empty
  row, every row deleted leaving the BOM); a save with rows deleted and a
  carried-over cell, rows changeable at once after a save;
  `RowIndex::from_starts`.

## Rust notes

- **A struct for a walk** (`Walk<'w, 's>` in `document/saving.rs`). The
  writer's state (where it is in the file and in the output, the running
  shift, the rows waiting to be inserted) lives in one struct with a
  method per kind of piece, instead of a long function with many local
  variables. It holds borrowed things, so it has lifetime parameters:
  `'w` for what it only reads (the reading, the edits), `'s` for the
  sink it writes to through `&'s mut dyn Sink`. They are separate because
  a `&mut` reference can't be shortened the way a shared one can.
- **`std::mem::take`** (`Walk::flush`) moves a vector out of the struct
  and leaves an empty one in its place, so the bytes can be handed on
  without copying them while `self` stays usable.
- **Stable sorting** (`Walk::finish`): `sort_by_key` keeps items with
  equal keys in their order, so sorting the fixes by kind keeps each
  kind's rows in order, as the oracle lists them.
- **`Option<Vec<u32>>` as "still valid"** (`Walk::starts`): if a row's
  start can't be noted (past 4 GiB), the list becomes `None`, and the
  rebase reports it instead of building a wrong index.
