# 2.4c Saving rows and columns

The writer walks the piece list, so rows and columns inserted and
deleted are saved splice for splice as the save oracle makes them; the
rebase builds the new reading's index, and each row's field count, from
the save's plan; the carry-over maps rows through the piece list.
Design: `docs/tasks/2.4.md` §6; ADR-0012 decision 4, ADR-0014 decisions
1 and 3–6.

## What was built

- **The walk** (`document/saving/walk.rs`, `stream` and `Walk`). The
  snapshot's logical rows, segment by segment (`RowMap::segments`):
  - a stretch of original rows is copied in bulk, but for the rows that
    need a look of their own: its edited rows, its first row (which may
    now follow other rows, or start the file), and its last if it now
    ends the output or used to end the file. A blank line split from a CR
    before it (decision 10) brings its next row in too;
  - each deleted original row is one delete of its whole extent;
  - a run of inserted rows is one insert at the start of the next
    original row after the previous live one (deleted or not), or at the
    end, as the oracle places them.
  `document/saving.rs` keeps the job and the rebase; the sinks are in
  `saving/sink.rs`.
- **The rules** (`save/mod.rs`). `row_splices` takes the row's output line
  ending and whether the row before ends in a lone CR; a row whose line
  ending changes is rewritten whole. Line endings (ADR-0004 d3, d4): an
  inserted row takes the file's most common ending (`Report::line_ending`,
  ties to the first seen, LF if none); the last output row has one only
  if the file had a final newline. Fixes as the oracle: `""` (d6),
  `Fix::CrSplit` (d10), the BOM-like first field of whichever row is first
  (d7), in the oracle's order (`Fix::rank`).
- **Refusals by logical row and column**: `check_encodable` names edited
  cells, inserted rows' values and a column insert's cells (one pass over
  the file, only if its value can't be encoded), the first
  `MAX_NAMED_CELLS` (1,000) with a `more` flag, as Save As UTF-8's
  `Unconvertible` (the FFI's `SaveFailure::Unencodable` carries it);
  Save As UTF-8's unconvertible cells are mapped to logical rows;
  `skipped_edits` skips rows past an incomplete document's cut.
- **The rebase** (`Document::rebuilt`). The walk notes each output row's
  start (`RowIndex::extend_starts` for copied stretches) and **field
  count** (copied rows keep the old file's, from its marks or its own
  saved counts; rows written are counted as written: one field a cell,
  `""` one, a blank line none). `RowIndex::from_starts` (which checks the
  first row starts just past the BOM) gets their mode (ties to the first
  seen, as the index pass), so the column count is right in the outcome's
  first screen and `Document::column_count` at once; the counts go to
  `Reading::counts`, which column operations use (`columns::Counts`) until
  the marks are complete. So rows *and columns* can be inserted and
  deleted as soon as a save ends; the index pass runs only for the
  diagnostics and the review. `IndexProgress` reports every row at once.
- **Carry-over** (`touched_cells`): no structural edit runs during a save,
  so each row touched since the snapshot is at its logical row in the
  snapshot's map, its row in the new file; cells are matched by `RowId`.
- **`SaveError::RowsChanged`** is gone: rows and columns save.

## Columns

- **Census** (`ColumnQuoting::census`), made the first time a row writes
  a new field. It parses each 4,096-row window itself
  (`Document::each_physical`), not through the grid's row cache, whose
  lock and LRU eviction made most of a column save's time and stalled
  the main thread's screen reads. It stops once no row can change its
  answers: the file doesn't quote every field, and every column some
  row's layout gives an original field (`original_columns`, from the
  field counts) has an unquoted one. A column with no original field (an
  inserted one) quotes every field only if the file does, so it doesn't
  hold the census to the end. The save's progress shows the pass
  (`SavePhase::Checking`, bytes read of the file), then writing again.
- **Rows a column operation changed** (`Walk::original`, `Walk::whole`):
  with any column operation in effect every original row is looked at,
  its layout folded once (`RowView::layout`, `same_shape_in`, `cell_in`).
  A row that isn't the same shape is written whole by
  `save::whole_row_bytes`: unedited fields' bytes copied (converted for
  Save As UTF-8, or named), edited fields quoted by their own quoting, new
  fields by their column, hatched cells by 2.2's rule, the oracle's
  fixes. No splice if the bytes come out as the file has them.
- **Inserted rows** classify cells by `RowView::cell_id`: an appended
  edit is a hatched cell, anything else with a value a new field.
- **Confirmed in saved bytes**: a row left with no cells is written `""`;
  padding goes with its hatched cell's column until a save, then stays
  (d5); column commands undone after a save work by value.

## Undo by value puts bytes back

A row or column delete undone after a save (or in a replay) puts each
unedited field back **as its bytes** (`RowView::put_back`, `edit::Value`
and `RawField`), not as how it reads: invalid bytes, a NUL and a field's
own quoting come back as they were (UTF-8 `a,b\xffc` came back as
`a,b\xef\xbf\xbdc` before). The view shows such a cell as
`ViewCell::Raw`; the writer writes its bytes (converted for Save As
UTF-8); a save doesn't encode it; the census doesn't count it. Edited
cells, hatched cells and inserted values come back as text, and so does
an unterminated quote's field (its bytes would swallow what follows) or,
after Save As UTF-8, a field that can't be converted. A delete by value
still compares how cells read. The oracle does the same
(`Document::restored`, `restore_row`, `restore_column`).

## Deviations and interpretations

1. **Structural edits right after a save**, before the saved file's index
   pass ends. ADR-0014 d1 asks for the whole file indexed and trusted: the
   index and field counts built from the plan are both, and the
   properties check them against `RowIndex::build` of the saved file and,
   once the pass ends, the marks. `progress().complete` is true from the
   start; 2.5 should wait for the diagnostics report's own `is_complete`
   for the banner.
2. **A by-value row delete ignores empty cells at the end** when it checks
   the rows read as recorded (`structural.rs`, `filled`): undoing an edit
   past a row's end after a save leaves an empty field there (ADR-0012
   d4), which reads the same.
3. **The BOM-like fix applies to whichever row is first in the output**,
   as the oracle's rule 9 says; before 2.4c only an edited row 0 was
   checked.
4. **New API**: `Report::line_ending`; `SavePhase::Checking`;
   `SaveError::Unencodable`'s `more` (also in the FFI).
5. **"Save after one row insert"** of the design is `save/rows_deleted`
   (1,000 rows deleted), under the same 500 ms budget.
6. **Every row is looked at once a column operation is in effect**, not
   only the rows it changed (finding those would mean folding each row's
   field count anyway).
7. **Undo by value restores a field's bytes** (above): ADR-0014 d3 says
   "by value"; this reads it as the field's value as the file holds it,
   which F1 (bytes not edited stay) asks for. For Rob: confirm, or an ADR.
8. **Oracle additions** (`leal-testkit`): `delete_column_from`,
   `restore_column`, `restore_row`, `restored` and raw cells, for the
   undo-after-save property.

## Tests

- **Saving property** (`saving/properties.rs`, F6): every edit kind the
  strategy made (cells, rows, columns), unfiltered, a sixth undone at once
  and half of those redone; saved (Save, Save over a change, Save As) and
  compared byte for byte and splice for splice, fixes included; the
  rebase's index equals `RowIndex::build` of the saved bytes, and before
  the index pass ends, the mode, the first screen's and the document's
  column count, and column operations not `StillReading`; after it, the
  save's field counts equal the marks; the reopen property; then **undo
  after a save**, every command undone by value (fields as their bytes),
  the same on an oracle of the saved file, saved again and compared. It
  fails if the product restores text. Refusals compare the oracle's cells
  capped at 1,000.
- **Incomplete Save As**: the copy cut at a random byte; cell edits
  taken (refusals listed: `NoSuchRow`, `NotReadYet`,
  `AfterUnterminatedQuote`), row and column edits refused `StillReading`;
  Save As writes the oracle's bytes up to the cut.
- **Edit property**: after edits, row and column runs, undos and redos,
  `save_plan` makes the oracle's splices or names its cells.
- Unit tests: line endings of inserted and deleted rows; rows and columns
  changeable at once after a save (and refused during one); a column
  insert and deletes on a 12-column file, the column count right at once
  and the counts equal to the marks; the census stopping at the first
  batch with an inserted column, and reading to the end for a column only
  the last row reaches; the census in the save's progress; a column
  insert's refusal capped at 1,000 with `more`; deletes undone after a
  save putting bytes back (invalid UTF-8, Windows-1252, a NUL, quoting,
  converted by Save As UTF-8 in between); `from_starts` and the BOM.

`just check-all`: 907 Rust tests, 215 app tests. `just test-deep`

## Rust notes

- **A struct for a walk** (`Walk<'w, 's>` in `document/saving/walk.rs`).
  The writer's state lives in one struct with a method per kind of piece.
  It holds borrowed things, so it has lifetime parameters: `'w` for what
  it only reads, `'s` for the sink it writes to through
  `&'s mut dyn Sink`. A `&mut T` can be shortened like any reference,
  but it is *invariant* in `T`: what it points to can't be treated as
  having a shorter lifetime, so behind `&'s mut dyn Sink` the trait
  object's own lifetime (`dyn Sink + 's`) can't be adjusted to match
  `'w`. Hence the sink gets its own lifetime parameter rather than
  sharing `'w` with the read-only borrows. (Corrected at the phase 2
  gate.)
- **An enum that carries data** (`edit::Value`): a value is either
  `Text(Arc<str>)` or `Raw(Arc<RawField>)`, and `match` makes every use
  say what it does with each; adding `ViewCell::Raw` made the compiler
  list every place that reads a cell. `Arc` lets the command, the edits
  and the view share one copy of a field's bytes.
- **Destructuring parameters** (`Walk::whole`): `(view, layout):
  (&RowView, &Layout)` takes a pair and names its parts, which keeps the
  argument list short without a struct.
- **`std::mem::take`** (`Walk::flush`) moves a vector out of the struct
  and leaves an empty one in its place, so the bytes can be handed on
  without copying them.
