# 2.5.3b App: after a save

After a successful Save, the window now shows the reading the core made of
the file it just wrote (ADR-0008 decision 1), as after a re-read: nothing
read from the old reading is used again. A kept old file is moved to a
Recovered folder at once and reported. The last part of ADR-0008
decision 8, the whole-file review's delimiter, is written. This closes
2.5.3a's known gaps: edit triangles lingering after a save, and the new
diagnostics arriving only on the next `checkOriginal`.

## How it works

**Adopting the saved reading** (`DocumentModel.adoptSaved`). When the
save's outcome has a first screen and the core's `progress().generation`
is newer than the model's, the model:
- takes the new generation (so `readingID` changes);
- drops `tiles` and `flagBlocks`;
- sets the review and the reviewed line ending to nil;
- cancels the old reading's waiters and waits for the new one's jobs.

It keeps the interpretation, column count and widths, number alignment,
header titles, the undo stack and, until the new one is complete, the
old diagnostics report: the values are the same. Edits made
during the save stay unsaved: the core carried them over, and the dirty
state is read from it. From a save's start until its outcome reaches
`saved(_:)`, `saveOutcomePending` keeps `checkOriginal` from taking the
new generation as a re-read (`restarted`). A save that couldn't read its
file back but finds a new generation (a drive back) calls `restarted`.

Sizing under way when the save ends read the old reading, so its result
would be dropped. It starts again on the new reading: either the first
refined sizing or a measuring after an edit.

**The window** (`DocumentChange.saved`). The `readingID` change redraws
every strip (2.0b), so no strip keeps the old reading's cells or the
saved edits' triangles. Unlike `.rows` or `.reloaded`, `.saved` doesn't
discard an open editor (edits carry on during a save). It also keeps the
selection, scroll position and inspector. Find searches the new reading
again without a step (`FindModel.searchAgain`): nothing moves the
selection, and the current match stays current. When the bar is hidden, `find.stop()` lets the old search go,
and with it the old reading. A copy promised to the pasteboard keeps
its own job, as after a Reload: it gives exactly the cells copied.

**Diagnostics.** After a save `IndexProgress.complete` is true at once
(2.4c), but the index pass still builds the diagnostics. While
`awaitingCompleteDiagnostics` is set, `refreshDiagnostics` takes only a
report with `complete`, and the old report stays meanwhile. So the
banner, the badge and the review neither flicker nor show a partial
report. The diagnostics banner and the suggestions
normally start afresh on a new reading. After Leal's own save, banners
the user closed stay closed (`readingFromSave`; Rob's decision).

**Not an outside change.** The core already gives the watcher the new
identity and clears `diverged` (2.2). `saved(_:)` takes the outcome's
status. The hosted test saves twice, with `checkOriginal` after each, and
sees no banner and no prompt.

**`keptOldFile`.** `saveFinished` starts `keepOldFile(path)`, and the
save waits for it, so Save and Close or ⌘Q tell the user first. If the
core kept it next to the user's file (`a (replaced, kept by Leal).csv`,
its first choice), it stays. Otherwise, off the main thread, it is moved
into Leal's Recovered folder in Application Support, under its own name,
numbered (" 2", " 3"…) if that's taken (`renamex_np` with
`RENAME_EXCL`; a copy across volumes). The emptied temporary folder is
removed. A sheet (an app-modal alert with no window) says "Leal saved
“a.csv” and kept the version it replaced.", with where it is: next to
it, or in the Recovered folder. Its buttons are OK (Return) and Show in
Finder. If the move fails, it gives the file's current path and asks the
user to move it somewhere safe. Either way, it is logged.

**Attributes (ADR-0008 decision 8).** The core writes
`com.apple.TextEncoding` and the interpretation attribute on every save,
before the swap. It records or removes them by the first-paint and
whole-file encoding guesses and the user's or the attribute's choices,
always with the new fingerprint (2.2, 2.3). It never copies Leal's two
from the old file. What was left was the whole-file *delimiter* review
(`SEAM(2.5)` in `save/attributes.rs`), now closed:
- When the review of a save's reading finishes with a delimiter
  suggestion, the model calls `onSavedReadingReviewed`.
- `CSVDocument.remember` takes a coordinated write of the file's
  metadata only, with the document as presenter. Inside it, on
  `FileWork`, it calls `rememberReviewedInterpretation()`. While the
  write is held nothing waits for the main actor (the 2.5.3a rule). It
  takes no file access of its own: asking for one while a save holds one
  blocks the main thread. With no coordinated write it doesn't call the
  core. Coordinated writes sharing a presenter don't wait for each other
  (checked: a second `.forReplacing` write with the same presenter is
  granted at once), so Leal's own save never waits for this write; the
  core's checks keep the two apart. It skips
  this while another save runs: that save's reading is reviewed in turn.
- The core writes `v=1;delimiter=…;header=…;file=<fingerprint>` (keeping
  a recorded `encoding`) only if all of these hold:
  - no save is under way;
  - the current reading is one a save made (`Reading::saved`);
  - its review has finished and suggests a delimiter;
  - neither the save nor an earlier call recorded a delimiter;
  - the watcher saw no change;
  - the file at its current path is the one that reading read (its
    source's volume, inode, length and modification time), not merely
    the watcher's: a later save that couldn't read its file back leaves
    the old reading current.
- It writes through `fsetxattr` on the descriptor it checked, so a file
  swapped in meanwhile is never touched. An extended attribute doesn't
  change that identity, so it isn't a change elsewhere.
- Once written, the delimiter counts as the attribute's choice
  (`Reading::remembered`, `AttributeFacts::remembered`): every later save
  records it itself, as decision 8 asks.

## Tests

`AfterSaveTests`: 12 hosted tests, sandboxed, against the real core:
- **Grid.** An edit is made while the save is held. After it: a new
  generation, the saved values, no triangle on saved cells (the edit made
  during the save keeps its own), strips equal to a direct draw, the same
  widths, the new reading's complete diagnostics, and undo carries on.
- **Diagnostics.** On a 200,000-row file, `progress.complete` is true
  right after the save. Polled every millisecond, the new reading's
  report is never partial, and there is always a report (the old one
  meanwhile). With the `awaitingCompleteDiagnostics` guard removed, it
  fails.
- **Find.** The search restarts on the new reading, the current match
  stays current, and it finds an edit made after the save. The old
  `Search` is freed. With a range selected whose active cell isn't a
  match, the selection doesn't move.
- **Gap.** `checkOriginal` ending between the save's end and `saved(_:)`
  leaves the generation alone; `saved(_:)` adopts it as a save's.
- **Twice.** Saved twice, with `checkOriginal` after each: no banner,
  no prompt, `diverged` false, and a closed diagnostics banner stays
  closed.
- **Kept file.** Moved to Recovered with its contents and the sheet's
  wording; a second one is numbered; one that can't be moved is reported
  where it is. One next to the user's file stays and is reported so.
  With no window, an app-modal alert says where it is.
- **Attributes.** After Save the attributes are the saved file's own; a
  garbled one is removed.
- **Review.** A file whose first 64 KB are comma-separated but whose
  whole-file review suggests semicolons: Save records nothing, then the
  review writes `delimiter=comma` with the saved fingerprint. A second
  save, with the window closed at once, records it itself.
- **No deadlock.** The recording is held inside its write; a save starts;
  the main thread reads `isDocumentEdited`, then blocks until the write
  ends; a background thread lets the recording go. A watchdog stops the
  host on a deadlock. The delimiter is recorded in the end.

Rust: `the_saved_readings_review_adds_the_interpretation_attribute`
(nothing for an opened reading; the save writes nothing, then the review
does; `diverged` stays false; a reopen reads comma; the next save
records it itself) and
`an_earlier_saves_reading_never_overwrites_a_later_saves_attribute` (a
recorded `encoding=`; nothing while a save runs; a later save that
can't read its file back keeps its attribute).

Results:
- `just check-all` passes: 915 Rust tests (1 skipped, as before),
  and `app-test` Debug 299 passed.
- `just app-test release`: 299 passed.
- `just check-no-test-exports` and `just check-no-bench` pass.

No hot path changed. The new work runs once per save (a generation
compare) and once per save's review (one `fstat` and one `fsetxattr`).

## Deviations and notes for Rob

- **The kept-file tests are unit-level.** Making the core keep an old
  file needs a race at the swap, which the app can't stage. The tests
  call `keepOldFile` directly. `saveFinished` calls it for any
  `outcome.keptOldFile`, and the save waits for the user's answer.
- **Show in Finder** reveals the file inside the sandbox container
  (`~/Library/Containers/…/Application Support/<bundle ID>/Recovered`).
- **A closed banner stays closed across a save** (Rob's decision). It
  still comes back after a Reload, Treat As or a re-read.
- **`same_file` still leaves out the volume** (a removable drive mounted
  again gets a new one, and Save relies on that). The review's check
  compares the volume as well.
- **The delimiter suggestion banner still shows after a save** of such a
  file: the reading still guessed comma. A reopen won't show it, because
  the attribute now records comma.
- **On-screen check:**
  - ⌘S on an edited file: the triangles go, and the badge settles once
    the pass ends.
  - ⌘S with the find bar open.
  - ⌘S twice.
  - A large file whose late rows use another delimiter: run
    `xattr -l` after saving.

## Rust notes

- **`Option<Result<&T, E>>` with `let … else`** (`document/remember.rs`):
  `let Some(Ok(review)) = reading.review_job.result() else { return
  Ok(false) };` takes the review only if the job has finished *and*
  succeeded. Any other case (still running, failed) returns early. The
  `else` block must leave the function, so the compiler knows `review`
  is set after it.
- **`is_some_and`**: `recorded.is_some_and(|r| r.delimiter.is_some())` is
  "there is a value, and this holds for it", without unwrapping.
- **`Arc` snapshot of the reading**: `self.current()` clones the `Arc`
  holding the current reading. It stays valid even if a save or re-read
  swaps in a new one meanwhile. The method then works on one consistent
  reading, and the `saved` flag tells it whether that reading is a save's.
- **`io::Result<bool>`** is `Result<bool, std::io::Error>`. `?` after
  `look_afresh(…)` passes an I/O error straight up to the caller. The FFI
  turns it into `LealError::Io` for Swift.
- **`AtomicBool` inside a shared reading** (`Reading::remembered`): the
  reading sits in an `Arc`, so only shared references (`&Reading`) reach
  it and a plain `bool` couldn't be changed. An atomic can: `store(true,
  Release)` after the attribute is written pairs with `load(Acquire)` in
  the next save, so a save that sees `true` also sees the write before it.
