# 2.6a Tidy-up, app items

Nits from the 2.5a, 2.5.3c and 2.6a reviews (PLAN 2.6a). The fuzz-memory
item and the hard-link Save As note are left open on purpose.

## What changed

- `snapshot` (`GridStripsTests`) fails (`XCTFail`) if the strips are still
  deferring ink after its 5 passes.
- `CellTileCache.readAhead` sets or widens `wanted` right after the rows are
  clamped, before the early returns (no fetch hook, empty columns, no
  column block that far right). A frame whose read ahead returned early
  used to leave the last frame's range, so a queued read for rows the
  scroll had left was not skipped. `GridDrawingTests`.
- `DocumentViewController.viewDidAppear` calls `updateWindowMinimum()`
  (banners and panes that came before the view had a window had left the
  minimum unset) and drops `queuedAlerts` for a document that has failed
  since (it says so itself). `DocumentTests`.
- `CSVDocument.mainThreadRereads` counts `read(from:)`'s main-thread
  branch; `testRevertToSavedNeverReachesTheMainThreadRead` (SaveAsTests)
  shows Revert to Saved (asked, and with no edits) and AppKit's
  `revert(toContentsOf:ofType:)` never reach it, and a direct call does.
- `testCancellingASaveAsQueuedBehindASave` (SaveAsTests): ⌘. stops both,
  nothing is written, the document keeps its file and edits, no alert.
- `revert(toContentsOf:ofType:)` now tells the user what stopped it, through
  the Reload path (`DocumentViewController.showRereadFailure`): an edit made
  meanwhile gives the existing "Leal didn’t reload “name”." alert (strings
  reused: Revert to Saved from the menu already ends in the same alert via
  `startReload`). Any other error gets Reload's "couldn’t reload" alert.
  `showReloadError` now goes through `showAlert` (stubbable) instead of
  `beginSheetModal` directly.

## 2.5a items

- **⌘⌫ in the inspector, not editing** (focused with nothing it can edit:
  a missing cell's note, an unread row, edits refused; the inspector is
  editable whenever the cell is, so there ⌘⌫ stays the text's). Decision:
  the key deletes the row
  (`LiteralTextView.performKeyEquivalent` → `deleteRows` through the
  responder chain when `!isEditable`), so it agrees with Edit > Delete Row,
  which is on. Why: DESIGN §4.2 lists ⌘⌫ as "delete row"; text deletion is
  only the right meaning where there is text to edit (the in-cell editor,
  the inspector while editing). Beeping while the menu item was on was the
  inconsistency; turning the item off would take away a working command.
  DESIGN §4.2's table says so. ⌘↩ in a non-editing inspector is still the
  inspector's commit (unchanged; it does nothing there).
- **Header-only file:** Insert Column Before/After are off with "A column is
  inserted beside the selected cell, and a file with only a header row has
  no cell. Insert a row first." (the core's own refusals, such as still
  reading, come first).
- **Find bar (or any non-editor text field) focused:** the row and column
  items are off with "Click the table first." Cut, Paste and Delete are the
  field's own then (enabled, acting on its text), so they need no tooltip.
- **VoiceOver** (`announce`, as Find and the refusals use): "Row inserted",
  "Column inserted", "Row duplicated" / "3 rows duplicated", "Row deleted" /
  "3 rows deleted", "Column deleted" / "2 columns deleted", "6 cells
  pasted", "2 cells cleared", "4 cells cut" / "2 rows cut". Only for a
  change made (`.edited`; Cut also when the copy was made). Undo and redo
  are not announced (they show in the Edit menu).
  All new strings are in `Localizable.xcstrings` (`just strings`).

## Manual checks for Rob

1. Open a CSV with a short row, show the inspector (⌘I), click the short
   row's missing (hatched) cell, then click in the inspector's note: ⌘⌫
   deletes the row (Edit > Delete Row is on). On an ordinary cell, with the
   cursor in the inspector, ⌘⌫ deletes text to the line start.
2. Open a file with only a header row: Edit > Insert Column Before/After
   are grey and hovering shows the "Insert a row first" tooltip. Insert a
   row, and they work.
3. Click the find field: hover the grey Insert Row/Column, Delete and
   Duplicate items: "Click the table first."
4. With VoiceOver on, insert, duplicate, delete rows and columns, paste,
   Delete and Cut in the grid: each says what it did (a sentence, after
   the selection speech).
5. (Rare) Make AppKit revert while an edit lands: no easy way by hand; the
   test covers it.
