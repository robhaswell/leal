# 2.7 Fuzzing

`cargo-fuzz` targets for the indexer, detection, the row parser and the
serializer, each checked against the testkit's oracle rather than for
panics alone; a `just fuzz` recipe; and a nightly CI workflow. DESIGN §5
test layer 4.

## What was built

- **`fuzz/`**, a cargo-fuzz crate in its own workspace (`[workspace]` in
  `fuzz/Cargo.toml`, its own `Cargo.lock`), so the release build and the
  main workspace never compile it. It depends on leal-core with
  `test-hooks` (for `Document::save_to_writer`, the save to memory) and
  on leal-testkit.
- **The oracle.** `fuzz/src/lib.rs` compiles the testkit's reference
  parser (`crates/leal-testkit/tests/oracle/mod.rs`) in by `#[path]`. It
  is kept in the testkit's integration tests so product code can't use it
  (0.2 notes); the fuzz crate is test code, so it may. Its `analyze` gives
  the layout, values and diagnostics for any bytes in any encoding,
  UTF-16 included, which the generator-based property tests can't: they
  only see files the generator writes.
- **Targets** (`fuzz/fuzz_targets/`):

  | Target | Input | Checks |
  |---|---|---|
  | `index` | any bytes | In every delimiter and each encoding the BOM allows (no BOM: UTF-8, Windows-1252 and one other single-byte encoding), built whole, chunk by chunk (1–61 bytes) and by the background indexer: row spans and line endings, extents tiling the file, field-count mode, unterminated quote and the row at every offset, all as the reference parser finds them; diagnostics (kinds, counts, locations) as the oracle derives them. |
  | `detect` | any bytes | Detection and the review run twice give the same answer. With no attribute the encoding is `expected_encoding` (ADR-0003 d1) and the review suggests nothing; with each TextEdit attribute it is `reopen_encoding` (ADR-0004 d11). A chosen encoding is refused exactly when the BOM doesn't allow it, and a chosen delimiter, header and encoding are used. Also the bytes as garbled attribute values, and as the head of a longer file. |
  | `rows` | any bytes | Readings as `index`: every field's span, quoting, text after the closing quote, unterminated quote, value bytes and display value as the reference parser's; parsing and display from a window give the same; display prefixes are the full value's first characters. |
  | `serialize` | file + edit script | See below; the encoding is detection's. |
  | `encodings` | file + edit script | As `serialize`, with the encoding chosen by the script among all 16 the BOM allows: every single-byte encoding (including those detection never picks) and UTF-16, through detection, editing, saving and reopening. Values include characters the encoding has (`Piece::High`, byte `0x80 \| n` in that table) and lacks. |

- **The serializer harness** (`fuzz/src/harness.rs`). An input is a file,
  optionally followed by `\0EDITS\0` and a script read with `arbitrary`:
  a delimiter choice, an encoding choice, Save / Save As / Save As UTF-8,
  and up to 24 ops (set a cell, insert a row of 1–4 values, delete a row,
  insert or delete a column, undo, redo). Rows and columns are taken
  modulo a little past the document's size, so some edits are refused and
  hatched cells are reached; values are pieces chosen to need quoting
  (quotes, delimiters, CR, LF, U+FEFF), a cell's original value (which
  removes its edit), another cell's value, or any text. For each input:
  1. The file is written to a temporary folder and opened as a user
     would (`Document::open`); the oracle analyses the same bytes. Every
     value must match before any edit.
  2. Each op is made on the document and on `leal_testkit::save::Document`;
     they must accept and refuse the same edits. Undo applies the last
     command's inverse and puts back the oracle as it was before it;
     redo makes the command and the oracle's edit again.
  3. `save_to_writer` must give the oracle's bytes; for Save and Save As
     also the oracle's splices (`check_only_changed`, F2/F6), the plan's
     splices and its fixes (F4); or the same refusal: read-only (UTF-16),
     or the same cells, capped at 1,000, for `Unencodable` and
     `Unconvertible` (F5).
  4. The saved bytes, opened afresh in the delimiter and encoding written,
     read as the oracle's rows: every value and field count, and the line
     endings the oracle says (ADR-0004 d10).
  5. Every command still done is undone, and saving again gives the
     original bytes exactly (F1, F3).
  `LEAL_FUZZ_VERBOSE=1` prints what each input exercised.
- **Seeds.** Every target is seeded from `tests/corpus` itself, which is
  byte-exact already (its `.gitattributes` has `-text`), so no copy can
  fall out of step with it. For `serialize` and `encodings`, `just fuzz`
  also writes each corpus file with a fixed script after it (64 bytes of
  SHA-512 of its name) to `fuzz/corpus/<target>.seeds`. `fuzz/leal.dict`
  gives libFuzzer the script marker, BOMs and CSV tokens.
- **`just fuzz <target> [seconds]`** (default 300), extra arguments to
  libFuzzer. Needs `cargo install cargo-fuzz` and nightly Rust
  (`LEAL_FUZZ_TOOLCHAIN`, default `nightly`). New inputs go to
  `fuzz/corpus/<target>`, crashes to `fuzz/artifacts/<target>` (both
  git-ignored); `-timeout=60` reports a hang as a crash.
- **`just fuzz-lint`**, run by `just check`: rustfmt and clippy
  (`-D warnings`) on the fuzz crate, on the pinned stable toolchain. A few
  seconds; it catches a core API change that breaks the targets on the
  commit, not in the next night's run.
- **CI** (`.github/workflows/fuzz.yml`): nightly at 02:41 UTC and by hand
  (`gh workflow run fuzz.yml -f seconds=1800`). One macOS runner per
  target, 10 minutes of fuzzing each, in parallel (about 15 minutes a job
  with the build; 45-minute timeout). Nightly Rust is installed for this
  job only. The corpus is kept between nights in the Actions cache. A
  crash or mismatch fails that target's job and uploads
  `fuzz/artifacts/<target>`.

## Local runs

Each target for 5 minutes (`just fuzz <target> 300`) on the M5 Pro,
nightly Rust with AddressSanitizer (cargo-fuzz's default), two at a time,
seeded from `tests/corpus` (inputs up to 22 KB, its largest file):

| Target | Runs | Runs/s | Result |
|---|---|---|---|
| `index` | 23,444, then 35,297 | 77, then 117 | Finding 1 in a 30 s trial first; then clean |
| `detect` | 30,191 | 100 | Clean |
| `rows` | 57,909 | 192 | Clean |
| `serialize` | 89,106 | 296 | Clean |
| `encodings` | 102,330 | 339 | Clean |

The second `index` run is after checking the row at offsets around each
row boundary rather than at every offset, which made large inputs about
ten times slower. Over the `serialize` corpus after its run
(`LEAL_FUZZ_VERBOSE=1 cargo fuzz run serialize corpus/serialize --
-runs=0`): 4,389 inputs, 2,355 of them kept 5,622 commands between them;
3,359 saved (1,574 Save, 765 Save As, 1,020 Save As UTF-8), 685 refused
as read-only (UTF-16), 91 as unencodable and 254 as unconvertible;
Windows-1252 2,295, UTF-8 1,033, UTF-16 LE 632, BE 429. The targets are
slow per input (each reads the input in up to 12 ways, and the edit
targets open two documents on disk), so the nightly 10 minutes is about
50,000–200,000 inputs a target.

## Findings

1. **Oracle: a U+FEFF after a UTF-16 BOM** (`index`, within seconds).
   `FE FF FE FF` is a UTF-16 BE file whose one row holds U+FEFF. Leal had
   it right; the oracle parsed its UTF-8 transcoding with `parse`, which
   skipped the leading `EF BB BF` as a UTF-8 BOM, and found no rows. The
   oracle now parses the transcoding with no BOM (`parse_after`).
   Regression tests: `the_oracle_reads_a_second_utf16_bom_as_text`
   (testkit) and `a_feff_after_a_utf16_bom_is_text` (core index). The
   generator never writes this (it drops a model BOM under a UTF-16 one),
   which is why the property tests didn't see it.
2. **Harness: `Layout::row_of_offset` counts characters.** For UTF-16 it
   adds a line ending's length in characters, not bytes, so the `index`
   target computes the row at an offset itself. A limitation of the
   testkit helper, used nowhere else with UTF-16; not changed.

## Decisions

- The serializer targets save with `save_to_writer` (in memory), as the
  task asks: the disk path, attributes, the rebase and undo after a save
  stay with the property tests (`document/tests/saving/properties.rs`),
  which cover them in depth. The reopen chooses the delimiter and
  encoding rather than relying on the encoding attribute, which a save to
  memory doesn't write.
- One runner per target rather than one job for all: failures are
  per target, and the wall time stays at about 15 minutes.

## New dependencies

Only in `fuzz/` (never in a product build): `libfuzzer-sys` (the engine
and `fuzz_target!`, from the rust-fuzz project, as cargo-fuzz generates)
and `arbitrary` (structured inputs from bytes, same project).

## Rust notes

- **`#![no_main]` and `fuzz_target!`** (each `fuzz_targets/*.rs`). A fuzz
  target has no `main`: libFuzzer's C++ `main` calls the closure given to
  `fuzz_target!` with each input. A panic is a crash: libFuzzer saves the
  input and stops.
- **`#[derive(Arbitrary)]`** (`harness.rs`, `Script`, `Op`, `Value`,
  `Piece`). Generates code that builds these types from raw bytes, so the
  fuzzer's mutations of bytes become mutations of edit scripts.
  `arbitrary_take_rest` lets the last field (the ops) use every byte left.
- **`#[path = …] pub mod oracle;`** (`lib.rs`). Compiles a file from
  elsewhere in the repo as a module of this crate, without making it part
  of the testkit's public API.
- **Lifetimes: `Oracle<'a>`** borrows the file's bytes and the parsed
  layout, so `run` declares `analysis` before `oracle` and keeps both in
  scope; `Made<'_>` holds clones of the oracle, so they borrow the same
  data. Undo is "put back the clone".
- **`LazyLock` statics** (`SCHEDULER`, `DIR`, `VERBOSE`): built on first
  use and shared by every input the process runs, so each input doesn't
  start its own thread pool.
