# 2.5a App: insert, duplicate and delete rows and columns

Status: built, reviewed, review findings fixed; then Rob's on-screen
follow-up (Duplicate Row, a new row's first cell, ⇧↩, the quote's
wording), accepted by Rob 2026-10-04, and its review fixed. The core's structural edits (2.4a–c), their FFI, and undo,
redo, the journal and recovery of them (2.5.2) were already there.

## What was built

**Edit menu** (after Go to Row…, two groups behind separators; no other
UI, ADR-0002):

| Item | Key | Acts on |
|---|---|---|
| Insert Row Above | — | above the active cell's row |
| Insert Row Below | ⌘↩ | below it (after the last row: appends) |
| Duplicate Row / Duplicate Rows | ⇧⌘↩ | every row of the selection |
| Delete Row / Delete Rows | ⌘⌫ | every row of the selection |
| Insert Column Before / After | — | before / after the active cell's column |
| Delete Column / Delete Columns | — | every column of the selection, one undo step |

- `app/Sources/Window/StructureCommands.swift`: the actions, enabling
  (`availability`), the selection afterwards, the words (`StructureText`).
  `MainMenu.structureItems()` builds the items.
  `DocumentStructure.swift`: the model's calls into the core, grid rows
  turned into logical rows; each command goes to `commandApplied` (2.5.2).
- A new row has as many empty cells as most rows; a new column's cells
  (and header title) are empty. **Header row**: grid rows exclude it, so
  it can't be selected, deleted or duplicated, and Insert Row Above on
  the first data row inserts at logical row 1.
- **One step, one name.** Delete Columns (several core commands) and
  Duplicate Row (one row insert) are one undo step with their own name,
  through `DocumentUndoManager.registerAsOneStep`: its group opens with
  the first command registered, so a refused command leaves nothing (no
  nameless Undo; Redo kept). Undone and redone, a step keeps its name
  (`stepName`); a refused undo's alert names the step.
- **⌘↩ is "below"** (the "add a record" flow; it can append). Above has
  no shortcut.

**Selection afterwards** (Rob): Insert Row selects the new row's first
cell; Duplicate Row the copies, in the same columns. Undo and redo: the
row where the change was, in the active cell's column.

**Duplicate Row (Rob's follow-up; accepted 2026-10-04):**
- The copy goes directly below; with several rows selected, a copy of
  each, in order, after the last selected row, as one undoable step.
- **Its fields as the row writes them**; its line ending the file's most
  common one, as Insert Row's (DESIGN §3.7 rule 3), so in a file of
  mixed endings it can differ from its row's. A new core command,
  `Document::duplicate_rows` (`structural.rs`), reads the rows'
  cells as values (`RowView::copy_values`) and inserts them as one row
  insert: unedited fields as their bytes (`Value::Raw`, quotes, escapes
  and spaces kept); an edited field as `Value::Copied { quoted }`, which
  the saver writes as the source writes an edited field (quoted if its
  field was, if needed, or if the file quotes every field); a hatched
  cell as `Copied` with `quoted: false` (the same rule); padding as
  `Value::Padding` (no bytes); a new cell as text (its column quotes it
  the same). Undo/redo by identity; after a save or in a replay by value
  (ADR-0014 d3, d8), which keeps these values. Refused while reading or
  saving (ADR-0014 d1), and for more than `DUPLICATE_ROW_LIMIT` (10,000)
  rows: it reads and copies on the main thread, and ⌘A or a whole column
  (`throughLastRow`) copied a 300k-row file in 0.36 s.
  `row_edits/duplicate_10k_rows` (reference file, copy + undo): 16.1 ms.
- Off (tooltip; the key beeps and VoiceOver hears why): when the last
  selected row is an open unterminated quote's (the copy would follow
  it, ADR-0004 d8), while reading or saving, and while another text
  field has the focus. In the in-cell editor ⇧⌘↩ (and ⇧⌘ with keypad
  Enter) commits, then duplicates; in the inspector it commits, then
  duplicates (⌘↩ there only commits). A held ⇧⌘↩ duplicates on each
  repeat, as ⌘↩ inserts.
- Known differences: a blank line's copy is `""` (ADR-0014 d9, Rob); a
  copy's edited cell edited again is a new field. In a file quoting every
  field, a copy of a typed-in (hatched) cell, undone and redone across
  saves, follows the saved file's quoting: its padding is an unquoted
  empty field, so the redone copy's value is unquoted (`"1",,z`).
  Acceptable under ADR-0014 d8; pinned by
  `a_copied_hatched_cell_in_a_quoted_file_across_saves`.

**Enabling, with the reason** (the menu item's tooltip; ⌘↩/⇧⌘↩/⌘⌫
reaching the grid beep and VoiceOver hears it):

| Core refusal | When | Tooltip |
|---|---|---|
| `StillReading` | not all read and trusted, or a drive's/share's copy not done (ADR-0014 d1) | "Rows and columns can be inserted and deleted once Leal has read the whole file." |
| `Saving` | a save runs | "Wait for the save to finish." |
| `TooManyRows` | Duplicate Row on over 10,000 rows | "Duplicate up to 10,000 rows at a time." |
| `AfterUnterminatedQuote` | a row, copy or column after the open quote (ADR-0004 d8) | "A quote in the last row is never closed, so a row inserted (a copy of the row, a column inserted) after it would land inside the quote. Insert Row Above (Insert Column Before) still works, and the cell can still be edited." |
| `NoSuchColumn` etc. | nothing there | off, no tooltip |

The diagnostics popover's unterminated-quote line says the same. The
app adds only: off once the document failed, while Reload replaces it,
and while a text field other than the two editors has the focus.

**Cost of asking**: the column questions find the longest row once per
version of the edits (cached, keyed by the edits' version and a `Weak`
pointer to the overlay). Reference file: `column_edits/can_insert_column`
3.06 ms → 31 ns asked again, 1.89 ms first after an edit.

**Keys and text fields.** A menu key equivalent wins over a text view's
own key, so:
- In the in-cell editor and the inspector (`LiteralTextView`) ⌘⌫ is the
  text's (delete to the start of the line). ⌘↩ and ⇧⌘↩ go on to the
  menu, which commits the edit first (the inspector takes ⌘↩ as commit).
  ⌘ (⇧⌘) with the keypad's Enter isn't the items' key: in the in-cell
  editor and the grid it does the same as ⌘↩ (⇧⌘↩); in the inspector
  ⇧⌘ with it duplicates too. Caps Lock is ignored in all these keys.
- In any other text field (the find bar, Go to Row's sheet via
  `keyWindow`) the items are off, so the keys stay the field's.
- In the grid, the keys reach `keyDown` only when the item is off (or for
  the keypad's Enter): `GridView.rowCommandKey` gives a `RowCommandKey`,
  run if it can be, else a beep and the reason. A held ⌘⌫ deletes once.
- **⇧↩ in the editors** (Rob's follow-up): a line break, as ⌥↩
  (`LiteralTextView.keyDown`; not while an input method composes). The
  in-cell editor's tooltip and VoiceOver help: "Return commits · ⇧↩ or
  ⌥↩ for a new line · Esc cancels"; DESIGN §4.2 lists it. The inspector's
  hint is unchanged: Return already makes a new line there.

**After a change** (`DocumentChange.structure` carries a
`StructureChange`): grid, strips, gutter, headers and widths redrawn; the
selection as above, scrolled into view; **Find** restarts after a
column's change, and after rows' catches up keyed by row id (ADR-0014
d2), dropping highlight tiles and a waiting Next; header titles are read
again after rows undone or redone at logical row 0; the inspector reads
the active cell again.

   selected; type, Return; ⌘Z twice ("Undo Insert Row").

## Rust notes

- `Value` (`crates/leal-core/src/edit/value.rs`) is an `enum`: a type
  whose value is one of several variants, each with its own data. Two
  were added, `Copied { text, quoted }` and `Padding`. Rust makes every
  `match` on it list each variant (or a catch-all), so the compiler
  pointed to every place that had to decide what a copy means
  (`text()`, `raw()`, `fit()`, `ViewCell::of_value`).
- `RowView::copy_values` matches on a tuple `(id, cell, self.own)`:
  one `match` looks at three things at once, first matching arm wins.
- The saver's `copied` closure (`saving/walk.rs`) chains `Option`
  methods: `.ok()` turns a failed conversion into `None`, `.and_then`
  goes on only with a value, so a missing field is simply "not a copy".
  `while matches!(cells.last(), Some(NewCell::Padding))` pops trailing
  padding: `matches!` is a `match` that answers true or false.
- The column questions' cache is a `Mutex<Option<Widest>>` holding a
  `Weak<Overlay>`, a pointer that doesn't keep the edits alive;
  `Weak::ptr_eq` tells whether they are still the same edits.
- FFI `can_…` methods return `Result<Option<EditRefusal>, LealError>`:
  the outer `Result` is "did the call work", the inner `None` "allowed".
  `DUPLICATE_ROW_LIMIT` is a `pub const` (a value fixed at compile
  time); Swift reads it through `duplicate_row_limit()`.
