# 1.4 Rows and fields

## What was built

### `leal_core::rows` (`crates/leal-core/src/rows/`)

The lenient row parser, display values and row cache of DESIGN §3.4.

| File | What it holds |
|---|---|
| `mod.rs` | The public API: `RowParser`, `ParsedRow`, `FieldSpan`, `RowsError`. The module docs give the rules, the display-value rules and the seam with 1.2 and 1.3a. |
| `parse.rs` | Splitting one row into fields. |
| `display.rs` | `value_bytes` (unquote, unescape) and `display_value` (then decode). |
| `encoding.rs` | `Encoding`: a provisional local copy of ADR-0005 decision 5's set (see "Seam"). |
| `cache.rs` | `RowCache`, the LRU cache of parsed rows. |
| `tests.rs` | 37 tests (6 of them property tests), plus a doctest in `mod.rs`. |

**Public API:**

```rust
let parser = RowParser::new(index.dialect(), Encoding::Utf8)?;   // Result<RowParser, RowsError>

let row = parser.parse_row(&index, r, bytes)?;   // Option<ParsedRow>: None if not indexed (yet)
let row = parser.parse(bytes, span)?;            // Option<ParsedRow>, for a span from RowIndex::row

row.span()                  // the row's bytes, without its line ending
row.fields()                // &[FieldSpan], never empty
row.field(i)                // Option<&FieldSpan>: None past the end of a short (ragged) row

field.start() / len() / span() / is_empty()
field.quoted()              // first unit is the quote
field.text_after_quote()    // Option<usize>: offset of the first unit after the closing quote
field.unterminated()        // the quote never closes; the field runs to the end of the file
field.raw(bytes)            // &[u8]: the raw bytes

parser.value_bytes(bytes, &field)    // Cow<[u8]>: unquoted and unescaped, not decoded
parser.display_value(bytes, &field)  // Cow<str>: the whole value (cell inspector)
parser.display_prefix(bytes, &field, max_chars)  // (Cow<str>, truncated): what the grid shows

let mut cache = RowCache::new(parser, DEFAULT_CACHE_ROWS);  // 256 rows, 100,000 fields
let mut cache = RowCache::with_limits(parser, max_rows, max_fields);
cache.row(&index, r, bytes)          // Option<Arc<ParsedRow>>, parsed on a miss
cache.contains(r) / len() / fields() / capacity() / max_fields() / clear() / parser()
```

Errors: `InvalidDialect` (the index's rule: delimiter and quote different
ASCII characters, neither CR nor LF) and `EncodingMismatch` (UTF-16 needs
UTF-16 code units, and every other encoding needs bytes).

### How a row is parsed

The index has already found the row, so its span holds no line ending, and
every CR or LF in it is inside quotes. So the parser looks for only two
things, each with one `memchr` call:

- **Outside quotes:** the next delimiter. A quote matters only as a field's
  first unit (DESIGN §3.4), which is a one-unit check at the field's start.
  So `a"b` is unquoted, and so is ` "a"` (a space first).
- **Inside quotes:** the next quote. If the next unit is also a quote, it
  is `""` and the search goes on; otherwise it is the closing quote. The
  field then runs to the next delimiter. If there is anything before it,
  that is text after the closing quote (`"a"b`), and quotes in it are
  literal (ADR-0003 decision 3), so `"a"b"c",` is one field.
- **No closing quote:** the field runs to the end of the row. Only the last
  row can do that (the index ends it at the end of the file), so the
  field's span includes any final newline.
- A blank row has one empty, unquoted field. `a,` has two fields, the
  second empty.

The search reuses the index's `Units` trait (`Bytes` and `Utf16`), so UTF-16
works the same way, one code unit at a time, and every offset is a byte
offset into the file as stored, BOM included (ADR-0003 decision 6). A UTF-16
unit whose *other* byte is `,` or `"` (U+222C, U+2C22) isn't a delimiter or
quote. A final odd byte belongs to the last field. To share `Units`, the
index's `scan` module is now `pub(crate)`; nothing else in it changed.

A span that isn't inside the file after the BOM, or (in UTF-16) doesn't
start and end on whole units, gives `None` rather than a panic.

### Display values

`value_bytes` gives the bytes the display value decodes, as the testkit's
`FieldLayout::value` defines them:

| Field | Value |
|---|---|
| unquoted | the raw bytes |
| quoted | between the quotes, `""` → `"` |
| text after the closing quote | the raw bytes: `"a"b` shows as `"a"b` (ADR-0002 question 6, ADR-0003 decision 2) |
| unterminated | everything after the opening quote, `""` → `"` |

`display_value` decodes that in the parser's encoding:

- **UTF-8:** `String::from_utf8_lossy`. Each invalid sequence shows as
  U+FFFD, split the way the testkit's encoding rule counts them.
- **UTF-16 LE/BE:** `char::decode_utf16`. An unpaired surrogate shows as
  U+FFFD (ADR-0003 decision 7), and so does a final odd byte (the
  testkit's convention, pinned by `utf16le-odd-length.csv`). U+0000 is
  kept as U+0000; how to draw it is the grid's choice.
- **Windows-125x, ISO-8859-2 and -15, Mac Roman:** `encoding_rs`'s WHATWG
  decoders. Windows-1252 decodes every byte (checked against the testkit's
  table for all 252 non-structural bytes); a byte another code page leaves
  unassigned shows as U+FFFD.
- **ISO-8859-1:** by hand (byte value = code point), because WHATWG, and so
  `encoding_rs`, treats the label `iso-8859-1` as Windows-1252. 1.2 does
  the same.

Both steps **borrow from the file** when they can (`Cow`, see the Rust
notes). Unquoting narrows the slice; only a field with `""` needs a copy.
Valid UTF-8, and ASCII in a single-byte encoding, decode without copying.
So for most fields a display value is a `&str` into the mapped file and
nothing is allocated. UTF-16 always allocates, since its text has to be
transcoded.

**Prefixes for the grid** (added after review). `display_value` decodes
the whole field, so one 1 MB UTF-16 field took 835 µs on this Mac, which
would be over the 1 ms screen budget on an M1 Air. The grid shows only the start of a cell, so
`display_prefix(bytes, field, max_chars)` returns the first `max_chars`
characters and whether there were more, with work proportional to
`max_chars`:

- It unescapes and decodes only a window of the value's raw bytes,
  `8 × (max_chars + 1)` long. A character takes at most 4 bytes of value (a
  UTF-8 sequence, an invalid sequence shown as one U+FFFD, a surrogate
  pair) and unescaping at most halves the bytes, so the window always holds
  `max_chars + 1` characters if the value has that many. The extra one is
  the look-ahead the last kept character may need, and it shows whether
  anything was cut. The window is a multiple of 8, so in UTF-16 it ends on
  a whole unit. A window that ends between the two quotes of `""` still
  gives `"`.
- In UTF-8 the window steps back (at most 3 bytes) to a character's first
  byte, so valid text still borrows instead of copying.
- The result is cut at a `char` boundary, so no character is ever split.
  (A character here is a Unicode scalar value, as Rust's `char` counts
  them; a combining accent counts as one. Grapheme clusters are the
  grid's business.)

**Fast search for `""`.** Parsing a row still has to find where each field
ends, so a 1 MB field with `""` every 15 bytes cost 680 µs for the screen,
almost all of it one `memchr` call per quote (about 120,000 of them). For
byte encodings, `closing_quote_in_bytes` now uses `memchr` to reach the
next quote, returns at once if it closes the field (the usual case, so
ordinary rows pay nothing), and otherwise, from a `""`, turns the next 64
bytes into a bitmask of quotes and walks its bits. That brought the screen
to about 200 µs. UTF-16 keeps the one-`memchr`-per-quote search (see
"Open questions").

### The row cache

`RowCache` keeps the rows read most recently, within two limits: at most
`DEFAULT_CACHE_ROWS` (256) rows, several screens, **and** at most
`DEFAULT_CACHE_FIELDS` (100,000) fields between them. A `FieldSpan` is 32
bytes, so the field limit keeps the cache at about 3.2 MB of spans plus
about 100 bytes per row, however wide the rows are. 256 rows of up to 390
fields fit; wider rows mean fewer rows kept. Without it, 256 rows of
10,000 columns would have been 82 MB (found in review). A single row with
more fields than the limit is parsed and returned but never kept, so it
can't evict everything else. A 12-field row is about 500 bytes, so the
reference file's cache is about 130 KB. It is a
`HashMap` from row number to `Arc<ParsedRow>`, with a counter that ticks on
every read. A hit updates the entry's tick. A miss parses the row, and if
the cache is full (either limit), evicts entries with the oldest tick until
the new row fits: a scan of at most 256 entries each, which costs well under a microsecond and happens only next to
parsing a row. That is much simpler than a linked list, and the benchmark
shows hits are what matters.

- A cache belongs to one parser, so to one dialect and encoding. After
  re-indexing with another delimiter or encoding, make a new cache.
- Rows the index has published never change, so cached rows stay right
  while indexing goes on. Rows the index doesn't have yet give `None` and
  aren't cached.
- `row` takes `&mut self`. The document (1.6) shares one between threads
  behind its `Mutex`, so the cache itself has no lock.
- `cache.row` checks the index's dialect against the parser's, so a row
  can't be parsed with a delimiter the index wasn't built with.

### Seam with 1.2 (to be joined in 1.3a)

The parser takes the index's `IndexDialect` (delimiter, quote, BOM length,
UTF-16 width and byte order) plus an `Encoding`. Task 1.2's detection types
aren't on `main` yet, so:

- `rows::Encoding` is a **provisional local copy** of ADR-0005 decision
  5's sixteen encodings, with the same variant names as `dialect::Encoding`
  on 1.2's branch. **1.3a should delete it and use 1.2's**, moving
  `Encoding::code_unit` across, and pass the detected encoding to
  `RowParser::new`. 1.2's `Encoding::whatwg` is the same lookup as this
  one's `single_byte`, and both decode ISO-8859-1 by hand.
- `encoding_rs` is added to the workspace with exactly the line 1.2 adds,
  so the two branches agree on it.
- **First paint** (1.3a) doesn't wait for the index. One way: index the
  first 64 KB on their own (`RowIndex::build` on that slice), drop the last
  row, which may be cut off, and parse the rest with this parser. Their
  spans are the same offsets as in the whole file.

## Tests

All in `crates/leal-core/src/rows/tests.rs`, written before the parser.
Against stubs (one empty field per row, empty display values, no caching),
31 of the 36 tests failed. Expected answers come from the testkit: the
generator's layouts and the corpus sidecars, both of which the testkit
checks against its reference parser. The reference parser itself is never
used here (0.2 notes, and the oracle's own header).

- **Generated files** (properties, 256 cases each, 20,000 in `test-deep`):
  clean and messy files from `csv_file` (UTF-8, and Windows-1252 when the
  ADR-0003 rule says so) and from `csv_file_utf16` (LE and BE). Each file is
  indexed, every row parsed, and the result turned into a testkit `Layout`,
  which must equal the generator's exactly: every row's span and line
  ending, every field's span, quoted flag, text-after-quote offset,
  unterminated flag and value. Then every display value must equal
  `decode_value` of the generator's value.
- **Any bytes** (`csv_bytes`, any of the four delimiters, every one of the
  16 encodings, UTF-16 with a BOM in front): nothing panics, the fields
  tile each row with one delimiter unit between them, and for byte
  encodings the whole parse passes the testkit's `check_tiles`.
- **Every corpus sidecar** (43 files): row count, every row's field count,
  tiling, and all 63 `[[cells]]` (display value and quoted flag). Also
  **every diagnostic**: `leal_testkit::diagnostics::derive` is run on the
  layout this parser produced and must give exactly the sidecar's kinds,
  counts and locations. That checks text after a closing quote and the
  unterminated quote from the parse directly, and invalid encoding and NUL
  through where each field starts and ends.
- **Hand-written cases:** plain, empty, leading and trailing fields; blank
  rows; quoted fields with delimiters, CR, LF and CRLF; `""` in all
  positions; literal quotes in unquoted fields and after a closing quote;
  text after a closing quote (offsets and raw display); unterminated quotes
  (with `""`, a lone final quote, a first field); every delimiter; a quote
  after a UTF-8 BOM, and the same bytes reopened as Windows-1252; invalid
  UTF-8; well-known characters in every single-byte encoding and an
  unassigned Windows-1253 byte; UTF-16 offsets, units whose other byte is
  structural, unpaired surrogates, a final odd byte and U+0000; when display
  values borrow; spans outside the file or off a UTF-16 unit; the wrong
  bytes; parser errors.
- **Cache:** hits return the same `Arc`; least-recently-read eviction;
  rows not indexed (or from another dialect's index) aren't cached; a
  capacity of 0 holds one row; and a property that, for any capacity and
  any sequence of reads, the cache returns what a fresh parse returns and
  holds exactly the rows a simple LRU list model says it should.

I checked that the tests catch real mistakes by breaking the code six ways:

| Mistake | Tests that failed |
|---|---|
| Text after a closing quote treated as a plain quoted field | 7 |
| A quote opens a field only at the row's start, not after a delimiter | 14 |
| `""` not unescaped | 10 |
| A final odd UTF-16 byte dropped from the display value | 2 |
| The cache evicts the most recently read row | 2 |
| A cache hit doesn't count as a read | 2 |

After review, more tests: `display_prefix` against the first `max_chars`
characters of `display_value` for every field of every generated file and
of any bytes in every encoding (for 11 values of `max_chars` around each
value's length, including that it borrows whenever `display_value` does);
a property over long fields built from the awkward pieces (`""`, 2- to
4-byte UTF-8, a truncated sequence, an invalid byte, NUL, lone and paired
surrogates) in every encoding, quoted and unquoted, which also checks that
a quoted field closes at its last byte however its `""` fall across the

| Mistake | Tests that failed |
|---|---|
| Prefix window of 2 bytes per character instead of 8 | 6 |
| No look-ahead character in the window | 5 |
| UTF-8 window cut mid-character (no step back) | 3 |
| Cache ignores the field limit | 2 |
| Cache keeps a row wider than the field limit | 2 |
| A `""` across a 64-byte block resumes at its second quote | 2 |
| Only the first quote of a `""` cleared from the mask | 8 |

## Benchmark

`crates/leal-bench/benches/rows.rs`, on the 1.2b reference file, 60 rows
from row 500,000 (a screenful of 720 cells), with the index built
beforehand. `rows/screen` is budgeted at 1 ms in `src/budgets.rs` (DESIGN
§3.9: reads for visible cells under 1 ms, on the main thread), so CI fails
if it goes over.

Same machine as 1.2b and 1.3: `Mac17,8`, Apple M5 Pro. This is **not** the
reference machine (a base M1 Air, which is slower).

| Benchmark | What | Median | Per cell |
|---|---|---|---|
| `rows/screen` | parse 60 rows, derive all 720 display values, no cache | **11.0 µs** | 15 ns |
| `rows/screen_cached` | the same rows from a warm `RowCache` | 5.6 µs | 8 ns |
| `rows/parse` | parsing alone | 6.0 µs | — |

- **Budget: 1 ms. Result: 11.0 µs**, about 90× under on this Mac. Even
  3× slower on the M1 Air, a full uncached screen is under 40 µs.
- Parsing and decoding cost about the same (6 µs each). The cache removes
  the parse; what's left is UTF-8 validation of 720 values, nearly all of
  them borrowed.
- Display values are measured as `Cow`s. The FFI (1.6) will copy each into
  a Swift string, which this benchmark doesn't count.
- `bench-report` over a full `just bench` run lists `rows/screen` as `ok`
  against its 1 ms budget.

**After review: a screen with a 1 MB field.** 59 rows of the reference
file plus one whose notes field is 1 MB, parsed uncached, every cell read
with `display_prefix(…, 256)` as the grid will (256 characters is more than
a 260 px column shows at any font size). All three are budgeted at 1 ms.
Same Mac, from a full `just bench` run after the review fixes:

| Benchmark | The 1 MB field | Median |
|---|---|---|
| `rows/screen_long_field_utf8` | unquoted, mixed-script UTF-8 | **24 µs** |
| `rows/screen_long_field_escaped` | quoted, `""` every 15 bytes or so | **200 µs** (680 µs before the faster `""` search) |
| `rows/screen_long_field_utf16` | the plain screen as UTF-16 LE | **41 µs** |
| `rows/screen` (for comparison, same run) | none | 12.1 µs |
| `rows/screen_cached` | none | 6.4 µs |

- What's left is parsing the long row: finding where the 1 MB field ends,
  at memory speed for plain text, and through about 120,000 quotes for the
  escaped one. Decoding is now a few hundred bytes per cell.
- The escaped case is the tightest: about 500 µs if the M1 Air is 2.5×
  slower, still inside the budget. The short-row numbers moved by about
  10% between runs on this Mac (11.0 to 12.1 µs), which is noise: the
  ordinary path doesn't build a mask.

## Decisions and deviations

- **Offsets are `usize`, not `u32`.** DESIGN §3.4 writes spans as
  `(start, len, quoted)`. `FieldSpan` keeps `start` and `len` as `usize`,
  like the index's public API, behind accessor methods. Parsed rows are
  short-lived or in the cache, which is capped at 100,000 fields, so `u32`
  (16 bytes a field instead of 32) would save at most 1.6 MB, and cost a
  checked conversion on every offset. The fields are private, so this can
  change without touching callers. (The first version of these notes said
  "about 50 KB", which held only for 12-column rows.)
- **The cache has a field limit as well as a row limit** (review). See
  "The row cache".
- **`display_prefix` for the grid, `display_value` for the inspector**
  (review). See "Display values".
- **`FieldSpan` carries more than a quoted flag:** the text-after-quote
  offset and the unterminated flag. Display values need them, and 1.5
  reports text after a closing quote at that offset.
- **`display_value` is a method of `RowParser`**, not of the field, because
  it needs the quote, the code unit and the encoding.
- **`RowParser::new` checks the encoding against the code unit**, so a
  UTF-16 encoding with byte code units (or the other way round) is an
  error rather than nonsense.
- **Tests use the generator and the sidecars, not the oracle itself.** The
  brief asked for comparison "against the testkit oracle". The 0.2 notes
  and the oracle's header say the real parser is tested against the
  generator and corpus, which the testkit checks against the oracle; 1.3
  did the same. Comparing whole `Layout`s on generated files, and deriving
  every sidecar diagnostic from this parser's spans, covers everything the
  oracle's parse gives (spans, quoted flags, display values).
- **No oracle or sidecar problems found.**

## Changes after review

The review approved the branch, with two should-fixes, both done (details
in the sections above):

- **The cache is bounded by fields as well as rows:** 256 rows and 100,000
  fields, about 3.2 MB of spans at most; a row wider than that isn't kept.
- **Long fields stay within the 1 ms budget:** `display_prefix` does work
  proportional to the characters asked for; byte-encoded fields with many
  `""` are searched with a bitmask; three new budgeted benchmarks put a
  1 MB field on screen (24, 200 and 41 µs).

The re-review found no correctness problems and two test gaps, now
closed:

- **A NUL quote character** (which `RowParser::new` accepts) is tested:
  closed with an escaped `\0\0`, and unterminated less than 64 bytes after
  one. Without the mask's padding clear, the second case fails.
- **Generated files with long values** (`long_values()`: up to 100 chunks,
  so up to 500 bytes, in at most 4 rows of 3 fields), in UTF-8 and UTF-16.
  The default generator's values are at most 20 bytes, so they never
  reached a 64-byte block boundary. With the `""` that straddles a block
  resuming one byte early, the long-value property fails and the
  default-size ones still pass. They take about 1.7 s each in `just check`
  but about 2 minutes each in `just test-deep` (20,000 cases, debug
  build), which is now the longest part of that run.
- **Rebasing onto main** (which now has 1.2 and the new benchmark-report
  tests) needed two small fixes: `leal-core/Cargo.toml`'s comment on
  `encoding_rs` now names both users, and `write_run` in
  `leal-bench/tests/report.rs` writes each budgeted benchmark at a
  fraction of its own budget, since it assumed every budget was 500 ms
  and so put the 1 ms row budgets over. `rows::Encoding` still duplicates
  1.2's `dialect::Encoding`, which is now on main; merging them is left to
  1.3a as planned.

## Open questions

- 1.3a: replace `rows::Encoding` with 1.2's `dialect::Encoding` (see
  "Seam"), and decide how first paint gets its rows before the index.
- 1.5: field-level diagnostics (invalid encoding, NUL) need a look inside
  each field during indexing. The index's scan doesn't split fields; should
  1.5 run this parser over each row in the same pass, or add field
  boundaries to the scan? The parser costs about 100 ns a row on this Mac,
  which would add about 100 ms to the 54 ms index of the reference file.
- 1.6: how should the grid draw U+0000, CR and LF inside a cell? The core
  gives them as they are.
- 1.6: **very long rows.** Parsing a row is proportional to its length, so
  a row of 1M fields takes about 10 ms to parse (measured in review), and
  because it is wider than the cache's field limit, it isn't cached and is
  parsed again on every read. Should the grid ask only for the columns it
  shows (a parse that stops after field N, or one that keeps a row's field
  offsets in a side index), and should 1.6 cap how many columns it lays
  out?
- **UTF-16 fields with many `""`** still take one `memchr` per quote (the
  bitmask search is for byte encodings). A 1 MB such field would cost about
  as much as the escaped UTF-8 case did before the fix (around 0.7 ms on
  this Mac). UTF-16 is read-only and rare, so this is left for 4.1's
  performance audit unless 1.6 finds it matters.
- Re-measure on a base M1 Air before the phase 1 gate (as 1.2b and 1.3
  also ask).

## Rust notes

- **`Cow<'a, str>`: borrowed or owned** (`display.rs`, `display_value`).
  `Cow` ("clone on write") is an enum with two cases: `Borrowed(&'a str)`,
  a view into someone else's memory, and `Owned(String)`, text the value
  owns. A function returning `Cow` can hand back a slice of the file when
  the text is already right, and build a new `String` only when it isn't
  (an escaped quote, an invalid byte, UTF-16). The caller uses either the
  same way, because `Cow<str>` derefs to `&str`; `.into_owned()` gives a
  `String` if one is needed. `String::from_utf8_lossy` already works this
  way, and `encoding_rs`'s decoders too, so `decode` just passes their
  `Cow` on.
- **Lifetimes on borrowed slices** (`fn display_value<'a>(&self, bytes: &'a
  [u8], field: &FieldSpan) -> Cow<'a, str>`). The `'a` says "the result
  may borrow from `bytes`, so it can't outlive them". Note that the result
  is tied to `bytes`, not to `self` or `field`: the parser and the field
  can be dropped while the text lives on, but the file's bytes can't. The
  compiler checks this, so a display value can never point into a file
  that has been unmapped. In `decode<'b>`, the input is a different slice
  (sometimes a temporary `Vec` from unescaping), hence a separate
  lifetime; when it is temporary, `display_value` calls `.into_owned()` so
  nothing borrows from the `Vec` after it is dropped.
- **Ownership in the cache: `Arc<ParsedRow>`** (`cache.rs`, `RowCache::row`).
  The cache owns its rows, but a caller wants to keep a row while asking
  for more, and a later miss may evict that very row. Returning
  `&ParsedRow` would tie the row to a borrow of the cache and stop any
  further call until it ended. Instead each row lives in an `Arc`, a
  reference-counted pointer: `Arc::clone` gives the caller a second handle
  to the same row (it copies a pointer and bumps a counter, not the
  fields). If the cache evicts the row, the caller's handle keeps it alive
  until the caller drops it. `Arc` rather than `Rc` because the document is
  shared between threads (DESIGN §3.9); `Rc`'s counter isn't thread-safe.
- **`&mut self` and `HashMap::get_mut`** (`RowCache::row`). Even a cache
  hit changes the cache (it records the read), so `row` takes `&mut self`.
  `self.rows.get_mut(&row)` returns a mutable reference into the map, used
  to update `last_read`, then `return`s before the map is touched again;
  the borrow checker accepts that because the reference isn't used after
  the `return`.
- **`min_by_key` over an iterator** (`evict_least_recently_read`).
  `self.rows.iter()` yields `(&key, &entry)` pairs; `min_by_key` keeps the
  one with the smallest `last_read`. `.map(|(&row, _)| row)` copies the
  key out, so the borrow of the map ends before `self.rows.remove(&row)`
  needs to change it.
- **Private fields and accessor methods** (`FieldSpan` in `mod.rs`). Only
  the parser can make a `FieldSpan`, so its invariants (a quoted field's
  span really starts with a quote, and so on) always hold, and
  `value_bytes` can rely on them. Code outside the module reads it through
  methods. That is also what makes the `usize`/`u32` choice changeable.
- **Generics reused across modules** (`split<U: Units>` in `parse.rs`). The
  parser is generic over the index's `Units` trait, like the scanner, so
  the compiler builds one copy for bytes and one for UTF-16. Changing
  `mod scan` to `pub(crate) mod scan` lets the `rows` module use it:
  `pub(crate)` means "visible anywhere in this crate, but not to other
  crates", so `Units` doesn't become public API.
- **`let … else` and `if let … &&`** (`quoted_field`, `decode_latin1`).
  `let Some(q) = … else { return …; };` binds `q` or leaves the function.
  `if value.is_ascii() && let Ok(text) = std::str::from_utf8(value)`
  (a *let chain*, new in Rust 2024) runs the block only when both hold, and
  binds `text` for it.
- **Bitmasks and `trailing_zeros`** (`closing_quote_in_bytes` and
  `quote_mask` in `parse.rs`). A `u64` has 64 bits, one per byte of a
  64-byte block: `quote_mask` sets bit `i` when byte `i` is a quote
  (`u64::from(b == quote) << i` turns `true` into 1 and moves it to place
  `i`). `mask.trailing_zeros()` counts the zero bits below the lowest 1,
  which is the position of the next quote, in one instruction.
  `mask &= !(0b11 << i)` clears bits `i` and `i + 1` (the two quotes of a
  `""`). The loop builds the mask over a fixed-size `[u8; 64]` array so the
  compiler knows the length and can compare many bytes at once.
- **Cutting a `Cow` without copying** (`first_chars` in `display.rs`).
  `text.char_indices().nth(n)` finds the byte where character `n` starts,
  so cutting there never splits a character. Then `match text` takes the
  `Cow` apart: a borrowed `&str` is re-sliced (`&s[..cut]`, still
  borrowed), and an owned `String` is shortened in place with `truncate`.
  Either way nothing is copied.
- **`as_chunks::<2>()`** (`decode_utf16`) splits a byte slice into `[u8;
  2]` pairs plus the odd byte left over, which is how the final odd byte of
  a UTF-16 file is found. `char::decode_utf16` turns code units into
  `Result<char, _>`, an `Err` for each unpaired surrogate, and
  `.unwrap_or(char::REPLACEMENT_CHARACTER)` turns that into U+FFFD.
